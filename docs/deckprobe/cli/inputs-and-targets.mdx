DeckProbe uses the logical filename extension to choose a driver, verifies the container and internal document type, then runs only the paths required by the requested Targets.

## Input modes

### Local file

Pass a file path as the final argument:

```bash
deckprobe report.pdf
```

The report uses `source_kind: "local_file"` and sets `display_name` to `report.pdf`.

### Read one file from stdin

Use positional `-` and provide a logical filename with an extension through `-n` / `--stdin-name`:

```bash
cat workbook.xlsx | deckprobe -n workbook.xlsx -
```

DeckProbe uses `workbook.xlsx` to select the Excel driver. Stdin is buffered at the CLI boundary and rejected if it exceeds the active physical-byte budget.

### Process a batch with JSONL

`--jsonl` keeps one DeckProbe process running for multiple inputs. **Each line on standard input is one input record**, and **each line on standard output is the corresponding result**.

This command sends two path records:

```bash
printf '%s\n' \
  '{"path":"sample.pdf"}' \
  '{"path":"deck.pptx","name":"quarterly.pptx"}' \
  | deckprobe --jsonl -t format --view values
```

- The first record reads `sample.pdf`.
- The second reads `deck.pptx`, but uses `quarterly.pptx` as the report display name and format-routing name.
- The command emits two compact JSON lines in input order.

When the caller has file bytes instead of a path, send a byte record. `name` supplies the extension used for routing, and `data_base64` contains the complete file bytes:

```bash
encoded=$(base64 < sample.pdf | tr -d '\n')
printf '{"name":"sample.pdf","data_base64":"%s"}\n' "$encoded" \
  | deckprobe --jsonl -t format --view values
```

`base64` is accepted as an alias for `data_base64`. A JSON string path such as `"sample.pdf"` is shorthand for `{"path":"sample.pdf"}`.

Targets, confidence, format options, budgets, strict mode, plan mode, and view options on the command apply to every record. JSONL output must remain one record per line, so it cannot be combined with `--pretty`. If one record fails, DeckProbe writes an Error Report at that position and continues with later records.

## Format routing and assertions

DeckProbe uses the extension to select a driver, then verifies the file signature and internal type. Renaming a PPTX file to DOCX does not make it a Word document; the command returns `MALFORMED_INPUT`.

`-f` / `--input-format` asserts that an input should belong to a specific format. It does not bypass verification:

```bash
deckprobe --input-format pdf report.pdf
deckprobe --input-format powerpoint deck.pptx
deckprobe --input-format iwork deck.key
```

The command fails if the detected format does not match the assertion. Run `deckprobe formats --pretty` to inspect accepted format names and their drivers.

## Required Targets

`-t` / `--targets` specifies facts DeckProbe must attempt to resolve. Repeat the option or separate values with commas. The default is `@default`.

```bash
deckprobe -t title -t page_count report.pdf
deckprobe -t title,page_count report.pdf
deckprobe -t @summary -t @security upload.docm
```

The command line accepts an unambiguous short name. For example, request `slide_count` from a PPTX:

```bash
deckprobe -t slide_count --view values deck.pptx
```

The result still uses the stable full key for machine consumption:

```json
{
  "values": {
    "powerpoint.slide_count": 12
  }
}
```

A Selector is a shortcut for a predefined group of Targets:

| Selector | Targets selected |
| --- | --- |
| `@header` | Header-level document identity facts |
| `@default` | Driver defaults at the active probe level |
| `@summary` | Identity, common metadata, and primary structure |
| `@security` | Encryption, macros, signatures, external relationships, and active content |
| `@structure` | Format-specific counts, names, dimensions, and structure |
| `@assets` | Previews, images, media, fonts, and embedded objects |
| `@quality` | Integrity, repair, extension matching, and conformance facts |
| `@format` | Every format-specific Target available at the active level |
| `@all` | Every Target available at the active level |

`@summary` is a curated set for fast inspection, not a promise to include every statistic for that format. If your application depends on PDF page count, request `page_count` explicitly instead of assuming it is present in `@summary`:

```bash
deckprobe -t @summary,page_count --view values report.pdf
```

## Optional Targets

Lowercase `-o` / `--optional-targets` asks for a value only when DeckProbe can obtain it from an already-selected path without additional reads:

```bash
deckprobe -t page_count -o object_count --view values report.pdf
```

Here, `page_count` is required and participates in path planning. `object_count` is optional. It appears as `pdf.object_count` only when the path selected for page count also produces object count at the requested confidence. Otherwise DeckProbe omits it without selecting another path or changing the report to `partial`.

Reusing an already-selected path this way is called piggyback collection. `-N` / `--no-piggyback` disables it, so it is not normally combined with `-o`.

## Probe level and confidence

### Probe level

`-l` / `--probe-level` limits the path depth and cost class available to the planner. Targets define **what you need**; the probe level defines **which paths may run**.

| Level | Accepted values | Eligible inspection |
| --- | --- | --- |
| `header` | `header`, `h`, `l0`, `0` | Container and header identity for fast format verification |
| `metadata` (default) | `metadata`, `m`, `l1`, `1` | Bounded metadata, core properties, and common structural counts |
| `deep` | `deep`, `d`, `l2`, `2` | Higher-cost format-specific structure, assets, and integrity paths |

For example:

```bash
# Verify document identity only
deckprobe -l header -t @header --view values report.pdf

# Read summary facts and page count at the default level
deckprobe -l metadata -t @summary,page_count --view values report.pdf

# Permit higher-cost paths, while requesting only needed Targets
deckprobe -l deep -t @security,attachment_count --view values report.pdf
```

### Confidence

`-c` / `--minimum-confidence` sets the minimum acceptable evidence confidence: `low`, `medium`, `high`, or `exact` (`l/m/h/x`). The default is `high`:

```bash
deckprobe -c exact -t format report.pdf
```

Use `-C` / `--target-confidence TARGET=CONFIDENCE` to override one Target:

```bash
deckprobe -t slide_count,orientation \
  -C slide_count=exact \
  deck.pptx
```

A Target listed by `deckprobe targets --format FORMAT --pretty` is a fact the driver **knows about**. For a particular request, the planner still needs a path that is allowed by `-l` and meets `-c` / `-C`. If none does, the Target appears in `execution.unresolved_targets`. Add `--strict` to turn that condition into exit status `5`.

## Format options

<Warning>
  Lowercase `-o` selects optional Targets. Uppercase `-O` sets a format option. They are different options.
</Warning>

`-O` / `--format-option` uses `KEY=VALUE` to adjust behavior of the selected driver. It does not accept arbitrary parameters, and Target schema fields are not format options.

For example, the PDF driver currently publishes two options:

| Key | Value | Effect |
| --- | --- | --- |
| `pdf.repair_xref` | `none` or `safe`; default `safe` | Whether bounded safe recovery is allowed for a damaged PDF xref |
| `pdf.max_objects` | Positive integer; default `100000` | Reject the PDF if its parsed object count exceeds this value |

```bash
# Reject a damaged xref instead of attempting safe recovery
deckprobe -O pdf.repair_xref=none report.pdf

# Limit the accepted PDF object count to 50000
deckprobe -O pdf.max_objects=50000 report.pdf
```

The output of `deckprobe targets --format pdf --pretty` contains a `format_options` array. Only keys, value types, and enum values listed in that array are valid for `-O`. The `targets` array and its JSON Schema describe report values, not driver options. After driver detection, an unambiguous key such as `repair_xref` may omit the `pdf.` prefix.

## Resource budgets

The probe level supplies default budgets. Override individual limits when processing untrusted input:

```bash
deckprobe \
  --probe-size 8388608 \
  --max-expanded-bytes 16777216 \
  --max-archive-entries 5000 \
  --timeout-ms 1000 \
  -t format,has_macros \
  upload.docm
```

| Option | Limit |
| --- | --- |
| `-b`, `--probe-size BYTES` | Maximum physical bytes read by probe paths |
| `-x`, `--max-expanded-bytes BYTES` | Maximum cumulative decompressed bytes |
| `-e`, `--max-archive-entries COUNT` | Maximum ZIP/OPC entry count |
| `-T`, `--timeout-ms MILLISECONDS` | Cooperative wall-clock budget |

A budget violation exits with status `4`. When DeckProbe can produce a report, consumed resources are recorded under `execution.actual_cost`. Applications that require a hard deadline should also enforce a process-level timeout around the CLI.

## Discover current Targets and options

Treat the installed binary as the authority:

```bash
deckprobe targets --format pdf --pretty
deckprobe targets --format docx --pretty
deckprobe targets --format xlsx --pretty
deckprobe targets --format pptx --pretty
deckprobe targets --format key --pretty
deckprobe targets --format numbers --pretty
deckprobe targets --format pages --pretty
```

The `targets`, `selector_expansions`, and `format_options` fields describe Targets, Selector expansions, and driver options respectively.

Continue with [Automation and Output](/deckprobe/cli/automation-and-output) to consume reports and exit statuses safely.
