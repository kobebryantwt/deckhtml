`--report` writes `<output>.report.json`. The current implementation has two report levels.

## Per-element local report

Local PPTX conversion can return:

- `schema_version`
- engine name and version
- conversion status
- slides and ordered element records
- stable `element_id`, kind, geometry, and object reference
- `mapping_mode`: `native`, `vector`, `raster`, `ignored`, or `unsupported`
- summary counts and structured diagnostics

This report answers which source elements remained editable and where simplification occurred.

## Aggregate report

When no per-element report is available, such as the current cloud fallback, the CLI writes aggregate information including input, output, mode, format, slide count, element counts, fonts, rasterization statistics, viewport, platform, and duration.

Do not assume the two shapes are identical. Check `schema_version` for the per-element contract or `version` for the aggregate contract.

## Diagnostics

Diagnostics contain a stable `rule_id`, severity, optional slide and element IDs, message, and recovery guidance. Rule families cover identity, unsupported kinds or styles, resources, browser failures, missing fonts, raster fallback, geometry, OOXML verification, animations, and iframes.

Applications should branch on `rule_id`, not localized message text.
