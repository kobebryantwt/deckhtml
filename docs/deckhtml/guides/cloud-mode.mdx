Cloud mode uploads the materialized HTML inputs, creates an HTML conversion task, waits for task completion, downloads the result, and writes it to the requested output path.

```bash
deckhtml deck.html -o deck.pptx --mode cloud
deckhtml deck.html -o deck.pptx --mode cloud --embed-fonts
```

## Authentication behavior

Cloud mode supports a stable guest UUID. Guest requests are rate-limited; the DeckHTML CLI starts the guest task automatically. For production use, sign in or configure an API key.

```bash
deckhtml auth login
deckhtml auth status
deckhtml config set api-key <key>
```

For CI, set `DECKHTML_API_KEY` instead of storing credentials interactively.

See [Authentication](/deckhtml/authentication) for credential precedence, storage, and status behavior.

## Differences from local mode

- Conversion runs remotely through a DeckOps task.
- `--embed-fonts` is available for PPTX output.
- Result files are downloaded after the asynchronous task completes.
- Cloud report output currently uses aggregate conversion statistics when a per-element report is not returned.
- Local mapping controls (`--exclude`, identity attributes, animations, transitions, and iframe handling) are not forwarded to the current cloud task.

<Warning>
  Cloud PPTX conversion is remote, but the current CLI performs a local post-conversion HTML inspection to report slide and font statistics. A usable local Chromium is therefore still required for the CLI's cloud PPTX path. Cloud PNG skips this post-inspection.
</Warning>

`auto` mode selects cloud only when credentials are already configured; otherwise it selects local mode.
