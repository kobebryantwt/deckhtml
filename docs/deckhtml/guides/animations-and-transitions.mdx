DeckHTML distinguishes element entrance animations from slide-to-slide transitions.

## Element animations

Animation conversion is enabled by default for PPTX. DeckHTML can capture:

- `data-animation` declarations with optional duration, delay, and trigger attributes
- supported CSS `@keyframes`
- class-gated opacity or transform transitions
- intercepted global anime.js calls

Declared effects currently map these names: `appear`, `fade`/`fade-in`, four `fly-in-*` directions, `zoom`/`zoom-in`, `spin` variants, and four `wipe-*` directions. Triggers accept `click`, `with`, or `after` (and their `*Previous` aliases). An animation outside the supported subset keeps its final visual state and produces a `DECKHTML_ANIMATION_UNMAPPED` diagnostic.

```html
<h1
  data-element-id="title"
  data-animation="fade"
  data-animation-duration="600"
  data-animation-trigger="after"
>
  Product update
</h1>
```

Disable entrance-animation export with `--no-animations` or `animations: false`.

Animation mapping applies to local PPTX generation. PNG captures the settled visible state, and the current cloud CLI task does not receive local animation options.

## Slide transitions

Transitions are enabled by default for local PPTX and use a random catalog effect per slide. Select one effect, cycle through a comma-separated list, or disable transitions. Common base effects include `fade`, `push`, `wipe`, `cover`, `pull`, `split`, and `dissolve`; an unknown name is rejected and the CLI error lists the available catalog.

```bash
deckhtml deck.html -o deck.pptx --slide-transition fade
deckhtml deck.html -o deck.pptx --slide-transition fade,push,wipe
deckhtml deck.html -o deck.pptx --no-slide-transitions
```

For deterministic random selection in application code, pass a transition object with a `seed` through the Node API.
