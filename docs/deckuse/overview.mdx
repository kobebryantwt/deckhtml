DeckUse lets applications, scripts, and coding agents maintain an existing PPTX without launching Microsoft PowerPoint or another desktop Office application. Find the slides or elements you want to update, change content and properties, add or remove supported objects, then export another PPTX that remains editable. All processing runs locally without uploading the presentation.

| Item | At a glance |
| --- | --- |
| Input | An existing `.pptx` file |
| Result | An updated, editable `.pptx` file |
| Execution | Local Node.js process; documents are not uploaded |
| Interfaces | `deckuse` CLI and Node.js `runCommand()` API |
| Authentication | None |

## Use DeckUse for

- Applying the same approved content or property change across many presentations.
- Producing customer, region, language, or campaign variants from an existing PPTX.
- Letting an agent locate and update specific slides or elements through stable references.
- Integrating PPTX changes, validation, and export into a local application or automation pipeline.
- Keeping the source and generated presentations on the current machine.

## What you can change

- Inspect slides, text boxes, shapes, groups, pictures, tables, charts, notes, layouts, masters, and themes that are present in the PPTX index.
- Query elements by kind, name, text, regular expression, slide ID, element ID, or text presence.
- Set or replace text; update position, size, rotation, fill, stroke, text styling, names, and visibility.
- Add, duplicate, or remove slides and supported elements; add pictures and tables; replace embedded pictures.
- Read speaker notes and table cells; update chart titles, series names, and cached values.
- Group several mutations into a dry run or an atomic batch and retain an operation log.

<Note>
  DeckUse is structural, not visual. It does not render slides, detect overlap, judge layout quality, or decide which edits are appropriate. Render or open the exported PPTX before delivery.
</Note>

## How changes are applied

```text
existing.pptx → create workspace → inspect / query → apply changes
              → validate → export → updated.pptx
```

The workspace keeps the indexed document state, current revision, operation log, and package files needed for validation and export. CLI commands and the Node.js API use the same versioned command protocol, so a workflow can review targets before applying a change and detect conflicting revisions.

## PPTX preservation boundary

DeckUse preserves unknown package parts and untouched XML where possible. ZIP entries are recompressed, so an unchanged entry is compared by its uncompressed content rather than byte-for-byte ZIP identity. Text replacement can collapse multiple text runs into one run while retaining the first run's style.
