Selectors filter the workspace index. Use a broad query to discover candidates, review their text and geometry, then pass a returned `ref` to commands that must change one exact element.

## String selector syntax

Space-separated terms are combined with AND.

| Form | Example | Match behavior |
| --- | --- | --- |
| Everything | `*` or `all` | Every indexed element |
| Free text | `Quarter` | Case-insensitive substring across kind, name, text, element ID, and slide ID |
| Kind | `kind=textbox` | Case-insensitive substring of the indexed kind |
| Name | `name=Title` | Case-insensitive substring of the object name |
| Literal text | `text=Revenue` | Case-insensitive substring of element text |
| Regular expression | `text~=^FY20[0-9]{2}$` | Unicode regular expression evaluated against element text |
| Text presence | `hasText=true` | Elements with non-empty indexed text |
| Slide ID | `slide=256` | Elements whose stable presentation slide ID contains `256` |
| Element ID | `id=256:10` | Elements whose ID contains the supplied value |

```bash
deckuse query ./workspace 'kind=textbox hasText=true' --limit 500 --json
deckuse query ./workspace 'text=Revenue' --json
deckuse query ./workspace 'text~=https?://' --limit 1000 --json
deckuse query ./workspace 'slide=256 kind=picture' --json
```

String selector values cannot contain spaces because spaces separate terms. Use a shorter unambiguous substring, a regular expression without literal spaces, or a structured selector through the Node.js API when the value itself must contain spaces.

## Structured selectors

JSON commands and the Node.js API also accept an object with these optional fields:

```json
{
  "kind": "textbox",
  "name": "Title",
  "text": "Quarterly Revenue",
  "textRegex": "^FY20[0-9]{2}$",
  "id": "256:10",
  "slide": "256",
  "hasText": true
}
```

All supplied fields must match. Invalid regular expressions simply match no elements in a query; validate user-authored expressions before relying on an empty result.

## Read and reuse a reference

A query result includes a reference similar to:

```json
{
  "documentId": "/absolute/path/workspace",
  "elementId": "256:10",
  "path": "/ppt/slides/slide1.xml#256:10",
  "revision": "msok74co-006861c9"
}
```

- `documentId` identifies the workspace.
- `elementId` combines the presentation slide ID with the element's OOXML non-visual ID path.
- `path` provides a structural alternative.
- `revision` protects a targeted mutation from using a stale reference.

Every persisted mutation creates a new workspace revision. Query again after a mutation before issuing another revision-bound targeted edit, or put related edits into one atomic batch built from the same inspected revision. Do not copy example IDs into another presentation.

<Note>
  Slide IDs are PowerPoint presentation IDs, not one-based page numbers. Query `kind=slide` to discover the IDs in the current file.
</Note>
