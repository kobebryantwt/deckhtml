DeckHTML has a small set of ideas that show up across the CLI, SDK, and MCP surfaces.

## Input

DeckHTML accepts HTML from three common sources:

- Local files
- Standard input
- Hosted URLs

For multi-slide workflows, you can provide multiple ordered HTML files and treat them as a single deck build.

## Output

DeckHTML currently focuses on two output families:

- `pptx` for editable slide decks
- `png` for image frames or previews

## Modes

There are two high-level execution modes:

- Local mode runs the conversion pipeline on the machine invoking DeckHTML.
- Cloud mode delegates execution to a remote service and unlocks cloud-only font embedding.

## Structured results

CLI and automation workflows benefit from machine-readable output. DeckHTML supports JSON responses and optional report generation so CI jobs and agent tools can consume results deterministically.

## Integrations

The same conceptual model is exposed through multiple surfaces:

- CLI for human-operated terminal usage
- SDK for application integration
- MCP for agent tooling and editor integrations
