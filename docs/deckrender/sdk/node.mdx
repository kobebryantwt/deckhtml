The package root provides the Node.js API and requires Node.js 18 or later. A normal installation includes optional local-rendering dependencies; use `--omit=optional` for a cloud-only service.

```bash
npm install @deckflow/deckrender
```

## Render locally

```ts
import { render } from '@deckflow/deckrender';

const result = await render({
  input: './deck.pptx',
  engine: 'local',
  format: 'image',
  imageFormat: 'png',
  pages: '1-5',
  width: 1920,
  out: './frames/',
});

console.log(result.engine); // local
console.log(result.route);  // local.office2html, local.capture
```

Local PPTX and PDF routes do not resolve credentials, contact DeckFlow, or upload document bytes. The execution machine needs the dependencies described in [Local and Cloud Engines](/deckrender/engines). Explicit `local` execution never falls back to cloud.

## Render through DeckFlow cloud

```ts
import { render } from '@deckflow/deckrender';

const result = await render({
  input: './deck.pptx',
  engine: 'cloud',
  format: 'video',
  out: './deck.mp4',
  apiKey: process.env.DECKFLOW_API_KEY,
});
```

Omit credentials for rate-limited guest mode. Cloud routes upload the source and any intermediate artifacts. A URL is fetched by the local Node.js process first; DeckRender does not inherit the user's browser cookies or current DOM.

Use `engine: 'auto'` for local-first selection. If the exact local route is unavailable, DeckRender calls `onWarning` before choosing cloud.

## Reuse a renderer

```ts
import { createRenderer } from '@deckflow/deckrender';

const renderer = createRenderer({
  apiKey: process.env.DECKFLOW_API_KEY,
  onWarning: (message) => console.warn(message),
});

const result = await renderer.render({
  input: './report.pdf',
  engine: 'auto',
  format: 'image',
  pages: '1,3,5-7',
  out: './report-pages/',
  onProgress: ({ phase, message, ratio }) => console.log({ phase, message, ratio }),
});
```

## Render options

| Field | Type | Notes |
| --- | --- | --- |
| `input` | `string` | File path, HTTP(S) URL, or `-` for stdin |
| `engine` | `'local' \| 'cloud' \| 'auto'` | Explicit value, then `DECKRENDER_ENGINE`, then `cloud`; SDK calls do not read CLI render-default files |
| `from` | `SourceFormat` | Explicit input type; required for stdin |
| `format` | `'image' \| 'pdf' \| 'video'` | Defaults to `image` |
| `imageFormat` | `'png' \| 'jpg' \| 'webp'` | Depends on the selected engine and route |
| `out` | `string` | File, directory, ZIP, or `-` |
| `pages` | `string` | 1-based selection such as `1-5` or `1,3,7-9` |
| `width` / `scale` | `number` | Image sizing for compatible routes |
| `quality` | `'low' \| 'medium' \| 'high'` | Image preset |
| `embedFonts` | `boolean` | Cloud HTML routes passing through PPTX |
| `timeout` | `number` | Cloud task wait timeout in seconds |
| `onProgress` | `(event) => void` | Resolve, plan, upload, task, wait, download, and write phases |

The SDK does not apply CLI profiles or saved CLI render defaults automatically. Pass options explicitly, or use the exported `PROFILES` and `layerOptions` helpers.

Use the engine-specific helpers before presenting a route in an application:

```ts
import { findLocalRoute, findRoute, localSupportedTargets, supportedTargets } from '@deckflow/deckrender';

console.log(localSupportedTargets('pptx')); // ['image', 'pdf']
console.log(supportedTargets('docx'));      // cloud: ['image', 'pdf']
console.log(findLocalRoute('pptx', 'image')?.tasks);
console.log(findRoute('docx', 'image')?.tasks);
```

These helpers inspect the installed route tables and do not contact DeckFlow.

## Custom engines and clients

`createRenderer()` also accepts:

- `client`: an existing `@deckops/sdk` cloud client.
- `engine`: a custom `RenderEngine` implementation for backward compatibility.
- `customEngine`: the unambiguous spelling for a custom engine.
- `onUnauthorized` and `onPaymentRequired`: hooks for the built-in cloud client path.

A custom engine and a built-in engine name cannot control the same renderer invocation. An injected client is treated as already configured and must own its authentication hooks.

For frontend applications, use the separate [Browser SDK](/deckrender/sdk/browser); do not bundle the Node.js package root into the browser.

## Handle typed errors

```ts
import { DeckRenderError, render } from '@deckflow/deckrender';

try {
  await render({ input: './deck.pptx', engine: 'local', format: 'image' });
} catch (error) {
  if (error instanceof DeckRenderError) {
    console.error(error.code, error.message, error.hint);
  }
}
```

See the [Result Contract](/deckrender/reference/result-contract) for returned fields and error codes.
