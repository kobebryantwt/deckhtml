DeckRender keeps render preferences in `~/.deckrender/config.json`, separate from the shared Deckflow credential file.

```bash
deckrender config set profile web
deckrender config set image-format webp
deckrender config set width 2560
deckrender config unset width
deckrender config list
deckrender config path
```

## Supported keys

| Key | Values |
| --- | --- |
| `profile` | `web`, `presentation`, `print`, `thumbnail` |
| `format` | `image`, `pdf`, `video` |
| `image-format` | `png`, `jpg`, `webp` |
| `quality` | `low`, `medium`, `high` |
| `width` | Positive long-edge pixel value |
| `scale` | Positive multiplier |
| `timeout` | Positive task wait time in seconds |

Precedence is:

```text
profile defaults < ~/.deckrender/config.json < explicit CLI options
```

If a profile or stored default cannot apply to the selected route, DeckRender drops it with a warning. An incompatible option typed explicitly remains an `unsupported_option` error.

## Isolated environments

```bash
export DECKFLOW_CONFIG_DIR=/tmp/deckflow-ci
export DECKRENDER_CONFIG_DIR=/tmp/deckrender-ci
export DECKOPS_CONFIG_DIR=/tmp/deckops-ci
deckrender hello.html -o hello.png --json --quiet
```

All three directories are needed to prevent an older DeckOps token from being selected as a fallback credential.

Use [Authentication](/deckrender/authentication) for guest mode, login, API keys, shared credentials, and credential precedence.
