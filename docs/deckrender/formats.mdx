DeckRender routes one source format to one output family. Recognizing an input does not mean every output or option is available for it.

## Input and output matrix

| Input | Image | PDF | Video |
| --- | --- | --- | --- |
| PowerPoint `.pptx` | PNG, JPEG, WebP | Yes | MP4 |
| PDF `.pdf` | PNG, JPEG, WebP | Local passthrough | — |
| Keynote `.key` | PNG, WebP | Yes | — |
| Word `.docx` | PNG, JPEG, WebP | Yes | — |
| HTML `.html`, `.htm`, URL | PNG, WebP | Yes | MP4 |
| Markdown `.md`, `.markdown` | PNG, WebP | — | — |
| Pages `.pages` | Embedded JPEG preview | One-page PDF wrapper | — |
| Numbers `.numbers` | Embedded JPEG preview | One-page PDF wrapper | — |

- **Yes** means the installed package provides the route.
- **—** means that source/output combination is unavailable.

Query the installed version instead of hard-coding this table:

```bash
deckrender formats
deckrender formats --json
```

The JSON form reports route availability, route `kind`, task chain, and fidelity caveat for each source/output pair.

## Image options by source

Image controls belong to the task that creates the image, so they differ by route.

| Image source | `--width` / `--scale` | `--image-format` | `--pages` |
| --- | --- | --- | --- |
| PowerPoint `.pptx` | Snaps to 1080, 1920, or 2560 px | `png`, `jpg`, `webp` | Yes |
| PDF | Any positive long-edge value | `png`, `jpg`, `webp` | Yes |
| Word `.docx` | Any positive value on the PDF-to-image step | `png`, `jpg`, `webp` | Yes |
| Keynote | Not available | `png`, `webp` | Yes |
| HTML or URL as HTML | Width and scale | `png`, `webp` | No; one full-page image |
| Markdown | Page width and scale | `png`, `webp` | No; one image |
| Pages or Numbers | Not available | Embedded JPEG only | No; first page only |

On cloud routes, an explicit incompatible option normally fails with `unsupported_option`. A value inherited from a profile or saved config is normally dropped with a warning so a general default does not break an otherwise valid route.

<Warning>
  HTML and Markdown do not apply `--quality`; use `--width` or `--scale` instead. Pages and Numbers write the embedded JPEG without transcoding `--image-format`, so use a `.jpg` output name.
</Warning>

<Tip>
  WebP is a separate per-image cloud conversion step. With `--pages`, DeckRender filters frames before WebP conversion, so only selected pages enter that extra step.
</Tip>

## Route-specific behavior

<AccordionGroup>
  <Accordion title="HTML to PDF or video">
    DeckRender first converts HTML to PPTX, then exports that PPTX. PDF follows slide layout rather than native browser print layout; video is a slideshow of the reconstructed deck, not a recording of a live page. The result includes a `caveat`.
  </Accordion>
  <Accordion title="Word to image">
    Word is converted to PDF, then the PDF is rendered into page images. The result `route` contains both tasks, including the intermediate file transfer between them.
  </Accordion>
  <Accordion title="Pages and Numbers">
    These local routes extract `preview.jpg` (or a fallback preview) from the iWork package. Only the first page and its stored resolution are available. Image output should use a `.jpg` destination because no local transcoder runs. PDF output wraps the same JPEG in a single-page PDF; it is not a full Pages or Numbers render.
  </Accordion>
  <Accordion title="PDF to PDF">
    A local PDF file is copied through without upload or re-rendering. URL and stdin inputs do not have a local path and therefore cannot use this passthrough route.
  </Accordion>
  <Accordion title="URL input">
    Without `--from`, a URL is treated as HTML. DeckRender fetches it in the local Node.js process, inserts a base URL for relative assets, and uploads the resulting source. It does not capture the current cookies, login state, or runtime DOM from the user's browser. Use `--from` when the URL points to another supported file type.
  </Accordion>
</AccordionGroup>

## Page selection and single-file output

`--pages` and `--page` apply only to multi-frame image routes. Selection happens after the base cloud render, so it reduces downloads and written files, but not the pages rendered by the base task or its compute cost.

PDF and video are single-file outputs. They reject sizing, image encoding, quality, and page-selection options because those controls apply to image routes.
