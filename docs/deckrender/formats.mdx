Format support depends on the selected engine. Check the installed package instead of assuming that a format available in cloud is also available locally.

```bash
deckrender formats --engine local
deckrender formats --engine cloud
deckrender formats --engine auto --json
```

## Local engine

| Input | Image | PDF | Video |
| --- | --- | --- | --- |
| PowerPoint `.pptx` | PNG, JPEG | Yes | — |
| PDF `.pdf` | PNG, JPEG | Unchanged passthrough | — |
| HTML `.html`, `.htm`, URL | PNG, JPEG | — | — |

Local PPTX and PDF routes keep document bytes on the machine. Local HTML does not contact DeckFlow, but the page may load its own remote resources. See [Local and Cloud Engines](/deckrender/engines) for dependencies and fidelity boundaries.

## Cloud engine

| Input | Image | PDF | Video |
| --- | --- | --- | --- |
| PowerPoint `.pptx` | PNG, JPEG, WebP | Yes | MP4 |
| PDF `.pdf` | PNG, JPEG, WebP | Unchanged passthrough | — |
| Keynote `.key` | PNG, WebP | Yes | — |
| Word `.docx` | PNG, JPEG, WebP | Yes | — |
| HTML `.html`, `.htm`, URL | PNG, WebP | Yes | MP4 |
| Markdown `.md`, `.markdown` | PNG, WebP | — | — |

Every cloud conversion uploads the source. Derived routes also transfer intermediate artifacts; for example, Word→image runs DOCX→PDF and then PDF→image. PDF→PDF remains a local passthrough because no conversion is required.

## Image controls

| Engine and input | `--width` / `--scale` | `--image-format` | `--pages` |
| --- | --- | --- | --- |
| Local PPTX | Continuous sizing | `png`, `jpg` | Yes; only selected slides are captured |
| Local PDF | Continuous sizing | `png`, `jpg` | Yes; only selected pages are rasterized |
| Local HTML/URL | Width and scale | `png`, `jpg` | No; one generic capture |
| Cloud PPTX | Snaps to 1080, 1920, or 2560 px | `png`, `jpg`, `webp` | Yes |
| Cloud PDF or DOCX-derived image | Any positive long-edge value | `png`, `jpg`, `webp` | Yes |
| Cloud Keynote | Not available | `png`, `webp` | Yes |
| Cloud HTML/URL | Width and scale | `png`, `webp` | No; one image |
| Cloud Markdown | Page width and scale | `png`, `webp` | No; one image |

An incompatible explicit option fails with `unsupported_option`; it is never silently ignored or converted through another engine. WebP uses an additional per-image cloud conversion step. Page selection happens before that step.

## Route behavior

<AccordionGroup>
  <Accordion title="Local PPTX rendering">
    DeckRender converts PPTX to HTML with `office2html`, captures slides with Chromium, and merges page PDFs when PDF output is requested. External CDN assets emitted by the converter are blocked; system fonts, icons, and complex Office effects may differ from the managed cloud pipeline.
  </Accordion>
  <Accordion title="Local PDF rendering">
    PDF images are rasterized through PDF.js in Chromium. PDF→PDF copies the original file without rendering or upload.
  </Accordion>
  <Accordion title="HTML to cloud PDF or video">
    Cloud execution first reconstructs HTML as PPTX. PDF follows slide layout rather than browser print layout, and video is a slideshow of the reconstructed deck rather than a live-page recording. The result includes a `caveat`.
  </Accordion>
  <Accordion title="Word to cloud image">
    Word is converted to PDF, then the PDF is rendered into page images. The returned `route` includes both cloud tasks.
  </Accordion>
  <Accordion title="URL input">
    The Node.js CLI and SDK fetch a URL locally. Local mode captures the fetched HTML on the machine; cloud mode uploads it after adding a base URL for relative assets. Neither mode inherits the user's browser cookies or current DOM.
  </Accordion>
</AccordionGroup>

PDF and video are single-file outputs and do not accept image sizing, encoding, quality, or page-selection options. See [Render PDF and Video](/deckrender/guides/render-pdf-and-video) for executable examples.
