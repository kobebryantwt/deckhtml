The CLI `--json` mode and Node.js API return the same `RenderResult` shape after artifacts are written.

```ts
interface RenderResult {
  ok: true;
  input: string;
  format: 'image' | 'pdf' | 'video';
  engine: string;
  route: RenderStepTask[];
  pages: number;
  outputs: RenderOutputEntry[];
  durationMs: number;
  caveat?: string;
}

interface RenderOutputEntry {
  page: number;
  file: string;
  width?: number;
  height?: number;
  bytes?: number;
}
```

| Field | Meaning |
| --- | --- |
| `input` | Original display path, URL, or `-` |
| `format` | Requested output family |
| `engine` | Built-in executor selected: `cloud`, `local`, or `passthrough` |
| `route` | Ordered steps such as `local.office2html`, `local.capture`, cloud task names, or `passthrough` |
| `pages` | Total pages produced before page filtering |
| `outputs` | Files or stream entries actually written after filtering |
| `durationMs` | End-to-end time including input resolution and artifact writing |
| `caveat` | Known fidelity limitation for the chosen route, when applicable |

The render plan and `route` are execution metadata. They do not contain parsed pages, elements, text, or Document IR.

Local PPTX image output, for example, reports:

```json
{
  "engine": "local",
  "route": ["local.office2html", "local.capture"]
}
```

The Browser SDK returns a related `BrowserRenderResult`. Its outputs contain temporary remote or Object URLs with a `blob()` method instead of Node.js `file` paths, and the result provides `dispose()` for SDK-owned Object URLs. See [Browser SDK](/deckrender/sdk/browser).

Output entry paths depend on the destination:

- Regular file and directory output uses the path written by DeckRender; relative `-o` values remain relative in the result.
- Raw stdout output uses `file: "-"`.
- For a ZIP destination, `outputs[].file` is the member name inside the archive, such as `001.png`, not the ZIP path. The CLI success line identifies the archive itself.

## Errors

The Node.js API throws `DeckRenderError`, which exposes `code`, `message`, optional `hint`, and optional backend `requestId`.

| Code | Meaning |
| --- | --- |
| `usage_error` | Invalid or conflicting invocation |
| `unsupported_format` | No route for the source and target pair |
| `unsupported_option` | The route exists but cannot apply an explicit option |
| `not_implemented` | The installed version recognizes but has not implemented the route |
| `auth_error` | Credential is required, invalid, or rejected |
| `render_error` | Rendering failed |
| `conversion_error` | An artifact could not be retrieved or written |

Use `deckrender formats --json` at runtime when software needs to discover the installed version's supported routes.
