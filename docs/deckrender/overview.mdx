DeckRender turns supported documents into visual artifacts for previews, delivery, visual review, and multimodal workflows. The CLI and Node.js SDK can use a private local engine or DeckFlow cloud; the Browser SDK provides cloud rendering directly from a web application.

| Item | At a glance |
| --- | --- |
| Inputs | `.pptx`, `.pdf`, HTML, URL, and additional cloud-supported formats |
| Outputs | PNG, JPEG, or WebP images; PDF; MP4 video |
| Interfaces | `deckrender` CLI, Node.js SDK, and cloud-only Browser SDK |
| Execution | Local for implemented PPTX/PDF/HTML routes, or DeckFlow cloud for broader coverage |
| Authentication | None for local routes; guest mode, API key, or session token for cloud routes |

## Use DeckRender for

- Page or slide previews and thumbnails.
- PNG, JPEG, or WebP frames for review, search, or visual pipelines.
- PDF delivery from supported presentation, document, or HTML inputs.
- MP4 slideshow output from PowerPoint, or from HTML through a PPTX route.
- A stable artifact and result contract across local and cloud render routes.
- Private local rendering for supported PPTX, PDF, and HTML routes without uploading document bytes to DeckFlow.

## How one render runs

<Steps>
  <Step title="Resolve the input">
    Read one file or stdin stream, or fetch one URL in the local Node.js process.
  </Step>
  <Step title="Choose an engine and route">
    Use `local`, `cloud`, or local-first `auto`, then match the source, output family, and compatible options against that engine's route table.
  </Step>
  <Step title="Execute locally or in the cloud">
    Local routes keep supported document processing on the machine. Cloud routes upload the source and execute managed conversion tasks.
  </Step>
  <Step title="Write and report the result">
    Download and write the requested artifact layout, then return a `RenderResult` describing the route and written files.
  </Step>
</Steps>

<Tip>
  DeckRender does not parse text or document elements, return Document IR, or edit source content. Its internal `RenderPlan` describes the execution route only.
</Tip>

## Data and execution boundary

An explicit `local` selection never uploads the document or falls back to cloud. It currently covers PPTX→image/PDF, PDF→image/PDF, and HTML or URL→image. Local PPTX and PDF routes do not resolve cloud credentials or contact DeckFlow. HTML pages may still fetch resources referenced by the page.

Cloud routes upload the source and any intermediate artifacts. Guest mode is available for evaluation; authenticated execution provides production quotas and workspace access. The default engine remains `cloud`, while `auto` chooses local when the exact route exists and warns before choosing cloud.

An HTTP(S) URL is fetched by the local Node.js process. DeckRender does not capture the current state, cookies, or authenticated session of the user's browser. In local mode the page is captured on the machine; in cloud mode the fetched source is uploaded.

<Warning>
  HTML-to-PDF and HTML-to-video first rebuild HTML as PPTX. The result follows a slide model rather than native print layout or a recording of a live page.
</Warning>
