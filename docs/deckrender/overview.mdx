DeckRender turns a document into visual artifacts. Give it a local file, URL, or stdin input and request images, a PDF, or a video; DeckRender selects a supported route, runs it, and writes predictable output files.

<CardGroup cols={3}>
  <Card title="Inputs" icon="file-import">
    Files, hosted HTML or Markdown, and stdin with an explicit source format.
  </Card>
  <Card title="Outputs" icon="images">
    PNG, JPEG, or WebP frames; PDF documents; or MP4 video where supported.
  </Card>
  <Card title="Interfaces" icon="terminal">
    The `deckrender` CLI and the `@deckflow/deckrender` Node.js API ship together.
  </Card>
</CardGroup>

## What DeckRender does

- Resolves and classifies the input.
- Selects a direct, multi-step, local, or passthrough rendering route.
- Applies route-compatible sizing, image encoding, and page selection.
- Writes one artifact, numbered frames, or a ZIP archive.
- Returns a stable result describing the engine, route, pages, files, and duration.

DeckRender does not parse document content into an intermediate representation, extract text or semantic structure, or edit source elements. Its render plan describes execution only; it is not a model of the document.

## Execution model

Most routes execute through Deckflow cloud tasks. PDF passthrough and the embedded preview available in Pages and Numbers documents run locally. Authentication is optional: the CLI can use rate-limited guest mode, while login or an API key provides authenticated access.

<Warning>
  Pages and Numbers output is generated from the preview embedded by iWork. It contains only the first page and uses the resolution stored in the document.
</Warning>
