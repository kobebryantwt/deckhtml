DeckRender keeps result data on stdout and progress, warnings, and errors on stderr. This allows callers to parse stdout without filtering terminal messages.

```bash
result=$(deckrender deck.pptx --json --quiet)
first_file=$(printf '%s' "$result" | jq -r '.outputs[0].file')
```

`--json` keeps the success document on stdout. Warnings are emitted as separate JSON objects on stderr. Add `--quiet` when automation needs stderr to contain only a final failure envelope.

## Success envelope

```json
{
  "ok": true,
  "input": "deck.pptx",
  "format": "image",
  "engine": "cloud",
  "route": ["convertor.ppt2image"],
  "pages": 3,
  "outputs": [
    {
      "page": 1,
      "file": "deck/001.png",
      "width": 1920,
      "height": 1080,
      "bytes": 184320
    }
  ],
  "durationMs": 8123
}
```

`pages` is the total page count before `--pages` filtering. `outputs` contains only the artifacts written by this invocation. A `caveat` field appears when the selected route has a known fidelity trade-off.

## Failure envelope

With `--json`, failures are written to stderr:

```json
{
  "ok": false,
  "error": {
    "code": "unsupported_option",
    "message": "--width is not supported for .key input.",
    "hint": "The selected route does not expose a resolution parameter."
  }
}
```

Backend failures may also include `requestId`; include it when reporting a service issue.

Without `--quiet`, stderr can contain newline-delimited warning objects before the final error object:

```jsonl
{"warning":"Resolution 2000 snapped to 1920: convertor.ppt2image accepts only 1080/1920/2560."}
{"ok":false,"error":{"code":"render_error","message":"Task convertor.ppt2image failed: ..."}}
```

For the simplest error parser, use `--json --quiet`. If warnings are needed, read stderr as JSON Lines and treat the last object containing `error` as the failure envelope.

## Exit codes

| Exit | Meaning | Error codes |
| --- | --- | --- |
| `0` | Success | — |
| `1` | Rendering or artifact conversion failed | `render_error`, `conversion_error` |
| `2` | The invocation, format pair, or option cannot run | `usage_error`, `unsupported_format`, `unsupported_option`, `not_implemented` |
| `3` | Credentials were required or rejected | `auth_error` |

When a configured credential is rejected, DeckRender warns and retries once as a guest. If the guest request is also rejected, CI and JSON mode return `auth_error` without opening an interactive login window. A `402 Payment Required` is never retried as guest.

```bash
export DECKFLOW_API_KEY='...'
deckrender deck.pptx --json --quiet
```

## Raw artifact streaming

For a single artifact, `-o -` writes bytes only:

```bash
deckrender page.html -o - > page.png
```

It cannot be combined with `--json`, and it fails if the route yields multiple frames.

## A complete CI pattern

```bash
set +e
deckrender deck.pptx --json --quiet -o frames/ > result.json 2> error.json
code=$?
set -e

case "$code" in
  0) jq -r '.outputs[].file' result.json ;;
  2) jq -r '.error.code + ": " + .error.message' error.json >&2 ;;
  3) echo "Configure DeckRender credentials before this job" >&2 ;;
  *) jq -r '.error.message' error.json >&2 ;;
esac

exit "$code"
```

Exit `2` covers invalid usage, unsupported combinations, unsupported options, and planned-but-unimplemented routes. Inspect `error.code` to distinguish them.
