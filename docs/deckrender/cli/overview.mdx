```bash
deckrender <input> [options]
deckrender <command> [options]
```

Each invocation renders one file path, HTTP(S) URL, or stdin stream.

## Input forms

```bash
deckrender deck.pptx
deckrender https://example.com/page.html -o page.png
cat page.html | deckrender - --from html -o page.png
```

Stdin has no filename, so `--from` is required. A URL defaults to HTML unless `--from` says otherwise. DeckRender fetches URL content locally and inserts a base URL when needed so relative page assets can resolve during rendering.

For a URL that points directly to another supported file, specify its type:

```bash
deckrender https://example.com/deck.pptx --from pptx -o frames/
```

URL requests do not inherit browser cookies, custom request headers, or a logged-in browser session. Download protected input in the application first, then pass the local file to DeckRender.

## Common render options

| Option | Purpose |
| --- | --- |
| `-o, --output <path>` | File, directory, `.zip`, or `-` for raw stdout bytes |
| `--engine <engine>` | `local`, `cloud`, or local-first `auto` |
| `--format <format>` | `image`, `pdf`, or `video`; otherwise inferred from `-o` or defaults to image |
| `--image-format <format>` | `png`, `jpg`, or `webp` |
| `--from <format>` | Override the source format; required for stdin |
| `--pages <ranges>` | Keep 1-based pages such as `1-5` or `1,3,5-7` |
| `--page <n>` | Keep one page; conflicts with `--pages` |
| `--width <px>` | Target long edge when the route supports it |
| `--scale <n>` | Multiply the route's default long edge |
| `--quality <level>` | `low`, `medium`, or `high` image preset |
| `--profile <name>` | `web`, `presentation`, `print`, or `thumbnail` |
| `--embed-fonts` | Embed fonts on routes that pass through HTML to PPTX |
| `--timeout <seconds>` | Cloud task wait timeout; default `300` |
| `--json` | Emit a machine-readable result on stdout |
| `--quiet` | Suppress progress and warnings |
| `-v, --verbose` | Emit detailed diagnostics to stderr |

`--quiet` and `--verbose` conflict. Option support depends on the selected route; most incompatible explicit options fail with `unsupported_option`. Check [Supported Formats](/deckrender/formats) for the route and option matrix.

The output extension can infer both output family and image encoding:

```bash
deckrender deck.pptx -o deck.pdf       # PDF
deckrender deck.pptx -o frame.webp     # WebP image output
deckrender deck.pptx --format video -o deck.mp4
```

If `--format` conflicts with the `-o` extension, `--format` wins and DeckRender warns. The filename is not renamed, so avoid combinations such as `--format pdf -o output.png` that put one file type behind another extension.

## Output path rules

| Situation | Written result |
| --- | --- |
| No `-o`, multiple images | `<input-name>/001.png`, `002.png`, … |
| No `-o`, one artifact | Beside the input with the target extension |
| Extensionless path or directory | Numbered artifacts inside the directory |
| File path and one artifact | Exactly that file |
| `out.png` and multiple images | `out-001.png`, `out-002.png`, … |
| `.zip` path | Numbered artifacts packed into the archive |
| `-o -` and one artifact | Raw artifact bytes on stdout |

Multiple artifacts cannot be streamed directly to stdout. Use a directory, a ZIP file, or narrow the result with `--pages`. Raw stdout and `--json` cannot be combined.

Page ranges are 1-based and inclusive. Local PPTX/PDF routes capture or rasterize only selected pages. Cloud routes render the complete source first, so selection reduces downloads and written files rather than base cloud compute. For WebP output, filtering happens before the per-frame conversion.

## Profiles

Profiles are named flag defaults, not different rendering engines. Explicit flags win.

| Profile | Defaults |
| --- | --- |
| `web` | Images, WebP, 1920 px, medium quality |
| `presentation` | Images, PNG, 1920 px, high quality |
| `print` | PDF |
| `thumbnail` | First page, JPEG, 640 px, low quality |

```bash
deckrender deck.pptx --profile web -o frames/
deckrender report.pdf --profile thumbnail -o cover.jpg
```

## Utility commands

| Command | Purpose |
| --- | --- |
| `deckrender formats [--engine local\|cloud\|auto] [--json]` | Show the route matrix for one engine selection |
| `deckrender auth login [--port N]` | Open browser login and store the returned session token |
| `deckrender auth status` | Validate effective credentials and display their source |
| `deckrender auth logout` | Remove credentials from the shared DeckFlow file |
| `deckrender auth path` | Print the shared credential path |
| `deckrender config set <key> <value>` | Save an API key or render default |
| `deckrender config unset <key>` | Remove one saved value |
| `deckrender config list` | Show effective settings, credentials, and their sources |
| `deckrender config path` | Print render and shared configuration paths |

```bash
deckrender formats
deckrender formats --engine local
deckrender auth login
deckrender auth status
deckrender auth logout
deckrender auth path
deckrender config list
deckrender config set profile web
deckrender config set engine local
deckrender config unset profile
deckrender config path
```

An explicit local engine never uploads or falls back to cloud. See [Local and Cloud Engines](/deckrender/engines) for installation and data boundaries, then continue with [automation and errors](/deckrender/cli/automation) for stable stdout/stderr behavior, JSON failures, and exit codes.
