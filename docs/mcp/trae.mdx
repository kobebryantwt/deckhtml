TRAE can use Deckflow MCP for HTML-to-PPTX, format conversion, and presentation-processing workflows. Unlike Claude Code or some CLI-first clients, TRAE does not currently rely on an `add mcp` terminal command. In practice, you add Deckflow from TRAE's MCP settings UI by choosing the manual configuration flow, then paste either a hosted Streamable HTTP config or a local stdio config.

<Note>
  Use the hosted Streamable HTTP config for the easiest setup and OAuth authorization flow. Use local stdio when TRAE needs to pass local absolute file paths to the MCP server.
</Note>

## Open the MCP configuration entry

<Steps>
  <Step title="Open TRAE settings">
    In TRAE, click the settings icon in the top-right corner, then switch to the `MCP` tab.
  </Step>
  <Step title="Add a custom MCP server">
    In `MCP Servers`, click `Add`, then choose the manual configuration option. TRAE opens an editable `mcp.json` tab for the new server entry.
  </Step>
</Steps>

![TRAE MCP settings entry](/images/mcp/trae-mcp-entry.png)

## Choose a configuration mode

<Tabs>
  <Tab title="Hosted Streamable HTTP">
    Paste this config into TRAE's `mcp.json` editor:

    ```json
    {
      "mcpServers": {
        "deckflow": {
          "url": "https://mcp.deckflow.com/mcp/v1/"
        }
      }
    }
    ```

    This mode connects TRAE to the hosted Deckflow MCP endpoint and then uses a browser-based authorization flow.
  </Tab>
  <Tab title="Local stdio">
    Paste this config when you want TRAE to talk to a locally running stdio server:

    ```json
    {
      "mcpServers": {
        "deckflow": {
          "command": "node",
          "args": ["/absolute/path/deckflow-mcp/dist/entry/stdio.js"],
          "env": {
            "DECKFLOW_API_KEY": "<your API key>"
          }
        }
      }
    }
    ```

    Use stdio mode when your workflow depends on local absolute file paths. Add `DECKFLOW_SPACE_ID` when you want all calls to resolve into a fixed Deckflow space.
  </Tab>
</Tabs>

## Hosted Streamable HTTP flow

<Steps>
  <Step title="Paste the hosted config">
    Use the hosted config shown above:

    ```json
    {
      "mcpServers": {
        "deckflow": {
          "url": "https://mcp.deckflow.com/mcp/v1/"
        }
      }
    }
    ```
  </Step>
  <Step title="Wait for the verification prompt">
    After saving the entry, TRAE shows the `deckflow` server in the MCP list. If authorization is still required, TRAE marks the server as needing verification and shows a link to continue the verification flow.
  </Step>
  <Step title="Complete authorization">
    Click the verification link, finish the browser authorization flow, then return to TRAE.
  </Step>
  <Step title="Confirm the server is ready">
    Once authorization succeeds, TRAE reports that verification completed successfully. You can then close the browser page and return to the MCP panel.
  </Step>
</Steps>

![TRAE verification required state](/images/mcp/trae-mcp-verify.png)

![TRAE verification success state](/images/mcp/trae-mcp-success.png)

## Local stdio flow

Paste this config into TRAE when you need a local stdio MCP server:

```json
{
  "mcpServers": {
    "deckflow": {
      "command": "node",
      "args": ["/absolute/path/deckflow-mcp/dist/entry/stdio.js"],
      "env": {
        "DECKFLOW_API_KEY": "<your API key>"
      }
    }
  }
}
```

TRAE does not need the OAuth verification screen in this mode. Instead, make sure the local server path is correct and the `DECKFLOW_API_KEY` environment variable is valid before you enable the server.

## Validation checklist

- TRAE shows the `deckflow` server as enabled in the MCP list.
- Hosted HTTP mode completes the verification step successfully.
- Deckflow tools are discoverable in the MCP tool list.
- A small utility call succeeds directly, or a long-running call returns a valid `taskId`.
- Completed tasks can be checked with `get_task` and downloaded with `download_task_result`.
