Deckflow MCP lets you connect Deckflow to MCP-compatible agents so they can turn HTML into editable PPTX decks, convert documents across delivery formats, and run presentation workflows without leaving the agent interface.

<Note>
  Use the hosted endpoint `https://mcp.deckflow.com/mcp/v1/` for most setups. The usual flow is: add the server, complete authentication if required, then start calling Deckflow tools.
</Note>

## Add Deckflow to Your Agent

<Steps>
  <Step title="Open your agent's MCP settings">
    In your agent, open the MCP, connectors, or tools settings area and choose the option for adding a custom server.
  </Step>
  <Step title="Paste the Deckflow MCP endpoint">
    Add the hosted Deckflow MCP URL:

    ```text
    https://mcp.deckflow.com/mcp/v1/
    ```
  </Step>
  <Step title="Authenticate if your client requires it">
    Some clients open a browser-based authorization flow after the server is added. Others let you store headers, query parameters, or local environment variables instead.
  </Step>
  <Step title="Verify the server and start using tools">
    After setup, confirm the `deckflow` server is connected, then try a small task such as converting HTML to PPTX or rendering a file into a delivery format.
  </Step>
</Steps>

<Tip>
  Menu names vary by client. Use the product guides below for the exact setup path supported by each agent.
</Tip>

## Supported Products

Deckflow MCP currently has setup guides for:

- [Codex](/mcp/codex): add Deckflow from Codex settings or by editing `~/.codex/config.toml`.
- [Cursor](/mcp/cursor): add Deckflow from Cursor MCP settings or by editing Cursor's MCP config file.
- [Claude Code](/mcp/claude-code): add Deckflow with `claude mcp add`, or by editing `~/.claude.json` / `.mcp.json`.

If your client supports custom MCP servers, the same hosted endpoint usually works there as well.

## What You Can Do

Once connected, your agent can use Deckflow for:

- [Turn HTML into editable PPTX](/mcp/tools#rendering-and-conversion): convert HTML slide pages or web-based presentation content into PPTX decks.
- [Convert files across delivery formats](/mcp/tools#rendering-and-conversion): move between PPTX, PDF, image, HTML, and related output formats for review, publishing, and handoff.
- [Process PPTX and related files](/mcp/tools#file-and-pptx-utilities): run OCR, compression, splitting, merging, font embedding, and inspection in the same workflow.
- [Generate, translate, and revamp presentations](/mcp/tools#presentation-and-document-creation): create draft decks from prompts and references, translate visual documents, and refresh existing presentations.

## Authentication and Transport

Most users should start with the hosted remote server:

```text
https://mcp.deckflow.com/mcp/v1/
```

Depending on the client, Deckflow MCP can be connected in one of three ways:

- **Client UI**: add a custom MCP server from a settings screen and finish browser-based auth if prompted.
- **Config file**: write the server entry directly into a local MCP config file such as `config.toml`, `mcp.json`, or `.mcp.json`.
- **CLI command**: register the server with a helper command such as `claude mcp add`.

If your workflow must pass local absolute file paths into the MCP server, use local `stdio` instead of the hosted endpoint. A typical shape looks like this:

```json
{
  "mcpServers": {
    "deckflow": {
      "command": "node",
      "args": ["/absolute/path/to/deckflow-mcp/dist/entry/stdio.js"],
      "env": {
        "DECKFLOW_API_KEY": "<your API key>"
      }
    }
  }
}
```

Use the hosted endpoint when you want the simplest setup. Use local `stdio` when the client must read local files directly from your machine.
