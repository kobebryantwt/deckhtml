Deckflow MCP lets your agent call Deckflow directly for presentation and document workflows. The most important use cases are turning HTML into PPTX decks, converting files across delivery formats, and handling PPTX or document-processing tasks without leaving the agent environment.

<Note>
  The production Streamable HTTP endpoint is `https://mcp.deckflow.com/mcp/v1/`. Menu names vary slightly by agent, but the setup flow is usually the same: add the server, authenticate, then start calling Deckflow tools.
</Note>

## Add Deckflow to your agent

<Steps>
  <Step title="Open your agent's MCP settings">
    In your MCP-compatible agent, open the MCP, connectors, or tools settings area and choose the option for adding a custom server.
  </Step>
  <Step title="Paste the Deckflow MCP endpoint">
    Use the hosted Streamable HTTP endpoint:

    ```text
    https://mcp.deckflow.com/mcp/v1/
    ```
  </Step>
  <Step title="Authenticate with OAuth or credentials">
    Prefer OAuth when your agent supports browser authorization. If it does not, use `Authorization: Bearer <API key>`, `X-Auth-Token: <user_... token>`, or `?API_KEY=<key>` depending on what the client can store.
  </Step>
  <Step title="Start creating">
    Ask the agent to convert HTML into PPTX, convert a file, inspect a deck, or run a document workflow. Long-running jobs return a `taskId`, which you can follow with `get_task` and `download_task_result`.
  </Step>
</Steps>

<Tip>
  Menu names vary slightly by client. For click-by-click setup, use the client-specific guides such as Codex, Cursor, or Claude Code.
</Tip>

## Transport options

<Tabs>
  <Tab title="Hosted HTTP">
    Use hosted HTTP when your MCP client can connect to a remote server.

    ```text
    https://mcp.deckflow.com/mcp/v1/
    ```

    Hosted HTTP supports OAuth, bearer API keys, user tokens, and `API_KEY` query credentials. In this mode, file inputs should be URLs or `fileId:<uploaded-file-id>` references.
  </Tab>
  <Tab title="Local stdio">
    Use local stdio when the MCP client should pass local absolute file paths to the server.

    ```json
    {
      "mcpServers": {
        "deckflow": {
          "command": "node",
          "args": ["/absolute/path/deckflow-mcp/dist/entry/stdio.js"],
          "env": {
            "DECKFLOW_API_KEY": "<your-api-key>"
          }
        }
      }
    }
    ```

    Stdio accepts local absolute paths, `http(s)` URLs, and `fileId:<uploaded-file-id>` inputs.
  </Tab>
</Tabs>

## Authentication choices

| Method | Best for | Notes |
|---|---|---|
| OAuth | Claude Code, Manus, and clients with remote MCP authorization | Add the URL and finish authorization in the browser. |
| `Authorization: Bearer <API key>` | Direct HTTP clients and controlled integrations | Optionally include `X-Space-Id`. |
| `X-Auth-Token: <user_... token>` | Existing Deckflow user-token workflows | Optionally include `X-Space-Id`. |
| `?API_KEY=<key>` | Clients that cannot send custom headers | Use only when headers or OAuth are unavailable. |
| `DECKFLOW_API_KEY` | Local stdio mode | Required for stdio unless credentials are supplied another way. |

<Tip>
  If your account belongs to multiple spaces, pass `DECKFLOW_SPACE_ID`, `X-Space-Id`, or `?spaceId=`. Without it, the server resolves the first activated space automatically.
</Tip>
