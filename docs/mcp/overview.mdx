Deckflow MCP is a hosted [Model Context Protocol](https://modelcontextprotocol.io) server for agent-driven presentation and document workflows. It lets tools such as Claude Code, Cursor, Codex, Manus, and other MCP clients call Deckflow capabilities directly instead of asking the model to compose shell commands by hand.

<Note>
  The production Streamable HTTP endpoint is `https://mcp.deckflow.com/mcp/v1/`. Use OAuth when your client supports remote MCP authorization. Use bearer credentials or query-based credentials only for clients that cannot complete OAuth.
</Note>

## How it works

<Steps>
  <Step title="Connect an MCP client">
    Add the hosted endpoint to an MCP-compatible client, or run the stdio entry locally when the client needs local file access.
  </Step>
  <Step title="Authenticate">
    Use OAuth for remote clients that support browser authorization. For direct integrations, send `Authorization: Bearer <API key>`, `X-Auth-Token: <user_... token>`, or `?API_KEY=<key>`.
  </Step>
  <Step title="Call a tool">
    Ask the agent to generate, translate, convert, render, inspect, or manage a task. Long-running creation tools return a `taskId` first.
  </Step>
  <Step title="Poll and download results">
    Use `get_task` to wait for completion and `download_task_result` to retrieve the generated artifact.
  </Step>
</Steps>

## Transport options

<Tabs>
  <Tab title="Hosted HTTP">
    Use hosted HTTP when your MCP client can connect to a remote server.

    ```text
    https://mcp.deckflow.com/mcp/v1/
    ```

    Hosted HTTP supports OAuth, bearer API keys, user tokens, and `API_KEY` query credentials. In this mode, file inputs should be URLs or `fileId:<uploaded-file-id>` references.
  </Tab>
  <Tab title="Local stdio">
    Use local stdio when the MCP client should pass local absolute file paths to the server.

    ```json
    {
      "mcpServers": {
        "deckflow": {
          "command": "node",
          "args": ["/absolute/path/deckflow-mcp/dist/entry/stdio.js"],
          "env": {
            "DECKFLOW_API_KEY": "<your-api-key>"
          }
        }
      }
    }
    ```

    Stdio accepts local absolute paths, `http(s)` URLs, and `fileId:<uploaded-file-id>` inputs.
  </Tab>
</Tabs>

## Authentication choices

| Method | Best for | Notes |
|---|---|---|
| OAuth | Claude Code, Manus, and clients with remote MCP authorization | Add the URL and finish authorization in the browser. |
| `Authorization: Bearer <API key>` | Direct HTTP clients and controlled integrations | Optionally include `X-Space-Id`. |
| `X-Auth-Token: <user_... token>` | Existing Deckflow user-token workflows | Optionally include `X-Space-Id`. |
| `?API_KEY=<key>` | Clients that cannot send custom headers | Use only when headers or OAuth are unavailable. |
| `DECKFLOW_API_KEY` | Local stdio mode | Required for stdio unless credentials are supplied another way. |

<Tip>
  If your account belongs to multiple spaces, pass `DECKFLOW_SPACE_ID`, `X-Space-Id`, or `?spaceId=`. Without it, the server resolves the first activated space automatically.
</Tip>
