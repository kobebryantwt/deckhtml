Claude Code can use Deckflow MCP as either a hosted HTTP server or a local stdio server. Hosted HTTP is the easiest path when you want browser-based OAuth. Local stdio is useful when the agent must pass local absolute file paths.

<Note>
  Prefer hosted HTTP for normal use. Use local stdio when your workflow depends on local files that are not available as URLs or uploaded `fileId` references.
</Note>

## Hosted HTTP setup

<Steps>
  <Step title="Add the Deckflow MCP endpoint">
    ```bash
    claude mcp add --transport http deckflow https://mcp.deckflow.com/mcp/v1/
    ```
  </Step>
  <Step title="Authorize in Claude Code">
    Run `/mcp` in Claude Code and follow the browser authorization prompt. The server supports MCP OAuth discovery, dynamic client registration, and PKCE.
  </Step>
  <Step title="Start a new Claude Code session">
    Ask Claude Code to list Deckflow tools or run a small task, such as rendering Markdown or converting a hosted file URL.
  </Step>
</Steps>

## Local stdio setup

Build the MCP server locally, then register the stdio entry:

```bash
npm install
npm run build

claude mcp add deckflow \
  -e DECKFLOW_API_KEY=<key> \
  -- node /absolute/path/deckflow-mcp/dist/entry/stdio.js
```

Add `DECKFLOW_SPACE_ID=<spaceId>` when you want all calls to use a specific Deckflow space.

## File input behavior

| Transport | Accepted file inputs |
|---|---|
| Hosted HTTP | `http(s)` URLs and `fileId:<uploaded-file-id>` |
| Local stdio | Local absolute paths, `http(s)` URLs, and `fileId:<uploaded-file-id>` |

## Validation checklist

- Claude Code lists the `deckflow` server in `/mcp`.
- Tool discovery shows generation, translation, rendering, file utility, and task management tools.
- A small utility task returns either a completed result or a `taskId`.
- Long-running tasks can be checked with `get_task` and downloaded with `download_task_result`.
