Deckflow's tool APIs still submit through the same `POST /tools/tasks` endpoint. What changes is the `type` value, accepted file formats, file-size limits, and any tool-specific JSON sent through `params`.

## Shared tool form-data fields

| Field | Type | Required | Meaning |
|---|---|---|---|
| `files` | `File` | Yes | Source files to process. Multiple files are supported. Some merge workflows require at least two files. |
| `type` | `String` | Yes | Tool task identifier such as `convertor.html2pptx` or `image.ocr`. |
| `params` | `String (JSON)` | No | Tool-specific JSON parameters. Defaults to `{}` when not required. |
| `notifyURL` | `String` | No | Webhook callback URL for task status changes. |

## Common rule

No matter which tool group you choose:

- submit through `POST /tools/tasks`
- encode tool-specific settings in `params`
- poll through `GET /tools/tasks/{id}`
- optionally download the result through `GET /tools/tasks/{id}/download`
