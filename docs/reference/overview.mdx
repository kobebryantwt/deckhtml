Deckflow's API is organized around a simple async task model. Even though the product exposes multiple business scenarios such as generation, translation, revamp, and file tools, they all build on the same two core endpoints:

- `POST /tools/tasks`
- `GET /tools/tasks/{id}`

This reference is therefore split into two layers:

- **Core APIs**: the actual submit and query endpoints
- **Scenario guides**: how to use `type` and `params` for generation, translation, revamp, and tool workflows

<Note>
  The interactive API pages are generated from the OpenAPI file in this repository, while the scenario guides explain how to map the same endpoints to different product use cases.
</Note>

## Shared model

Deckflow uses the same async lifecycle across business scenarios:

- Authenticate with `Authorization: Bearer <YOUR_API_KEY>`.
- Submit files, task type, and JSON options as `multipart/form-data`.
- Receive a task identifier immediately.
- Poll the task endpoint until the job is complete or failed.
- Download the final file from the signed URL returned in the task result.
