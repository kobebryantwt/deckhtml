DeckOps turns a document into a durable, agent-operable intermediate representation. Parse once to create a local artifact, then read the IR or generate Markdown repeatedly without reopening the source document.

| | At a glance |
| --- | --- |
| Best for | Search ingestion, retrieval pipelines, document understanding, and repeatable downstream processing |
| Local inputs | PDF, PPTX, DOCX, and static web-page source |
| Cloud inputs | Keynote and web pages that require runtime rendering; local formats can also be uploaded explicitly |
| Primary result | A versioned artifact containing `deckir.v1`, assets, quality information, and an optional DeckProbe report |
| Derived view | Markdown, including optional page splitting or PDF source anchors |
| Interfaces | CLI, Node.js SDK, and a cloud-only Browser SDK |

## What DeckOps gives your application

- **One document model:** pages, nodes, text runs, geometry, source references, assets, and quality checks use the public `deckir.v1` schema.
- **A reusable artifact:** the source hash, parser identity, options, IR, assets, and generated views are stored together.
- **A visible quality boundary:** partial or opaque content is reported rather than silently approximated.
- **Local-first execution:** PDF, PPTX, DOCX, and static URL source use local parsers by default and do not require credentials.
- **Explicit cloud execution:** use the cloud engine for Keynote, runtime web pages, or when your application deliberately chooses cloud parsing.

```text
document ── parse ──> artifact/
                       ├── ir.json
                       ├── manifest.json
                       ├── probe.json
                       ├── assets/
                       └── views/markdown/
                                ↑
                         convert from IR
```

<Tip>
  `parse` is the only operation that reads and interprets the source. `convert` consumes an existing artifact; when given a document directly, it performs the parse and conversion as a one-shot convenience.
</Tip>

## Choose an execution engine

- `local` is the default. It keeps supported files on the machine and needs no DeckFlow account.
- `cloud` explicitly uploads the input and requires an available guest or authenticated cloud path.
- `auto` still starts locally. It may upload only when `--allow-upload` or `allowUpload: true` explicitly grants permission.

The browser entry is cloud-only: it can inspect a selected local file with DeckProbe before upload, but document parsing itself runs in DeckFlow cloud.
