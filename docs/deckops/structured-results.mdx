`ir.json` is a cross-format `deckir.v1` document. It gives applications one stable envelope while allowing source-specific detail through node types, styles, source references, and extensions.

## Top-level shape

```json
{
  "schemaVersion": "deckir.v1",
  "format": "pptx",
  "source": {
    "sha256": "<source-sha256>",
    "name": "slides.pptx",
    "bytes": 45210
  },
  "producer": {
    "engine": "local",
    "name": "deckparse-pptx",
    "version": "1"
  },
  "document": {
    "metadata": {},
    "pages": [],
    "nodes": [],
    "assets": []
  },
  "quality": {
    "status": "pass",
    "checks": [],
    "coverage": {}
  }
}
```

## Pages and nodes

Each page has a stable ID, zero-based index, optional dimensions, ordered node IDs, and a source reference. Nodes form a tree through `parentId` and `children` and can include:

- `type`, `order`, text, rich-text runs, style, and links
- page, bounding box, and z-index when the source exposes layout
- confidence and issue codes
- an `opaque` record when DeckOps can retain an object but cannot fully interpret it
- `extensions` for format-specific information that does not belong in the common fields

`sourceRef` records where a page or node came from, such as a page index, part name, XML path, object ID, byte range, or character span. Use these references for traceability instead of inferring source locations from Markdown order.

## Assets

Asset records contain a stable ID, artifact-relative path, hash, byte size, optional media type, and optional source reference. Nodes refer to these persistent identities; applications should resolve paths relative to the artifact directory.

## Quality report

The quality report separates a successful parse from its fidelity:

- `status` is `pass`, `degraded`, or `unsupported`.
- `checks` contain a stable code, severity, message, and optional page/node detail.
- `coverage` can report parsed pages, parsed versus opaque objects, and text-character counts.
- `recommendation: "cloud"` indicates that cloud parsing may improve a local result; it does not trigger an upload.

Use `--fail-on-degraded` when degraded output should fail a CLI job. Otherwise, consume the IR and surface relevant checks in your own workflow.

## Validate the schema

The published npm package exports the JSON Schema:

```js
import schema from '@deckflow/deckops/schemas/deckir.v1.schema' with { type: 'json' };
```

The Node.js SDK also exports `validateDeckIR()` for runtime validation.
