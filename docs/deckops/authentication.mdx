Local parsing and conversion need no DeckFlow account. Authentication is resolved only when DeckOps actually selects the cloud engine, such as for Keynote, runtime URL parsing, or an explicit `--engine cloud` request.

## Get an API key

Open [DeckFlow Settings](https://app.deckflow.com/start#settings), enter the settings page, and create or copy an API key. Store it in a secret manager and expose it only to server-side processes.

```bash
export DECKOPS_API_KEY="<api-key>"
deckops parse slides.key --engine cloud
```

`DECKOPS_API_KEY` takes priority over the shared `DECKFLOW_API_KEY`. Never embed either value in frontend JavaScript.

## Browser login for the CLI

```bash
deckops auth login
deckops auth status
deckops config list
```

Login stores a user token in the shared DeckFlow credential location. DeckOps, DeckRender, and DeckHTML can reuse the same login. Use `deckops auth logout` to remove it.

Credentials are stored under `~/.deckflow/credentials`; product defaults use `~/.deckflow/deckops/config.json`. `deckops config list` shows the resolved value and its source without requiring you to guess which environment variable or file won.

## Node.js

```ts
import { createClient } from '@deckflow/deckops';

const client = createClient({
  apiKey: process.env.DECKOPS_API_KEY,
  spaceId: process.env.DECKOPS_SPACE_ID,
});

const document = await client.parse('slides.key', { engine: 'cloud' });
```

Client options can also provide a user `token` and `apiBase`. Environment variables are convenient for the CLI; explicit client options are easier to isolate in multi-tenant server applications.

## Browser applications

The Browser SDK deliberately has no `apiKey` option. Pass a user-scoped token that is safe for the browser, or route requests through an authenticated backend proxy that keeps the server API key private.

```ts
import { createClient } from '@deckflow/deckops/browser';

const client = createClient({
  apiBase: '/api/deckops',
  token: userAccessToken,
  onUnauthorized: refreshUserAccessToken,
});
```

If guest access is enabled for your deployment it can be used for limited evaluation. Do not design a production workflow around guest quota or availability.
