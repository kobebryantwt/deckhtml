> Pick the right output behavior for terminal use, automation, CI, and agent workflows.

DeckHTML separates results and diagnostics:

- stdout is for the final result
- stderr is for progress, logs, and errors

## Default output

By default, DeckHTML prints the final result on stdout.

```bash
deckhtml index.html -o deck.pptx
```

```text
deck.pptx
```

If you omit `-o`, the CLI derives the output path from the input name when possible:

```bash
deckhtml index.html
```

```text
index.pptx
```

## Artifact formats

The published CLI infers artifact type from the `-o` extension:

```bash
deckhtml index.html -o deck.pptx
deckhtml index.html -o frames.png
```

Documented artifact types:

- `pptx`
- `png`

Execution mode also affects artifact behavior:

- local and cloud execution can expose different processing paths
- use local mode for the simplest same-machine flow
- use cloud mode when you need hosted execution or cloud-only font embedding

## `--json`

Use `--json` when another program needs to parse the result:

```bash
deckhtml index.html -o deck.pptx --json
```

```json
{
  "ok": true,
  "input": ["index.html"],
  "output": "deck.pptx",
  "format": "pptx",
  "mode": "local"
}
```

With `--json`, stdout should contain only JSON. Logs and diagnostics remain on stderr.

## `--quiet` and `--verbose`

Use `--quiet` to suppress non-essential logs:

```bash
deckhtml index.html -o deck.pptx --quiet
```

Use `--verbose` for detailed logs:

```bash
deckhtml index.html -o deck.pptx --verbose
```

These flags conflict:

```bash
deckhtml index.html --quiet --verbose
```

Representative stderr:

```text
Error: --quiet conflicts with --verbose
```

## Errors and exit behavior

Errors are written to stderr. When `--json` is active, you should still expect diagnostic information to stay off stdout.

Representative JSON-shaped error payload:

```json
{
  "error": {
    "code": "usage_error",
    "message": "--quiet conflicts with --verbose"
  }
}
```

Representative error categories used in the docs:

| Code | Meaning |
| --- | --- |
| `usage_error` | Invalid flags, missing input, or conflicting options. |
| `auth_error` | Cloud mode requires a valid API key. |
| `render_error` | The page could not be loaded or rendered. |
| `conversion_error` | Conversion failed after rendering. |

## Stdout vs stderr

| Stream | Content |
| --- | --- |
| stdout | Final output path or JSON result. |
| stderr | Progress, warnings, verbose logs, and errors. |
