# Document Information

Document Information is the parsing target of DeckOps. It is more detailed than a DeckProbe report and is organized into three layers.

## File Identity

File Identity combines common file metadata with format-specific state. Depending on the source format, this can include:

- PDF version, creator, producer, XMP metadata, encryption, and permissions.
- PowerPoint version, company, theme, language, and security state.
- Word title, subject, language, producer version, and security state.
- Excel calculation mode, protection state, producer version, and security state.
- Keynote, Pages, or Numbers producer versions and declared metadata.

## Document Structure

Document Structure represents the physical and logical organization of the file, not only aggregate counts. Examples include:

- Page, slide, canvas, or sheet dimensions and orientation.
- Hidden slides or sheets, sections, masters, layouts, and themes.
- Document outlines, slide structures, workbook structures, and pagination structures.
- Fonts, layers, assets, named ranges, pivots, form fields, and embedded files.

## Content Intelligence

Content Intelligence contains the actual document objects and their usable properties. The intended model includes:

- Text blocks, paragraphs, headings, and text styles.
- Images, shapes, icons, charts, tables, SmartArt, and equations.
- Cells, formulas, conditional formatting, validation rules, and filters.
- Notes, comments, annotations, footnotes, revisions, and hyperlinks.
- Audio, video, embedded objects, transitions, builds, and animations where the source format supports them.

Unlike a DeckProbe signal or count, a DeckOps object can carry content, position, style, hierarchy, references, and other information needed for downstream interpretation or reconstruction.

## From parsing to IR

The current conceptual flow is:

```text
source document
      ↓ parse
Document Information
      ↓ schema normalization
document IR
      ↓ transform or reconstruct
derived output
```

Document Information describes what the parser must recover. The IR is the schema-normalized result produced from that parsed information. The exact boundary and schema will be refined when the DeckOps implementation is available.
