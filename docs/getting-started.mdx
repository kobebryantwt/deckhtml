Choose the first result your application needs. Each section provides installation, a concrete invocation, and the signal that proves the example succeeded.

| Product | First result | Runs | Credentials |
| --- | --- | --- | --- |
| DeckProbe | Schema v2 facts about a document | Local | None |

| DeckUse | Updated PPTX | Local | None |

## DeckProbe: inspect a known PDF

<span className="product-kicker">Local · no credentials · factual JSON</span>

```bash
npm install -g @deckflow/deckprobe
deckprobe --version

curl -fL https://mozilla.github.io/pdf.js/web/compressed.tracemonkey-pldi-09.pdf -o sample.pdf
deckprobe -t format,page_count --view values --pretty sample.pdf
```

The npm package's CLI uses the platform-specific native binary. Success means exit code `0`, `schema_version: 2`, driver `pdf`, and resolved values for `document.format` and `pdf.page_count`:

```json
{
  "schema_version": 2,
  "status": "ok",
  "driver": { "id": "pdf", "profile": "pdf" },
  "values": {
    "document.format": "pdf",
    "pdf.page_count": 14
  }
}
```

See the [DeckProbe Quickstart](/deckprobe/quick-start) for platform installers and the complete response.

## DeckRender: create a PNG

<span className="product-kicker">Cloud route · guest available · visual artifact</span>

```bash
npm install -g @deckflow/deckrender
deckrender hello.html -o hello.png --json
test -s hello.png
```

The command uploads the HTML to DeckFlow cloud, writes `hello.png`, and returns a `RenderResult` containing `ok`, route, page count, output path, bytes, and duration. Create the HTML input and review guest limits in the [DeckRender Quickstart](/deckrender/quick-start).

## DeckOps: run a cloud task

<span className="product-kicker">Cloud · asynchronous task · downloadable result</span>

Install the published task SDK:

```bash
npm install @deckops/sdk
```

Save this input as `sample.html`:

```html
<!doctype html>
<html><body><h1>Hello DeckOps</h1></body></html>
```

Save the following as `run.mjs`. It creates a guest task, starts it explicitly, waits for completion, and downloads its result metadata:

```js
import { createDeck } from '@deckops/sdk';

const deck = createDeck();
const task = await deck.convertHtmlToPng({ files: ['./sample.html'] });

await deck.tasks.start(task.id);
const completed = await deck.tasks.wait(task.id, { timeout: 120 });
const result = await deck.tasks.down(completed.id);

console.log(JSON.stringify({
  taskId: completed.id,
  type: completed.type,
  status: completed.status,
  result,
}, null, 2));
```

Run it:

```bash
node run.mjs
```

The HTML is uploaded to DeckFlow cloud. A successful result identifies the task and returns a PNG download URL, byte size, and hash:

```json
{
  "taskId": "<task-id>",
  "type": "convertor.html2png",
  "status": "completed",
  "result": ["<download-url>", 8063, "<hash>"]
}
```

Continue with the [DeckOps Quickstart](/deckops/quick-start) for progress handling and current package availability notes.

## DeckUse: update an existing PPTX

<span className="product-kicker">Local · existing PPTX · editable output</span>

<Warning>
  DeckUse provides a `deckuse` CLI and its intended install command is `npm install -g @deckflow/deckuse`. The current 1.0.0 Registry metadata references four private placeholder adapters, however, so that install cannot resolve all dependencies. The commands below build and link the same CLI from source until the published dependency list is corrected.
</Warning>

```bash
git clone https://github.com/deckflow/deckuse.git
cd deckuse
pnpm install
pnpm install:global
deckuse --help
curl -fL https://docs.deckflow.com/images/deckuse-sample.pptx -o input.pptx
deckuse init input.pptx ./workspace --json
printf '%s\n' '{"type":"replaceText","find":"2025","replace":"2026"}' \
  | deckuse apply ./workspace --json
deckuse validate ./workspace --json
deckuse commit ./workspace -o updated.pptx --json
```

DeckUse works locally through a versioned workspace. Its CLI can inspect and query PPTX structure, update text, properties and geometry, add/duplicate/remove supported slides and elements, work with pictures, tables and chart caches, then export another PPTX. Other document adapters remain unimplemented. Follow the [DeckUse Quickstart](/deckuse/quick-start) for prerequisites, expected query output, and final verification.

## DeckHTML: generate a PPTX locally

<span className="product-kicker">Local Chromium · HTML source · PPTX output</span>

```bash
npm install -g @deckflow/deckhtml
deckhtml deck.html -o deck.pptx --mode local --json --quiet
test -s deck.pptx
```

The command uses local Chromium and returns normalized paths, output format, execution mode, and slide count. Prepare the browser and a slide-sized HTML source in the [DeckHTML Quickstart](/deckhtml/quick-start).
