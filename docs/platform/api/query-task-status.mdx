Use this endpoint after submitting any DeckFlow job. It is the shared status endpoint for generation, translation, revamp, and tool workflows.

## What this endpoint returns

- the current `status`
- the accepted `type`, parsed `params`, source `files`, and task name
- lifecycle timestamps and elapsed execution fields such as `consumedMS`
- `allowGetResult`, which indicates whether the result endpoint can be used
- accounting and delivery fields such as `credits`, `downloadNum`, and `lastDownloadAt`

## Standard polling flow

<Steps>
  <Step title="Store the task ID">
    Read the `id` value returned from `POST /tools/tasks`.
  </Step>
  <Step title="Poll until a terminal state">
    Repeat `GET /tools/tasks/{id}` until the task becomes `completed` or `failed`.
  </Step>
  <Step title="Read the result URL">
    Once the task becomes `completed`, call `GET /tools/tasks/{id}/download` and read the URL from `target`.
  </Step>
</Steps>

<Warning>
  A newly accepted task can briefly return `200` with an empty body and no `Content-Type`. Treat that as a non-terminal poll result and retry; do not pass an empty response directly to a JSON parser.
</Warning>

## Verified response statuses

| Status | When it occurs | Response signal |
| ---: | --- | --- |
| `200` | The API key owns the task | Full task record; a just-created task can briefly have an empty body |
| `401` | Bearer token is invalid | `code: "noAuth"` |
| `403` | The API key belongs to another Space | `code: "notAllowed"` and `The secret key is invalid on this space` |
| `404` | Task ID does not exist, including malformed IDs | `code: "notFound"` |
| `500` | Authorization header is omitted | `code: "unexpectedError"` and `Profile uuid is required` |

<Note>
  A zero-credit task was accepted, then returned a normal `200` task record with `status: "failed"`, `credits: 0`, and `allowGetResult: false`. The task detail did not include a separate credit error object.
</Note>

## Polling examples

<Tabs>
  <Tab title="cURL">

```bash
curl --location 'https://app.deckflow.com/api/tools/tasks/task-uuid-string' \
  --header 'Authorization: Bearer <YOUR_API_KEY>'
```

  </Tab>
  <Tab title="JavaScript">

```js
const response = await fetch('https://app.deckflow.com/api/tools/tasks/task-uuid-string', {
  method: 'GET',
  headers: {
    Authorization: 'Bearer <YOUR_API_KEY>'
  }
});

const task = await response.json();
console.log(task.status, task.allowGetResult);
```

  </Tab>
  <Tab title="Python">

```python
import requests

response = requests.get(
    "https://app.deckflow.com/api/tools/tasks/task-uuid-string",
    headers={"Authorization": "Bearer <YOUR_API_KEY>"},
)

task = response.json()
print(task["status"])
print(task.get("allowGetResult"))
```

## Server-Sent Events (SSE)

DeckFlow also supports a streaming status mode on this same endpoint. To enable it, send the extra request header:

```text
response-event-stream: yes
```

In this mode, the endpoint returns `text/event-stream`. The server pushes status updates as `data: { ...taskJSON }` events and closes the stream automatically when the task reaches `completed` or `failed`.

## SSE examples

<Tabs>
  <Tab title="cURL">

```bash
curl --location 'https://app.deckflow.com/api/tools/tasks/task-uuid-string' \
  --header 'Authorization: Bearer <YOUR_API_KEY>' \
  --header 'response-event-stream: yes'
```

  </Tab>
  <Tab title="JavaScript">

```js
const response = await fetch('https://app.deckflow.com/api/tools/tasks/task-uuid-string', {
  method: 'GET',
  headers: {
    Authorization: 'Bearer <YOUR_API_KEY>',
    'response-event-stream': 'yes'
  }
});

const reader = response.body.getReader();
const decoder = new TextDecoder();

while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  console.log(decoder.decode(value, { stream: true }));
}
```

  </Tab>
  <Tab title="Python">

```python
import requests

with requests.get(
    "https://app.deckflow.com/api/tools/tasks/task-uuid-string",
    headers={
        "Authorization": "Bearer <YOUR_API_KEY>",
        "response-event-stream": "yes",
    },
    stream=True,
) as response:
    for line in response.iter_lines():
        if line:
            print(line.decode("utf-8"))
```

  </Tab>
</Tabs>

<Tip>
  Use ordinary JSON polling by default. SSE is most useful when your client wants live task progress without implementing its own poll loop.
</Tip>
