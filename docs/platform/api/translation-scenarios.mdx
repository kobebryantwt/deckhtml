Translation jobs reuse the same unified async task API. The difference is that the `type` field must be fixed to `translation`, and `params` must contain the language fields defined below.

## Core mapping

| Field | Value |
|---|---|
| Endpoint | `POST /tools/tasks` |
| `type` | `translation` |
| Files | Presentation-style documents such as PPTX, Keynote, PDF, Word, and Excel |
| Query endpoint | `GET /tools/tasks/{id}` |

## Form-data fields

| Field | Type | Required | Meaning |
|---|---|---|---|
| `spaceId` | `String` | No | Target workspace Space ID. |
| `files` | `File` | Yes | PPTX, Keynote, PDF, Word, or Excel source documents. Multiple files are supported. |
| `type` | `String` | Yes | Fixed value: `translation`. |
| `name` | `String` | No | Human-readable task name, such as `"AI translation task"`. |
| `params` | `String (JSON)` | Yes | JSON string containing the translation parameters below. |

## `params` fields

| Field | Type | Required | Meaning |
|---|---|---|---|
| `from` | `String` | Yes | Source language code, such as `"zh"`. |
| `to` | `String` | Yes | Target language code, such as `"en"`. |
| `notifyURL` | `String` | No | Webhook callback URL for task status changes. |

## Example `params`

```json
{
  "from": "zh",
  "to": "en",
  "notifyURL": "https://your.domain/callback"
}
```

<Tip>
  The official DeckFlow docs position this workflow around presentation-style files and emphasize preserving layout and visual structure where possible.
</Tip>
