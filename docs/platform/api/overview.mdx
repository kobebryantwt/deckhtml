DeckFlow's API is organized around a common async task flow. Business scenarios such as generation, translation, revamp, and tool APIs all reuse the same submission and task-management pattern.

<Note>
  This shared API remains in the platform layer until each scenario has a confirmed owner in the new product model. Product-specific APIs should move under that product once their contracts and ownership are explicit.
</Note>

At the reference level, the most important shared endpoints are:

- `POST /tools/tasks`
- `GET /tools/tasks/{id}`
- `GET /tools/tasks/{id}/download`

This section is therefore split into two layers:

- <strong>Core APIs</strong>: submit a task, query its status, and download the finished result
- <strong>Scenario guides</strong>: understand which `type`, `files`, and `params` fields to send for each business workflow

<Note>
  The phrase "common async task flow" is a descriptive label used in this guide for the shared task lifecycle and authentication model. It is not a separate product term.
</Note>

## Common async task flow

DeckFlow uses the same lifecycle across business scenarios:

- Authenticate with `Authorization: Bearer <YOUR_API_KEY>`.
- Submit files, task type, and JSON options as `multipart/form-data`.
- Receive a task identifier immediately.
- Poll the task endpoint or subscribe through SSE until the job is complete or failed.
- Download the final file from `result.url` or from the dedicated download endpoint.
