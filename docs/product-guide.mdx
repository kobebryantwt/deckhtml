Start with the artifact your application must receive—facts, pixels, structured content, an updated source file, or a new deck—then confirm where the work runs. The same source file can enter several products for different results.

## Product comparison

| Product | Start with | Produces | Runs | Does not replace |
| --- | --- | --- | --- | --- |
| DeckProbe | Existing PDF, Office, or modern iWork document | Schema v2 target evidence and measured probe cost | Native Rust CLI or local WebAssembly | Full content parsing, rendering, or editing |
| DeckRender | Supported document, URL, stdin, or browser-selected file | Images, PDF, or video | Explicit local or cloud engine; Browser SDK is cloud-only | Structured content extraction or source editing |
| DeckOps | PDF, PPTX, DOCX, Keynote, URL, or existing artifact | Durable `deckir.v1` artifact and Markdown views | Local-first CLI/Node.js; explicit cloud routes; cloud-only Browser SDK | Visual rendering or editable source mutation |
| DeckUse | Existing PPTX | Versioned workspace and updated PPTX | Local Node.js command workflow | DOCX/XLSX/Keynote editing, rendering, or visual review |
| DeckHTML | Local HTML/SVG, ordered files, stdin, or HTML URL | PPTX or PNG; PPTX mapping diagnostics | Local browser or cloud task through the CLI; local Node.js API | General-purpose conversion of existing Office files |

## Common decisions

<AccordionGroup>
  <Accordion title="DeckProbe or DeckOps?">
    Use <strong>DeckProbe</strong> when verified document-level facts are the final result or are needed before accepting and routing a file. Use <strong>DeckOps</strong> when the application needs page and element content in a reusable IR or a Markdown view. A deeper DeckProbe level still returns target evidence, not a DeckOps parse result.
  </Accordion>
  <Accordion title="DeckRender or DeckOps?">
    Use <strong>DeckRender</strong> when your application needs visual output such as images, PDF, or video. Use <strong>DeckOps</strong> when it needs structured document state, source traceability, or Markdown that can be regenerated without reparsing.
  </Accordion>
  <Accordion title="DeckUse or DeckHTML?">
    Use <strong>DeckUse</strong> when an existing PPTX is the source of truth and you need to change its current content. Use <strong>DeckHTML</strong> when HTML or SVG is the authoring source and a new PPTX or PNG is the result.
  </Accordion>
  <Accordion title="Can products be combined?">
    Yes. A typical ingestion flow can use DeckProbe to validate a file, DeckOps to parse it, and DeckRender to produce previews. These are separate calls with separate result contracts; DeckFlow does not require every workflow to use all products.
  </Accordion>
</AccordionGroup>
