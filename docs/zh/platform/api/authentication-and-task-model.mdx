DeckFlow 的不同 API 场景，底层都复用同一套基础能力。在看生成、翻译、焕新和工具 API 之前，建议先把这层公共模型理解清楚。

## Base URL

```text
https://app.deckflow.com/api
```

## 获取 API Key

<Steps>
  <Step title="打开 DeckFlow 设置">
    登录 DeckFlow，然后访问 [API Key 设置页面](https://app.deckflow.com/start#settings)。
  </Step>
  <Step title="创建并复制 API Key">
    在设置页面中配置 API Key，然后将其复制到服务端或开发环境使用的安全凭证存储中。
  </Step>
  <Step title="设置环境变量">
    ```bash
    export DECKFLOW_API_KEY="YOUR_API_KEY"
    ```
  </Step>
</Steps>

<Warning>
  API Key 属于服务端凭证。不要写入浏览器代码、提交到代码仓库或输出到日志。
</Warning>

## 必填请求头

| 请求头 | 是否必填 | 作用 |
|---|---|---|
| `Authorization` | 是 | 使用 `Bearer <YOUR_API_KEY>` 进行认证。 |
| `Content-Type` | 提交任务时必填 | `POST /tools/tasks` 使用 `multipart/form-data`；Multipart Boundary 交由 HTTP 客户端自动添加。 |

```bash
curl 'https://app.deckflow.com/api/tools/tasks/TASK_ID' \
  --header "Authorization: Bearer $DECKFLOW_API_KEY"
```

## 通用异步任务流程

<Steps>
  <Step title="完成认证">
    从安全凭证存储中读取 API Key，并通过 `Authorization` 请求头传入。
  </Step>
  <Step title="提交任务">
    上传一个或多个文件，指定 `type`，并通过 `params` 传递场景参数。
  </Step>
  <Step title="跟踪状态">
    保存返回的任务 ID，随后通过 `GET /tools/tasks/{id}` 轮询，或通过 `response-event-stream: yes` 订阅 SSE 实时流。
  </Step>
  <Step title="下载结果">
    任务进入 `completed` 后，调用 `GET /tools/tasks/{id}/download`，并从 `target` 中读取结果地址。
  </Step>
</Steps>

## 公共提交字段

这些字段会在生成、翻译、焕新和工具 API 中反复出现：

| 字段 | 是否必填 | 含义 |
|---|---|---|
| `spaceId` | 否 | 目标工作空间或空间 ID。 |
| `files` | 与 `fileIds` 二选一 | 本次请求上传的源文件。上传多个文件时重复提交该 Multipart 字段。 |
| `fileIds` | 与 `files` 二选一 | DeckFlow 中已有文件的 ID。需要使用能够保留重复 Multipart 值的客户端传入数组。 |
| `type` | 是 | 业务场景或工具类型标识，例如 `generation`、`translation`、`revamp`、`convertor.html2pptx`。 |
| `name` | 否 | 任务显示名称。 |
| `notifyURL` | 否 | 任务状态变更时的 Webhook 回调地址。 |
| `params` | 通常建议传 | 包含场景参数的 JSON 字符串。 |

## 状态处理

- 任务创建后，通常会先进入 `pending` 或其他非终态。
- 继续查询，直到任务进入 `completed` 或 `failed`。
- 创建接口返回 `201` 只表示任务已被接受，不代表处理成功。
- 任务完成后，通过结果接口获取输出地址和元数据。
- 失败任务的详情中可能没有独立错误信息。排查时需要保留任务 ID 和终态。

<Warning>
  实测无剩余额度时，接口仍以 `201` 接受任务，返回 `credits: 0`，随后任务进入 `failed`；服务并未返回 `429`。因此必须检查任务终态，不能把创建成功当作处理成功。
</Warning>
