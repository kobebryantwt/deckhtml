无论是生成、翻译、焕新还是工具类任务，最终都使用这个接口查询执行状态。

## 这个接口会返回什么

- 当前 `status`
- 已接受的 `type`、解析后的 `params`、源 `files` 和任务名称
- 生命周期时间，以及 `consumedMS` 等执行耗时字段
- 表示结果接口是否可用的 `allowGetResult`
- `credits`、`downloadNum`、`lastDownloadAt` 等计费与交付字段

## 标准轮询流程

<Steps>
  <Step title="保存任务 ID">
    从 `POST /tools/tasks` 的返回结果中读取 `id`。
  </Step>
  <Step title="持续查询直到任务结束">
    使用 `GET /tools/tasks/{id}` 重复查询，直到任务进入 `completed` 或 `failed`。
  </Step>
  <Step title="读取结果链接">
    任务进入 `completed` 后，调用 `GET /tools/tasks/{id}/download`，并从 `target` 中读取结果地址。
  </Step>
</Steps>

<Warning>
  新创建的任务可能短暂返回没有响应体、没有 `Content-Type` 的 `200` 响应。请把它视为尚未进入终态的一次轮询并重试，不要直接把空响应交给 JSON 解析器。
</Warning>

## 已验证的响应状态

| 状态码 | 出现场景 | 响应特征 |
| ---: | --- | --- |
| `200` | API Key 属于该任务 | 返回完整任务记录；刚创建时可能短暂没有响应体 |
| `401` | Bearer Token 无效 | `code: "noAuth"` |
| `403` | API Key 属于另一个 Space | `code: "notAllowed"`，并包含 `The secret key is invalid on this space` |
| `404` | Task ID 不存在，包括格式异常的 ID | `code: "notFound"` |
| `500` | 未提供 Authorization 请求头 | `code: "unexpectedError"`，并包含 `Profile uuid is required` |

<Note>
  实测无剩余额度的任务被接受后，详情接口正常返回 `200`，任务记录包含 `status: "failed"`、`credits: 0` 和 `allowGetResult: false`，但没有单独的额度错误对象。
</Note>

## 轮询示例

<Tabs>
  <Tab title="cURL">

```bash
curl --location 'https://app.deckflow.com/api/tools/tasks/task-uuid-string' \
  --header 'Authorization: Bearer <YOUR_API_KEY>'
```

  </Tab>
  <Tab title="JavaScript">

```js
const response = await fetch('https://app.deckflow.com/api/tools/tasks/task-uuid-string', {
  method: 'GET',
  headers: {
    Authorization: 'Bearer <YOUR_API_KEY>'
  }
});

const task = await response.json();
console.log(task.status, task.allowGetResult);
```

  </Tab>
  <Tab title="Python">

```python
import requests

response = requests.get(
    "https://app.deckflow.com/api/tools/tasks/task-uuid-string",
    headers={"Authorization": "Bearer <YOUR_API_KEY>"},
)

task = response.json()
print(task["status"])
print(task.get("allowGetResult"))
```

## Server-Sent Events (SSE)

这个接口还支持基于同一路径的 SSE 实时流模式。只需要额外增加请求头：

```text
response-event-stream: yes
```

启用后，接口会返回 `text/event-stream`，服务端会以 `data: { ...taskJSON }` 的形式持续推送状态更新；当任务进入 `completed` 或 `failed` 时，连接会自动关闭。

## SSE 示例

<Tabs>
  <Tab title="cURL">

```bash
curl --location 'https://app.deckflow.com/api/tools/tasks/task-uuid-string' \
  --header 'Authorization: Bearer <YOUR_API_KEY>' \
  --header 'response-event-stream: yes'
```

  </Tab>
  <Tab title="JavaScript">

```js
const response = await fetch('https://app.deckflow.com/api/tools/tasks/task-uuid-string', {
  method: 'GET',
  headers: {
    Authorization: 'Bearer <YOUR_API_KEY>',
    'response-event-stream': 'yes'
  }
});

const reader = response.body.getReader();
const decoder = new TextDecoder();

while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  console.log(decoder.decode(value, { stream: true }));
}
```

  </Tab>
  <Tab title="Python">

```python
import requests

with requests.get(
    "https://app.deckflow.com/api/tools/tasks/task-uuid-string",
    headers={
        "Authorization": "Bearer <YOUR_API_KEY>",
        "response-event-stream": "yes",
    },
    stream=True,
) as response:
    for line in response.iter_lines():
        if line:
            print(line.decode("utf-8"))
```

  </Tab>
</Tabs>

<Tip>
  默认优先使用普通 JSON 轮询即可。只有当你的客户端确实需要实时接收状态更新时，再切到 SSE。
</Tip>
