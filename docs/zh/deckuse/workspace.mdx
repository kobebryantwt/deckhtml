DeckUse 始终通过持久化工作区执行操作。`init` 把源 PPTX 复制到支持 OPC 的文件包中，建立可查询索引，记录当前适配器和版本，并提取内嵌媒体供本地检查。

```text
workspace/
├── package.pptx
└── .deckuse/
    ├── manifest.json
    ├── index.json
    ├── operations.jsonl
    └── media/
```

| 文件 | 用途 |
| --- | --- |
| `package.pptx` | 当前可编辑的文件包状态 |
| `manifest.json` | 源路径、格式、适配器版本、当前版本、校验和与能力 |
| `index.json` | 元素引用、文本、几何信息、位置和附加数据索引 |
| `operations.jsonl` | 初始化与已持久化命令的追加式记录 |
| `media/` | 从 PPTX 提取的内嵌媒体；图片查询结果会引用这些本地文件 |

DeckUse 运行期间不要直接编辑这些文件。请使用命令协议，让文件包、索引、版本、校验和与操作日志保持一致。

## 版本与事务规则

每次持久化修改都会生成新版本。修改命令的 `transactionId` 必须等于当前清单版本，或使用字面值 `latest`；元素引用也可以携带读取时的版本。

- CLI 的 `apply` 会读取当前清单，并自动补充顶层事务 ID。
- Node.js API 要求调用方提供完整命令封装。
- 事务或带版本引用已经过期时，会返回 `TRANSACTION_CONFLICT`，而不是静默覆盖较新的修改。
- 从同一主 PPTX 生成客户、地区或受众版本时，请分别创建独立工作区。

## 试运行

在修改或批处理上设置 `dryRun: true`，可以执行校验并返回预期结果，但不持久化文件包、索引、版本和操作日志：

```json
{
  "type": "replaceText",
  "find": "FY2025",
  "replace": "FY2026",
  "dryRun": true
}
```

把该对象交给 `apply` 时，CLI 会补充其余顶层协议字段。

## 原子与非原子批处理

`batch` 最多接收 1000 条修改命令。默认的 `atomic: true` 会在内存副本上执行全部修改，只有全部成功才持久化。设置 `atomic: false` 后，失败前的修改会被保留，并返回 `PARTIAL_BATCH_APPLIED`；仅在业务允许部分完成时使用。

当前 JSON Schema 要求嵌套命令包含完整命令封装，请查看[命令参考](/zh/deckuse/commands#批处理与试运行)。

## 校验与提交

```bash
deckuse validate ./workspace --json
deckuse commit ./workspace -o updated.pptx --json
```

当前校验会检测 PPTX 内部关系指向的部件是否缺失。提交时先写入临时文件，重新打开生成的文件包，随后再把它重命名到目标位置。目标文件已存在时会拒绝覆盖，除非添加 `--force`。

<Warning>
  当前校验是有限的结构检查。它不会渲染幻灯片、验证每一条 OOXML 规则、检查字体、检测重叠，也不会确认图表工作簿与图表缓存一致。请保留原始文件，并目视检查导出的 PPTX。
</Warning>

## 保留行为

DeckUse 会尽量保留未修改的 XML 和未知文件包部件。ZIP 条目会重新压缩，因此不承诺压缩包字节完全一致。复制幻灯片时，会克隆可变的备注和图表部件；版式和媒体可能继续共享。删除图片或幻灯片时，只会清理由其他关系不再引用的媒体。
