DeckUse 不会直接修改源 PPTX。首先创建工作区，再使用 `inspect` 或 `query` 了解 CLI 可以定位哪些对象，最后提交修改命令。

## 创建工作区

```bash
deckuse init input.pptx ./workspace --json
```

初始化成功后会返回规范化的工作区路径、源格式、当前版本、文件包校验值和检测到的能力。下面的缩略结果保留了接入时最先使用的字段：

```json
{
  "ok": true,
  "value": {
    "schemaVersion": "1.0",
    "workspaceId": "/absolute/path/workspace",
    "format": "pptx",
    "source": "/absolute/path/input.pptx",
    "revision": "mssob1ss-2943b374",
    "files": [
      {
        "path": "package.pptx",
        "mediaType": "application/vnd.openxmlformats-officedocument.presentationml.presentation",
        "checksum": "..."
      }
    ],
    "metadata": { "capabilities": { "slides": { "add": true, "duplicate": true, "remove": true } } }
  },
  "diagnostics": []
}
```

工作区包含独立的可修改文件包和索引。后续命令应继续使用这个工作区，不需要在每次查询或修改前重新执行 `init`。

## 检查文档

```bash
deckuse inspect ./workspace --depth 2 --json
```

`inspect` 主要返回两部分：

- `document.format`、`document.revision` 和 `document.capabilities` 描述当前工作区。
- `elements` 包含 DeckUse 找到的幻灯片、形状、文本框、图片、表格、图表、备注、版式、母版和主题索引。

一条幻灯片索引的结构如下：

```json
{
  "ref": {
    "documentId": "/absolute/path/workspace",
    "elementId": "slide:256",
    "path": "/ppt/slides/slide1.xml",
    "revision": "mssob1ss-2943b374"
  },
  "kind": "slide",
  "partUri": "/ppt/slides/slide1.xml",
  "slideId": "256",
  "name": "Slide 256",
  "location": {
    "slideId": "256",
    "partUri": "/ppt/slides/slide1.xml"
  }
}
```

当前 PPTX 适配器会返回完整的扁平索引。`--depth` 接受 `0` 到 `100`，但不会裁剪这份扁平列表。

## 查询候选元素

已知所需对象的类型、文字、名称、幻灯片 ID 或元素 ID 时，使用 `query`：

```bash
deckuse query ./workspace 'kind=textbox hasText=true' --limit 100 --json
deckuse query ./workspace 'text=Revenue' --json
deckuse query ./workspace 'text~=^FY20[0-9]{2}$' --limit 1000 --json
deckuse query ./workspace 'slide=256 kind=picture' --json
```

`--limit` 默认为 `100`，最大为 `10000`。查询成功时，`value` 是结果数组；空数组表示查询执行成功，但没有找到匹配对象。

一条文本框结果的结构如下：

```json
{
  "ref": {
    "documentId": "/absolute/path/workspace",
    "elementId": "256:5",
    "path": "/ppt/slides/slide1.xml#256:5",
    "revision": "mssob1ss-2943b374"
  },
  "kind": "textbox",
  "partUri": "/ppt/slides/slide1.xml",
  "slideId": "256",
  "parentId": "slide:256",
  "location": {
    "slideId": "256",
    "partUri": "/ppt/slides/slide1.xml",
    "ancestorIds": [],
    "cNvPrId": "5"
  },
  "name": "TextBox 4",
  "text": "Q2 FY2025 · APRIL – JUNE 2025",
  "transform": {
    "x": 566928,
    "y": 2084831,
    "width": 10607040,
    "height": 365760
  }
}
```

全部字符串选择器，以及 Node.js API 支持的结构化选择器，请查看[选择器与元素引用](/zh/deckuse/selectors)。

## 判断结果是否适合修改

构造定向修改命令前，依次确认：

1. `value` 中的元素数量符合工作流预期。
2. `kind`、`slideId`、`name` 和 `text` 能确定目标对象。
3. 返回的 `ref` 来自当前工作区，而不是帮助文档或其他演示文稿。
4. 执行修改时，`revision` 仍然是当前版本。

`256` 这类幻灯片 ID 是演示文稿内部的稳定 ID，并不是从 1 开始的页码。可以查询 `kind=slide` 获取当前文件的幻灯片 ID。

<Warning>
  每次持久化修改都会生成新的工作区版本。此后，包含旧版本的引用会返回 `TRANSACTION_CONFLICT`。执行下一项定向修改前应重新查询；也可以把相关操作放入一个经过检查的原子批处理。
</Warning>

## 选择 inspect 还是 query

| 目标 | 命令 |
| --- | --- |
| 发现文档能力或查看完整索引 | `inspect` |
| 获取范围可控的候选元素 | `query` |
| 定向修改一个已知元素 | 先执行 `query`，再复用返回的 `ref` |
| 在应用代码中读取一个元素 | Node.js `getText` 命令 |

确认修改目标后，继续阅读[修改与导出](/zh/deckuse/cli/apply-and-export)。
