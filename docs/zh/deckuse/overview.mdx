DeckUse 让应用、脚本和 Coding Agent 可以精确修改现有 PPTX。先找到需要更新的幻灯片或元素，再修改内容和属性、增删支持的对象，最后导出一份仍可继续编辑的 PPTX。整个过程在本地完成，不会上传演示文稿。

| 项目 | 快速了解 |
| --- | --- |
| 输入 | 一个现有 `.pptx` 文件 |
| 结果 | 一份修改后仍可编辑的 `.pptx` 文件 |
| 执行位置 | 本地 Node.js 进程；不会上传文档 |
| 接入方式 | `deckuse` CLI 和 Node.js `runCommand()` API |
| 认证 | 不需要 |

## DeckUse 适合什么

- 在多份演示文稿中执行同一项已经确定的内容或属性修改。
- 基于现有 PPTX 生成面向不同客户、地区、语言或活动的版本。
- 让 Agent 通过稳定引用定位并修改指定幻灯片或元素。
- 把 PPTX 修改、校验和导出接入本地应用或自动化流水线。
- 让源文件和生成文件始终保留在当前机器。

## 可以修改什么

- 检查 PPTX 索引中的幻灯片、文本框、形状、组合、图片、表格、图表、演讲者备注、版式、母版和主题。
- 按类型、名称、文本、正则表达式、幻灯片 ID、元素 ID 或是否包含文本来查询元素。
- 设置或替换文本；修改位置、尺寸、旋转、填充、描边、文字样式、名称和隐藏状态。
- 添加、复制或删除幻灯片和支持的元素；添加图片与表格；替换内嵌图片。
- 读取演讲者备注和表格单元格；修改图表标题、系列名称和缓存值。
- 把多项修改组成试运行或原子批处理，并保留操作日志。

<Note>
  DeckUse 处理结构，不处理视觉判断。它不会渲染幻灯片、检测元素重叠、评价版式，也不会替 Agent 决定该修改什么。交付前仍需打开或渲染导出的 PPTX。
</Note>

## 修改过程

```text
existing.pptx → 创建工作区 → 检查 / 查询 → 执行修改
              → 校验 → 导出 → updated.pptx
```

工作区保存文档索引、当前版本、操作日志，以及校验和导出所需的文件包内容。CLI 与 Node.js API 使用同一套带版本的命令协议，因此工作流可以先检查修改目标，再执行操作，并识别版本冲突。

## PPTX 保留边界

DeckUse 会尽量保留未知的文件包 Part 和未修改的 XML。ZIP 条目会被重新压缩，因此未修改内容按解压后的数据保持一致，不保证 ZIP 字节完全相同。文本替换可能把多个文本 Run 合并成一个 Run，并保留第一个 Run 的样式。
