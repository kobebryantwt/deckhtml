DeckUse 是面向 Coding Agent 的本地、Schema 驱动文档操作引擎。它把现有演示文稿导入带版本的工作区，建立结构索引，执行明确的 JSON 命令，校验文件包，最后导出另一个仍可编辑的 PPTX。

| 项目 | 当前契约 |
| --- | --- |
| 输入 | 一个现有 `.pptx` 文件 |
| 输出 | 带版本的本地工作区，以及修改后的 `.pptx` |
| 执行位置 | 本地 Node.js 进程；不会上传文档 |
| 接入方式 | `deckuse` CLI 和 Node.js `runCommand()` API |
| 运行环境 | Node.js 24 或更高版本；源码开发使用 pnpm 10 |
| 认证 | 不需要 |

```text
existing.pptx → 初始化工作区 → 检查 / 查询 → 执行 JSON 命令
              → 校验 → 提交 → updated.pptx
```

## 可以完成什么

- 检查 PPTX 索引中的幻灯片、文本框、形状、组合、图片、表格、图表、演讲者备注、版式、母版和主题。
- 按类型、名称、文本、正则表达式、幻灯片 ID、元素 ID 或是否包含文本来查询元素。
- 设置或替换文本；修改位置、尺寸、旋转、填充、描边、文字样式、名称和隐藏状态。
- 添加、复制或删除幻灯片和支持的元素；添加图片与表格；替换内嵌图片。
- 读取演讲者备注和表格单元格；修改图表标题、系列名称和缓存值。
- 把多项修改组成试运行或原子批处理，并保留操作日志。

<Note>
  DeckUse 处理结构，不处理视觉判断。它不会渲染幻灯片、检测元素重叠、评价版式，也不会替 Agent 决定该修改什么。交付前仍需打开或渲染导出的 PPTX。
</Note>

## 当前格式边界

目前只实现了 PPTX 编辑适配器。命令层预留了 DOCX、XLSX、Keynote 和 Numbers 名称，但初始化会返回 `FORMAT_NOT_IMPLEMENTED`；它们还不是可编辑目标。

DeckUse 会尽量保留未知的文件包 Part 和未修改的 XML。ZIP 条目会被重新压缩，因此未修改内容按解压后的数据保持一致，不保证 ZIP 字节完全相同。文本替换可能把多个文本 Run 合并成一个 Run，并保留第一个 Run 的样式。

<Warning>
  当前 Registry 中的 `@deckflow/deckuse@0.2.0` 依赖了一组尚未全部发布的适配器包，因此普通的 `npm install @deckflow/deckuse` 目前会失败。源码工作区可以构建，PPTX 测试也已通过；公开依赖修正前，请按照快速开始从源码安装。
