`--report` 会写入 `<output>.report.json`。DeckHTML 提供两个报告层级。

## 本地逐元素报告

本地 PPTX 转换可以返回：

- `schema_version`
- 引擎名称和版本
- 转换状态
- 幻灯片和有序元素记录
- 稳定的 `element_id`、元素类型、几何信息和对象引用
- `mapping_mode`：`native`、`vector`、`raster`、`ignored` 或 `unsupported`
- 汇总计数和结构化诊断

这个报告可以回答哪些源元素保持可编辑，以及哪些位置发生了简化。

```json
{
  "schema_version": 1,
  "engine": { "name": "@deckflow/deckhtml", "version": "0.6.2" },
  "status": "succeeded",
  "slides": [
    {
      "slide_id": "cover",
      "index": 1,
      "elements": [
        {
          "element_id": "title",
          "kind": "text",
          "mapping_mode": "native",
          "object_ref": "ppt/slides/slide1.xml#name:title",
          "geometry": { "x": 0.75, "y": 0.8, "w": 6.5, "h": 0.7, "unit": "inch" },
          "warnings": []
        }
      ]
    }
  ],
  "summary": { "native": 1, "vector": 0, "raster": 0, "ignored": 0, "unsupported": 0 },
  "diagnostics": []
}
```

源文件没有声明 `data-element-id` 或配置的标识属性时，`element_id` 为 `null`。需要使用报告进行回归检查时，请先为元素添加稳定标识。

## 聚合报告

没有逐元素报告时，例如当前云端回退路径，CLI 会写入聚合信息，包括输入、输出、模式、格式、幻灯片数量、元素计数、字体、栅格化统计、视口、平台和耗时。

不要假设两种报告结构完全相同。逐元素契约检查 `schema_version`，聚合契约检查 `version`。

## 诊断

诊断项包含稳定的 `rule_id`、严重程度、可选的幻灯片与元素 ID、消息和恢复建议。规则覆盖元素标识、不支持的元素类型或样式、资源、浏览器故障、缺失字体、栅格降级、几何、OOXML 校验、动画和 iframe。

应用应根据 `rule_id` 分支，而不是依赖本地化消息文本。

```json
{
  "rule_id": "DECKHTML_ANIMATION_UNMAPPED",
  "severity": "warning",
  "element_id": "hero",
  "message": "<供开发者阅读的详细信息>",
  "recovery": "<建议的源文件调整方式>"
}
```

可以先用 `summary.raster` 和 `summary.unsupported` 快速判断，再检查元素记录与诊断定位原因。如果要求转换过程本身直接失败，而不是由应用读取报告后判断，请使用 Node.js API 的严格模式。
