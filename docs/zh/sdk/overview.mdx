SDK 章节面向希望在服务端、内部工具或自动化代码里直接调用 DeckHTML 的团队。

<Note>
  当前 npm 包已经暴露了可用的 Node 程序化接口，所以这一部分可以先围绕 Node SDK 使用路径展开。
</Note>

## 当前可用的 SDK 文档

<CardGroup cols={2}>
  <Card title="Node SDK" href="/sdk/node">
    通过 JavaScript 或 TypeScript 调用 `convertHtmlToPptx()` 完成程序化转换。
  </Card>
  <Card title="Python SDK">
    即将提供。
  </Card>
</CardGroup>

## 什么时候应该用 SDK

如果你的场景符合下面这些特征，就更适合走 SDK：

- 转换流程是后端应用逻辑的一部分
- 你希望在 JavaScript 或 TypeScript 代码里直接调用 DeckHTML
- 你更希望传入类型化参数，而不是拼接 shell 命令
- 你需要在内存中直接拿到转换结果 `Buffer`

## 建议接入顺序

<Steps>
  <Step title="先用 CLI 验证输入和结果">
    在终端里先确认 HTML 输入、输出行为和基础参数都符合预期。
  </Step>
  <Step title="再迁移到 Node SDK">
    把已经验证过的输入路径迁移到 `convertHtmlToPptx()` 这样的程序化调用方式。
  </Step>
  <Step title="接入你自己的存储或任务系统">
    程序化接口返回的是内存里的转换结果，所以最终如何落盘、上传或继续分发，由你的应用自己控制。
  </Step>
</Steps>
