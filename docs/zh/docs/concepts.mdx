DeckHTML 在不同接入面之上，其实共享一套相对稳定的基础概念。理解这些概念之后，你在 CLI、SDK 或 MCP 之间切换时会顺畅很多。

## 输入

DeckHTML 常见支持三类输入来源：

- 本地 HTML 文件
- 标准输入 `stdin`
- 托管 URL

如果你的演示文稿由多页组成，也可以按顺序提供多个 HTML 文件，把它们当作一次完整的演示构建任务。

## 输出

DeckHTML 当前围绕三类输出结果组织工作流：

- `pptx`：可继续编辑的演示文稿
- `pdf`：固定版式输出，适合审阅和归档
- `png`：图片帧或预览图

## 模式

从执行方式看，DeckHTML 有两个高层次模式：

- 本地模式：在当前调用机器上直接执行转换流程
- 云端模式：把执行委托给远端服务，并解锁云端专属增强能力

## 结构化结果

如果你是在 CLI、CI 或自动化环境里使用 DeckHTML，结构化结果会很重要。DeckHTML 支持 JSON 输出，也支持生成额外报告，方便脚本、流水线或智能体稳定消费结果。

## 集成方式

同一套概念会通过不同接入面暴露出来：

- CLI：面向终端里的直接操作
- SDK：面向应用代码里的程序化集成
- MCP：面向智能体工具和编辑器集成
