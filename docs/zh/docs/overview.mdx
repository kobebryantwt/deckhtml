# 使用 DeckHTML 构建演示文稿工作流

DeckHTML 面向开发者提供从 HTML 到演示文稿产物的工作流能力。你可以从 CLI 开始验证输入输出，再接入 API、SDK，或者通过 MCP 暴露给智能体客户端使用。

<Note>
  这套文档优先按照开发者实际接入路径组织：先跑通一次端到端转换，再根据你的使用场景进入 CLI、API、SDK 或 MCP。
</Note>

## 可以用它做什么

<CardGroup cols={3}>
  <Card title="PPTX 演示文稿">
    生成适合继续编辑、评审或交付的演示文稿文件。
  </Card>
  <Card title="PDF 输出">
    输出固定版式文档，用于分享、留档和审阅。
  </Card>
  <Card title="PNG 画面">
    把页面渲染成图片，适合缩略图、预览图和自动化管线。
  </Card>
</CardGroup>

## 推荐阅读顺序

<Steps>
  <Step title="先跑通第一次转换">
    从 [快速开始](/zh/docs/quick-start) 开始，先确认你的 HTML 输入可以顺利生成目标产物。
  </Step>
  <Step title="理解接入模型">
    然后阅读 [CLI 概览](/zh/cli/overview)、[MCP 概览](/zh/mcp/overview) 和 [API 概览](/zh/reference/overview)，判断后续应走哪条集成路径。
  </Step>
  <Step title="选择具体接入面">
    终端和脚本场景进入 [CLI](/zh/cli/overview)，服务端代码场景进入 [SDK](/zh/sdk/overview)，智能体场景进入 [MCP](/zh/mcp/overview)。
  </Step>
</Steps>

<Tip>
  如果你的主要目标是接入智能体工作流，建议在读完快速开始后直接进入 [MCP 概览](/zh/mcp/overview)，不用先深入 CLI 的全部细节。
</Tip>
