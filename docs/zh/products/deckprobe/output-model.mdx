# 输出模型

DeckProbe 使用稳定的 Schema v2 报告外壳，但报告中的事实由 Target 驱动。它并不承诺所有文档格式都返回完全相同的一组固定扁平字段。

## 稳定报告外壳

完整 Probe Report 包含：

| 字段 | 含义 |
| --- | --- |
| `schema_version` | 报告契约版本，当前为 `2` |
| `tool_version` | 生成报告的 DeckProbe 版本 |
| `status` | `ok`、`partial` 或 `error` |
| `input` | 展示名称、输入来源类型和物理文件大小 |
| `driver` | 选中的格式驱动及 Profile |
| `results` | Target ID 到证据记录的映射 |
| `execution` | 探测级别、所选路径、预估和实际成本、未解析 Target |
| `diagnostics` | 结构化警告与诊断信息 |

每条结果记录 `target`、`status`、可选 `value`、`confidence`、`confidence_score`、所选 `path` 和证据 `source`。Target 状态可以是 `resolved`、`estimated`、`planned`、`unknown`、`unsupported`、`invalid`、`budget_exceeded` 或 `failed`。

```json
{
  "schema_version": 2,
  "status": "ok",
  "driver": {
    "id": "powerpoint",
    "profile": "pptx"
  },
  "results": {
    "powerpoint.slide_count": {
      "target": "powerpoint.slide_count",
      "status": "resolved",
      "value": 42,
      "confidence": "exact",
      "confidence_score": 1,
      "path": "powerpoint.presentation_xml",
      "source": "ppt/presentation.xml"
    }
  }
}
```

<Note>
  示例经过缩减，只突出 Target 证据。完整报告还包含 `tool_version`、`input`、`execution` 和 `diagnostics`。
</Note>

## 通用基座与格式扩展

当前实现注册了三类 Target Scope：

- `Common`：跨格式的身份、元数据、安全和质量 Target，例如 `document.format`、`document.author` 和 `security.encrypted`。
- `Office`：Office 驱动共享的事实，例如 `office.document_kind`、包条目数量和 OOXML Conformance。
- `Format`：格式驱动拥有的命名空间 Target，例如 `powerpoint.slide_count`、`excel.sheet_names`、`pdf.xref_type` 或 `keynote.slide_size`。

因此，DeckProbe 输出具有稳定的外层结构和共享词汇，同时允许已验证的文件格式通过自身命名空间提供额外事实。

## 探测深度与成本

DeckProbe 提供 `header`、`metadata` 和 `deep` 三个级别。级别限制可用 Target 和执行路径，但不会把结果变成 DeckOps 风格的元素模型。

每次执行均受物理读取量、解压量、归档条目数和运行时间预算约束。Planner 会选择满足目标置信度的最低成本有效路径，报告同时记录预估和实际 I/O 成本。

## 当前动画边界

当前实现没有通用的 `contains_animation` 或 `has_animation` Target。

- PowerPoint 驱动目前没有暴露动画或切换 Target。
- Keynote 驱动提供 `keynote.slides_with_builds_count` 和 `keynote.slides_with_transitions_count`，分别统计包含构建动画和切换效果的幻灯片数量。
- 这些 Keynote 结果是文档级统计，不是动画时间线或效果定义。

具体动画类型、触发方式、顺序和对象关系属于 [DeckOps Document IR](/zh/products/deckops/document-ir) 所描述的深度内容模型。

## 当前没有 `complexity`

`complexity` 不在当前 Target 注册表或 Schema v2 契约中。如果工作流需要复杂度分类，应根据文件大小、页面或幻灯片数量、包条目数量和资源数量等已实现事实自行计算。

## 发现当前版本的真实契约

```bash
deckprobe --pretty formats
deckprobe --pretty targets --format pptx
deckprobe schema
```

仓库中的 [JSON Schema](https://github.com/deckflow/deckprobe/blob/main/docs/deckprobe-report.schema.json) 是权威的机器可读报告契约。
