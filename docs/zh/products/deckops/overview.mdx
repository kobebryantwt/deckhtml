# DeckOps

DeckOps 是面向云端工作流的完整文档运行时，通过统一的 SDK 能力面提供 Probe、Parse、Extract、Convert 和 Render。

它的核心抽象是统一的 **Document IR**。不同格式的 Parser 将 PPTX、PDF、Keynote、Markdown 等支持的输入转换成同一种中间表示；下游操作面向 IR 实现，不再分别处理每一种源格式组合。

<Note>
  可以从架构上把 Document IR 类比为 LLVM IR：多种源格式先降低到共享表示，再由多种下游操作消费。这里只是设计类比，不表示兼容 LLVM。
</Note>

## 核心操作

| 操作 | 目标 |
| --- | --- |
| Probe | 在深度处理前嗅探文档身份、结构摘要、安全和质量信号 |
| Parse | 将支持的源格式降低为统一 Document IR |
| Extract | 返回页面语义结构和内容，例如 Title、Subtitle、Chart、Speaker notes 和 Footnotes |
| Convert | 生成另一种支持的格式，例如 PPTX → PDF、Keynote → PPTX 或 Markdown → PPTX |
| Render | 生成页面或幻灯片视觉画面，用于预览和下游处理 |

## Extract 是结构化提取

Extract 不只是把文字拼接出来。它基于 IR 保留页面边界、语义角色、层级和对象关系，使调用方能够区分 Title 与 Subtitle、Chart 与 Caption，以及 Speaker notes、Footnotes 和画布上的可见内容。

## 产品边界

只需要本地 Rust 或浏览器 SDK 获取目标式文件事实时，使用独立的 [DeckProbe](/zh/products/deckprobe/overview)；只需要云端渲染时，使用独立的 [DeckRender](/zh/products/deckrender/overview)。

一个云端工作流需要组合文档运行时，或需要共享 IR 支撑 Parse、Extract、Convert 和 Render 时，使用 DeckOps。需要通过源文件感知模型把变更写回支持的 Office 文件时，使用 [DeckUse](/zh/products/deckuse/overview)。

<Info>
  DeckOps 的执行能力位于云端，通过 SDK 接入。具体包、认证、调用限制、支持格式矩阵和 IR Schema 将在实现契约可用后补充。
</Info>
