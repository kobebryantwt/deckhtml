先选择应用需要得到的第一个结果。下面每个部分都包含安装、具体调用，以及能够证明示例成功的结果信号。

<Note>
  下文中的 DeckFlow JavaScript 包和 CLI 都通过 npm 安装。如果当前地区无法稳定访问默认 Registry，可在对应安装命令末尾增加 `--registry=https://registry.npmmirror.com`。建议只对单条命令生效，不要直接修改全局 Registry；镜像同步偶尔可能晚于 npm 官方版本。
</Note>

| 产品 | 第一个结果 | 执行位置 | 凭证 |
| --- | --- | --- | --- |
| DeckProbe | 文档事实的 Schema v2 报告 | 本地 | 无 |
| DeckRender | PNG、PDF 或支持的视频渲染 | 本地或云端 | 本地无需凭证；云端游客或认证 |
| DeckOps | 可持久保存的 DeckIR 产物和 Markdown 视图 | 默认本地；明确选择时使用云端 | 本地无需凭证 |
| DeckUse | 更新后的 PPTX | 本地 | 无 |
| DeckHTML | 从 HTML 生成 PPTX 或 PNG | 本地或云端 | 本地无需凭证 |

## DeckProbe：检查一个已知 PDF

<span className="product-kicker">本地 · 无需凭证 · 事实 JSON</span>

```bash
npm install -g @deckflow/deckprobe
deckprobe --version

curl -fL https://mozilla.github.io/pdf.js/web/compressed.tracemonkey-pldi-09.pdf -o sample.pdf
deckprobe -t format,page_count --view values --pretty sample.pdf
```

npm 软件包中的 CLI 会调用对应平台的原生二进制。成功时退出码为 `0`，`schema_version` 为 `2`，驱动为 `pdf`，并解析出 `document.format` 和 `pdf.page_count`：

```json
{
  "schema_version": 2,
  "status": "ok",
  "driver": { "id": "pdf", "profile": "pdf" },
  "values": {
    "document.format": "pdf",
    "pdf.page_count": 14
  }
}
```

完整响应和更多输入方式见 [DeckProbe 快速开始](/zh/deckprobe/quick-start)。

## DeckRender：生成 PNG

<span className="product-kicker">本地或云端 · 视觉产物 · 结构化结果</span>

```bash
npm install -g @deckflow/deckrender
deckrender hello.html --engine local -o hello.png --json --quiet
test -s hello.png
```

命令调用已安装的 Chrome/Chromium/Edge，把 HTML 保留在当前机器，写入 `hello.png`，并返回包含 `engine`、路线、页数、输出路径、字节数和耗时的 `RenderResult`。创建输入、检查本地依赖并体验游客云端路线，请查看 [DeckRender 快速开始](/zh/deckrender/quick-start)。

## DeckOps：解析一次，再生成 Markdown

<span className="product-kicker">默认本地 · 可持久 DeckIR · 可复用视图</span>

```bash
npm install -g @deckflow/deckops
deckops --version

curl -fL https://docs.deckflow.com/images/deckuse-sample.pptx -o sample.pptx
deckops parse sample.pptx --json
deckops convert sample/ --json
test -s sample/views/markdown/index.md
```

第一条命令创建 `sample/`，其中包含 `ir.json`、`manifest.json`、可选的 `probe.json` 和解析资源。第二条命令直接读取该 IR，不会重新解析 PPTX；成功结果会显示 `"reusedParse": true`，并写入 Markdown 视图。

DeckOps 默认把 PDF、PPTX、DOCX 和静态网页源码留在本地。完整验证流程和显式选择云端引擎的方法见 [DeckOps 快速开始](/zh/deckops/quick-start)。

## DeckUse：更新现有 PPTX

<span className="product-kicker">本地 · 现有 PPTX · 可编辑输出</span>

```bash
npm install -g @deckflow/deckuse
deckuse --version
curl -fL https://docs.deckflow.com/images/deckuse-sample.pptx -o input.pptx
deckuse init input.pptx ./workspace --json
printf '%s\n' '{"type":"replaceText","find":"Presentation Title Text","replace":"DeckUse Updated Title","selector":"kind=textbox","limit":1}' \
  | deckuse apply ./workspace --json
deckuse validate ./workspace --json
deckuse commit ./workspace -o updated.pptx --json
```

DeckUse 通过带版本的工作区在本地执行。CLI 可以检查和查询 PPTX 结构，修改文本、属性与几何信息，添加、复制或删除支持的幻灯片和元素，处理图片、表格与图表缓存，最后导出另一个 PPTX。前置条件、预期查询结果和最终验证请查看 [DeckUse 快速开始](/zh/deckuse/quick-start)。

## DeckHTML：在本地生成 PPTX

<span className="product-kicker">本地 Chromium · HTML 输入 · PPTX 输出</span>

```bash
npm install -g @deckflow/deckhtml
deckhtml deck.html -o deck.pptx --mode local --json --quiet
test -s deck.pptx
```

命令使用本地 Chromium，返回规范化路径、输出格式、执行模式和幻灯片数量。准备浏览器和幻灯片尺寸的 HTML 见 [DeckHTML 快速开始](/zh/deckhtml/quick-start)。
