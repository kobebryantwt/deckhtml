Deckflow 按文档任务组织产品。先确定应用需要得到什么结果，再进入对应产品文档完成安装、配置和接入。

## 选择第一个目标

| 使用场景 | 产品 | 第一步 |
| --- | --- | --- |
| 获取格式、元数据、结构、安全或资源事实 | DeckProbe | [完成第一次嗅探](/zh/deckprobe/quick-start) |
| 生成页面图片、缩略图或幻灯片预览 | DeckRender | [了解 DeckRender](/zh/deckrender/overview) |
| 解析成 Document IR、提取语义结构或转换格式 | DeckOps | [了解 DeckOps](/zh/deckops/overview) |
| 修改支持的 Office 源文件元素 | DeckUse | [了解 DeckUse](/zh/deckuse/overview) |
| 从 HTML 生成演示文稿产物 | DeckHTML | [完成第一次生成](/zh/deckhtml/quick-start) |

如果多个产品看起来都适用，可以在[选择产品](/zh/product-guide)中比较它们的能力边界。

## 按产品文档继续

每个产品区域都采用一致的文档组织方式：

<CardGroup cols={2}>
  <Card title="概览">
    了解产品解决什么问题、支持哪些输入，以及何时使用。
  </Card>
  <Card title="快速开始">
    安装或配置所需接入方式，并得到第一个结果。
  </Card>
  <Card title="使用指南">
    将产品应用到具体工作流、输入类型和运行约束。
  </Card>
  <Card title="CLI、SDK 或 API">
    通过该产品实际提供的接入方式完成集成。
  </Card>
  <Card title="输出与参考">
    确认响应契约、Schema、参数和错误行为。
  </Card>
</CardGroup>
