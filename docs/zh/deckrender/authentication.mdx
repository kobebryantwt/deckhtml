本地路线不需要 DeckFlow 凭证。云端路线可以通过限频的游客模式进行体验；持续调用、CI、生产额度或私有 Workspace 应使用 API Key，或者通过 CLI 的浏览器流程完成登录。登录后保存 Session Token，适合交互式开发；API Key 更适合无人值守服务。

<Note>
  前端 Browser SDK 使用独立契约：配置用户 Token，或显式设置 `guest: true`。它不会读取本地凭证文件、提供登录界面，也不应在浏览器代码中使用长期 API Key。
</Note>

## 浏览器登录

```bash
deckrender auth login
deckrender auth status
```

登录会打开 DeckFlow 授权页面，并把返回的 Token 保存到 `~/.deckflow/credentials`。存在凭证时，`auth status` 会向服务端验证并显示来源；没有凭证时，它只会报告当前使用访客模式，不发起凭证验证请求。

## API Key

配置 CLI 前，先获取 API Key：

<Steps>
  <Step title="打开 DeckFlow 设置">
    登录 DeckFlow，然后访问 [API Key 设置页面](https://app.deckflow.com/start#settings)。
  </Step>
  <Step title="创建并保存 API Key">
    在设置页面中配置 API Key，复制后保存到开发或生产环境使用的安全凭证存储中。
  </Step>
</Steps>

在开发机器上配置：

```bash
deckrender config set api-key YOUR_API_KEY
deckrender auth status
```

CI 或容器中建议使用环境变量，不写入凭证文件：

```bash
export DECKFLOW_API_KEY='YOUR_API_KEY'
deckrender hello.html -o hello.png --json --quiet
```

`DECKRENDER_API_KEY` 的优先级高于 `DECKFLOW_API_KEY`；为兼容已有环境，也会读取 `DECKHTML_API_KEY`。

<Warning>
  API Key 属于服务端凭证。不要写入浏览器代码、提交到代码仓库或输出到日志。
</Warning>

## 凭证解析

每个字段独立按以下顺序解析：

1. Node.js Renderer 显式选项。
2. DeckRender 或 DeckFlow 环境变量。
3. `~/.deckflow/credentials`。
4. 只读的 `~/.deckops/config.json`。
5. 内置 API 地址默认值。

运行 `deckrender config list` 可以查看脱敏后的有效值和来源。

## 退出登录与回退凭证

```bash
deckrender auth logout
deckrender config list
```

退出登录只会删除 DeckFlow 共享文件中的凭证。环境变量或 DeckOps 配置中的 Token 仍然可能让后续调用处于认证状态，请通过 `config list` 确认最终来源。

CLI 或 Node.js 中已配置的凭证被拒绝时，DeckRender 会丢弃该凭证及关联的 `spaceId`，给出警告并以游客模式重试一次。`402 Payment Required` 不会重试。如果游客请求也被拒绝，交互式终端可以继续浏览器登录；JSON 和 CI 调用不会打开浏览器，而是返回 `auth_error`。

格式、Profile、宽度和超时等渲染默认值请查看[配置](/zh/deckrender/configuration)。
