DeckRender 把支持的文档转为预览、交付、视觉审阅和多模态流程需要的视觉产物。CLI 与 Node.js SDK 可以选择私有本地引擎或 DeckFlow 云端；Browser SDK 则让前端应用直接接入云端渲染。

| 项目 | 快速了解 |
| --- | --- |
| 输入 | `.pptx`、`.pdf`、HTML、URL，以及云端支持的其他格式 |
| 输出 | PNG、JPEG、WebP 图片；PDF；MP4 视频 |
| 接入方式 | `deckrender` CLI、Node.js SDK 和纯云端 Browser SDK |
| 执行位置 | 已实现的 PPTX/PDF/HTML 路线可在本地执行，更多格式通过 DeckFlow 云端完成 |
| 认证 | 本地路线无需认证；云端支持游客模式、API Key 或 Session Token |

## DeckRender 适合什么

- 页面或幻灯片预览和缩略图。
- 用于评审、搜索或视觉流程的 PNG、JPEG、WebP 图片。
- 从支持的演示文稿、文档或 HTML 生成 PDF。
- 从 PowerPoint 生成 MP4，或通过 PPTX 路径从 HTML 生成 MP4。
- 在本地与云端渲染路径中获得稳定的产物与结果契约。
- 对支持的 PPTX、PDF 和 HTML 路线进行私有本地渲染，不向 DeckFlow 上传文档字节。

## 一次渲染如何执行

<Steps>
  <Step title="解析输入">
    读取一个文件或标准输入流，或者在本地 Node.js 进程中抓取一个 URL。
  </Step>
  <Step title="选择引擎与路线">
    使用 `local`、`cloud` 或本地优先的 `auto`，再根据源格式、目标产物和兼容参数匹配对应引擎的路线表。
  </Step>
  <Step title="在本地或云端执行">
    本地路线在当前机器完成支持的文档处理；云端路线会上传源文件并执行托管转换任务。
  </Step>
  <Step title="写出并返回结果">
    下载并按指定布局写出产物，然后返回描述执行路线和文件位置的 `RenderResult`。
  </Step>
</Steps>

<Tip>
  DeckRender 不解析文本或文档元素，不返回 Document IR，也不编辑源内容。内部的 `RenderPlan` 只描述执行路径。
</Tip>

## 数据与执行边界

显式选择 `local` 后，文档不会上传，也不会在失败时转为云端。当前本地支持 PPTX→图片/PDF、PDF→图片/PDF，以及 HTML 或 URL→图片。本地 PPTX 和 PDF 路线不会读取云端凭证或访问 DeckFlow；HTML 页面仍可能加载自身引用的远程资源。

云端路线会上传源文件和中间产物。游客模式适合体验，认证模式提供生产额度和 Workspace 访问。默认引擎仍为 `cloud`；`auto` 会优先使用当前路线对应的本地能力，只有本地不支持时才警告并选择云端。

HTTP(S) URL 由本地 Node.js 进程获取。DeckRender 不会捕获用户浏览器当前的状态、Cookie 或认证会话。本地模式在当前机器捕获页面；云端模式则上传获取到的源内容。

<Warning>
  HTML 转 PDF 和 HTML 转视频会先把 HTML 重建为 PPTX。结果遵循幻灯片模型，并不是原生打印布局或在线页面录制。
</Warning>
