本示例把一份已知演示文稿中的 `Presentation Title Text` 修改为 `DeckUse Updated Title`。源文件与输出文件都留在本地，并且不会覆盖原始 PPTX。

## 前置条件

- Node.js 18 或更高版本
- 不需要 DeckFlow 账号或 API Key

## 运行示例

<Steps>
  <Step title="安装 CLI">
    ```bash
    npm install -g @deckflow/deckuse
    deckuse --version
    deckuse --help
    ```
  </Step>
  <Step title="下载文档示例演示文稿">
    ```bash
    curl -fL https://docs.deckflow.com/images/deckuse-sample.pptx \
      -o input.pptx
    ```

    这份文档示例中有一个可编辑文本框的内容为 `Presentation Title Text`。
  </Step>
  <Step title="初始化并检查匹配结果">
    ```bash
    deckuse init input.pptx ./workspace --json
    deckuse query ./workspace 'text=Presentation Title' --limit 10 --json
    ```

    只有查询返回预期文本框时才继续。先检查再修改，可以避免对未知文件执行意外的全局替换。
  </Step>
  <Step title="创建确认后的操作">
    保存为 `replace.json`：

    ```json
    {
      "type": "replaceText",
      "find": "Presentation Title Text",
      "replace": "DeckUse Updated Title",
      "selector": "kind=textbox",
      "limit": 1
    }
    ```
  </Step>
  <Step title="执行、校验并导出">
    ```bash
    deckuse apply ./workspace --input replace.json --json
    deckuse validate ./workspace --json
    deckuse commit ./workspace -o updated.pptx --json
    ```

    请确认 `apply` 结果包含 `ok: true`、`matched: 1` 和一个新版本。提交前，校验也必须返回 `ok: true`。
  </Step>
  <Step title="把输出作为新输入验证">
    ```bash
    deckuse init updated.pptx ./verification --json
    deckuse query ./verification 'text=DeckUse Updated Title' --limit 10 --json
    test -s updated.pptx
    ```

    验证查询应返回 `DeckUse Updated Title`，并且不再包含 `Presentation Title Text`。PowerShell 中使用以下命令检查文件：

    ```powershell
    if (!(Test-Path updated.pptx) -or (Get-Item updated.pptx).Length -eq 0) { exit 1 }
    ```
  </Step>
</Steps>

## 本示例验证了什么

- DeckUse 在修改前索引到了预期的源对象。
- JSON 命令只匹配了一个文本框。
- 工作区通过结构校验。
- `commit` 生成了非空、可以重新读取的独立 PPTX。

<Warning>
  结构校验不等于视觉校验。把 `updated.pptx` 用于交付流程前，请打开或渲染检查。
</Warning>
