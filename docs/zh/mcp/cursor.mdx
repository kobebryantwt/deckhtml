本页重点说明如何在 Cursor 中配置 Deckflow MCP。重点不是介绍工作流模式，而是帮助你完成接入：添加服务器、完成授权、确认工具可见，然后开始使用 Deckflow。

<Note>
  Cursor 的 MCP 入口会因版本略有差异，但常见方式基本一致：要么通过设置页添加，要么直接编辑 MCP 配置文件。
</Note>

## 通过 Cursor 设置页添加

<Steps>
  <Step title="打开 Cursor 的 MCP 设置">
    在 Cursor 中进入 Settings，然后打开 MCP 或 Tools & Integrations 相关区域。
  </Step>
  <Step title="新增自定义 MCP Server">
    创建一个名为 `deckflow` 的服务器条目。
  </Step>
  <Step title="填写 Deckflow 端点">
    使用托管地址：

    ```text
    https://mcp.deckflow.com/mcp/v1/
    ```
  </Step>
  <Step title="如有需要则完成授权">
    如果 Cursor 要求在浏览器中完成授权，先完成该流程，再返回 MCP 面板。
  </Step>
</Steps>

## 备选方式：直接编辑 MCP 配置

如果你的 Cursor 版本通过 JSON 文件管理 MCP 配置，可以直接写入：

```json
{
  "mcpServers": {
    "deckflow": {
      "url": "https://mcp.deckflow.com/mcp/v1/"
    }
  }
}
```

把这段配置写入当前环境对应的 Cursor MCP 配置位置，或者写入项目级 MCP 文件中。

## 本地 stdio 方式

如果你的 Cursor 工作流必须传递本地绝对路径文件，可以切换成本地 stdio：

```json
{
  "mcpServers": {
    "deckflow": {
      "command": "node",
      "args": ["/绝对路径/deckflow-mcp/dist/entry/stdio.js"],
      "env": {
        "DECKFLOW_API_KEY": "<你的 API key>"
      }
    }
  }
}
```

## 验证连接

配置完成后，确认：

- Cursor 的 MCP 列表中已经出现 `deckflow`
- 服务状态正常，且已完成授权
- 在 chat 或 agent 模式下可以发现 Deckflow 工具
