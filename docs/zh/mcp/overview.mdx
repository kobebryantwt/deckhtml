Deckflow MCP 可以接入常见的 MCP 客户端，让智能体直接调用 Deckflow 的演示文稿能力，包括 HTML 转可编辑 PPTX、格式转换、文件处理，以及生成、翻译、焕新等工作流。

<Note>
  托管端点为 `https://mcp.deckflow.com/mcp/v1/`。大多数客户端的接入流程都类似：添加服务器、完成授权、确认工具可见，然后开始调用 Deckflow 工具。
</Note>

## 将 Deckflow 添加到你的智能体

<Steps>
  <Step title="打开客户端的 MCP 配置入口">
    在你的智能体客户端中找到 MCP、连接器或工具设置，并进入添加自定义服务器的入口。
  </Step>
  <Step title="填写 Deckflow MCP 端点">
    使用托管端点：

    ```text
    https://mcp.deckflow.com/mcp/v1/
    ```
  </Step>
  <Step title="按客户端要求完成授权">
    有些客户端会自动拉起浏览器授权；有些客户端则通过配置文件、Header、Query 参数或环境变量保存凭证。
  </Step>
  <Step title="确认连接成功并开始调用工具">
    配置完成后，先确认 `deckflow` 服务已可用，再开始执行 HTML 转 PPTX、格式转换或文档处理任务。
  </Step>
</Steps>

<Tip>
  不同客户端的菜单名称可能略有差异。下面的产品页会给出各自更具体的配置方式。
</Tip>

## 支持的产品

当前文档已经提供以下接入指南：

- [Codex](/zh/mcp/codex)：通过 Codex 设置页或编辑 `~/.codex/config.toml` 接入。
- [Cursor](/zh/mcp/cursor)：通过 Cursor 的 MCP 设置页或配置文件接入。
- [Claude Code](/zh/mcp/claude-code)：通过 `claude mcp add`、`.mcp.json` 或 `~/.claude.json` 接入。
- [TRAE](/zh/mcp/trae)：通过图形化 MCP 面板手动添加托管配置或本地 stdio 配置。
- [WorkBuddy](/zh/mcp/workbuddy)：通过连接器界面配置托管 Deckflow MCP，并完成授权。

如果你的客户端支持自定义 MCP Server，通常也可以直接复用同一个 Deckflow 托管端点。

## 你可以做什么

连接完成后，Deckflow MCP 主要适合这些场景：

- [HTML 转可编辑 PPTX](/mcp/tools#rendering-and-conversion)：把 HTML 幻灯片页面或网页演示内容转成 PPTX 演示文稿。
- [多种格式之间转换](/mcp/tools#rendering-and-conversion)：在 PPTX、PDF、图片、HTML 等格式之间转换，方便交付、评审和分享。
- [处理 PPTX 与文件工具链](/mcp/tools#file-and-pptx-utilities)：在同一条工作流里完成 OCR、压缩、拆分、合并、嵌入字体和内容检查。
- [生成、翻译与焕新演示文稿](/mcp/tools#presentation-and-document-creation)：基于提示词和参考材料生成初稿，翻译保留版式的文档，或重新整理已有演示文稿。

## 接入方式说明

大多数用户优先使用托管端点：

```text
https://mcp.deckflow.com/mcp/v1/
```

不同客户端通常会采用以下三种接入方式之一：

- **图形界面添加**：在设置页里新增自定义 MCP Server，并在需要时完成浏览器授权。
- **直接编辑配置文件**：手动把 Deckflow 写进 `config.toml`、`mcp.json` 或 `.mcp.json`。
- **CLI 注册**：通过类似 `claude mcp add` 的命令快速完成配置。

如果你的工作流必须把本地绝对路径文件直接交给 MCP Server 处理，就需要改用本地 `stdio` 模式。一个典型配置如下：

```json
{
  "mcpServers": {
    "deckflow": {
      "command": "node",
      "args": ["/绝对路径/deckflow-mcp/dist/entry/stdio.js"],
      "env": {
        "DECKFLOW_API_KEY": "<你的 API key>"
      }
    }
  }
}
```

如果你追求最省事的接入方式，优先使用托管端点；如果客户端必须直接访问你本机上的文件，再切换到本地 `stdio` 模式。
