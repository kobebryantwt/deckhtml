本页重点说明如何在 Codex 中配置 Deckflow MCP。核心目标很简单：把一个或多个 Deckflow Server 注册进 Codex、确认连接成功，然后开始在日常工作流里调用 Deckflow 工具。

<Note>
  Codex 的用户级配置通常保存在 `~/.codex/config.toml`，也可以通过项目内的 `.codex/config.toml` 做项目级覆盖。
</Note>

## 推荐方式

大多数情况下，优先通过 Codex 的设置界面添加 MCP Server。如果你更习惯通过配置文件维护环境，也可以直接把这些 Deckflow Server 写进 Codex 的配置文件中。

## 通过 Codex 图形界面添加

<Steps>
  <Step title="打开 MCP Server 设置">
    在 Codex 中进入设置页，并打开 MCP Servers 相关区域。
  </Step>
  <Step title="新增一个或多个自定义服务器">
    创建类似 `deckflow-html2pptx`、`deckflow-pptx`、`deckflow-tools` 这样的 MCP Server 条目。
  </Step>
  <Step title="填写对应的 Deckflow 端点">
    按需添加这些托管端点：

    ```text
    https://mcp.deckflow.com/v1/html2pptx
    https://mcp.deckflow.com/v1/pptx
    https://mcp.deckflow.com/v1/tools
    ```
  </Step>
  <Step title="如有提示则完成授权">
    如果 Codex 会拉起浏览器或要求补充凭证，先完成这一步，再返回 MCP 列表。
  </Step>
</Steps>

## 备选方式：直接编辑 `config.toml`

你也可以在 Codex 配置文件中直接写入这些 Deckflow Server：

```toml
[mcp_servers.deckflow-html2pptx]
url = "https://mcp.deckflow.com/v1/html2pptx"
enabled = true

[mcp_servers.deckflow-pptx]
url = "https://mcp.deckflow.com/v1/pptx"
enabled = true

[mcp_servers.deckflow-tools]
url = "https://mcp.deckflow.com/v1/tools"
enabled = true
```

如果这是你个人环境，写入 `~/.codex/config.toml` 即可；如果你希望只在某个项目中生效，可以写入项目目录下的 `.codex/config.toml`。

## 验证连接

配置完成后，至少确认以下几点：

- Codex 的 MCP 设置页里能看到你添加的 Deckflow Server
- 每个已添加的服务都已启用且连接成功
- 新会话里可以发现 Deckflow 暴露的工具

## 先试一个任务

```text
使用 deckflow-html2pptx 把这份 HTML 幻灯片页面转换成可编辑的 PPTX。
```

```text
使用 deckflow-pptx 把这个演示文稿按章节拆成多个 PPTX 文件。
```

```text
使用 deckflow-tools 把这个 PDF 转成图片，方便评审。
```
