Deckflow 的各类 API 场景共用同一套任务模型。在阅读生成、翻译、焕新或工具 API 之前，建议先理解这一层共用基础。

## Base URL

```text
https://app.deckflow.com/api
```

## 必填请求头

| 请求头 | 是否必填 | 作用 |
|---|---|---|
| `Authorization` | 是 | 使用 `Bearer <YOUR_API_KEY>` 进行认证。 |
| `Content-Type` | 提交任务时必填 | 创建任务时使用 `multipart/form-data`。 |

## 共用异步流程

<Steps>
  <Step title="完成认证">
    在请求头中传入 API Key。
  </Step>
  <Step title="提交任务">
    上传文件、指定 `type`，并在 `params` 中放入场景参数。
  </Step>
  <Step title="轮询状态">
    保存任务 ID，并持续查询直到任务完成或失败。
  </Step>
  <Step title="下载结果">
    任务完成后，从返回结果中的签名下载链接获取最终文件。
  </Step>
</Steps>

## 常见提交字段

| 字段 | 是否必填 | 含义 |
|---|---|---|
| `files` | 大多数场景必填 | 待处理的源文件。合并类场景支持多个文件。 |
| `type` | 是 | 业务场景或工具类型，例如 `generation`、`translation`、`revamp`、`convertor.html2pptx`。 |
| `params` | 通常建议传 | 场景相关的 JSON 字符串。 |
| `name` | 否 | 任务显示名称。 |
| `notifyURL` | 否 | 任务状态变更的 Webhook 回调地址。 |
| `spaceId` | 否 | 当环境要求时传入空间 ID。 |

## 状态处理

- 创建成功后，任务通常会进入 `pending` 或 `processing` 状态。
- 持续轮询查询接口，直到进入终态。
- 成功后会返回结果元数据与下载链接。
- 失败后会返回错误信息，便于排查。
