Deckflow API 的业务能力很多，但底层其实围绕同一套异步任务模型展开。无论是文档生成、翻译、焕新，还是文件转换与优化，本质上都建立在两个核心接口之上：

- `POST /tools/tasks`
- `GET /tools/tasks/{id}`

因此，这一节会分成两层来讲：

- **核心接口**：解释任务是如何被提交和查询的
- **场景文档**：解释同一个接口在不同 `type + params` 下怎么覆盖不同业务能力

<Note>
  交互式接口页由仓库内的 OpenAPI 文件驱动；场景页则用于帮助你理解同一个接口在不同业务场景中的调用方式。
</Note>
