翻译任务仍然复用统一的异步任务接口。区别只是 `type` 必须固定为 `translation`，而 `params` 中需要明确传入语言参数。

## 场景映射

| 字段 | 值 |
|---|---|
| 接口 | `POST /tools/tasks` |
| `type` | `translation` |
| 文件 | PPTX、Keynote、PDF、Word、Excel 等演示型或文档型文件 |
| 查询接口 | `GET /tools/tasks/{id}` |

## Form Data 字段

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|---|---|
| `spaceId` | `String` | 否 | 目标工作空间 Space ID。 |
| `files` | `File` | 是 | 待翻译的源文档。官方文档列出 PPTX、Keynote、PDF、Word、Excel，支持上传多个文件。 |
| `type` | `String` | 是 | 固定值：`translation`。 |
| `name` | `String` | 否 | 任务显示名称，例如 `"AI 翻译文档任务"`。 |
| `params` | `String (JSON)` | 是 | 包含翻译参数的 JSON 字符串。 |

## `params` 字段说明

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|---|---|
| `from` | `String` | 是 | 源语言代码，例如 `"zh"`。 |
| `to` | `String` | 是 | 目标语言代码，例如 `"en"`。 |
| `notifyURL` | `String` | 否 | 任务状态变更通知的 Webhook 回调地址。 |

## 支持的语言列表

## `params` 示例

```json
{
  "from": "zh",
  "to": "en",
  "notifyURL": "https://your.domain/callback"
}
```

<Tip>
  官方文档明确将这个工作流定位为面向演示型文档的翻译流程，并强调尽量保留原始版式和视觉结构。
</Tip>
