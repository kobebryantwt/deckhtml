五个产品解决不同的文档任务。选择时应关注应用最终需要什么结果，而不只是输入文件的格式。

| 产品 | 适合场景 | 执行方式 | 主要结果 |
| --- | --- | --- | --- |
| DeckProbe | 快速嗅探、上传检查、路由和策略判断 | 本地原生 Rust 或 Browser JS SDK | 带置信度和实际成本的 Target 证据 |
| DeckRender | 专注文档渲染 | 通过 SDK 调用云端渲染 | 页面或幻灯片画面 |
| DeckOps | 云端解析、提取、转换和文档操作 | 通过 CLI 或 SDK 执行云端任务 | 格式专属结构化结果、Markdown 或生成文件 |
| DeckUse | 源文件感知的 Office 文件操作 | 本地库工作流 | 更新后的 Office 源文件 |
| DeckHTML | HTML 与 SVG 驱动的 Deck 创作 | 本地与云端路径 | 根据浏览器布局生成 PPTX 或 PNG |

## DeckProbe 还是 DeckOps？

这是最容易混淆的边界：

- 最终结果是文档级事实，例如已验证格式、元数据、数量、安全信号、置信度和探测成本时，选择 **DeckProbe**。
- 需要页面和元素结构、格式专属解析结果、Markdown 投影、信息提取或格式转换时，选择 **DeckOps**。
- DeckProbe 的 `deep` 级别仍然返回 Target 证据，不会返回 DeckOps 解析结果。

## DeckRender 还是 DeckOps？

- 只需要渲染后的页面或幻灯片时，选择 **DeckRender**。
- Render 属于更大的流程，并且还需要 Probe、Parse、Extract 或 Convert 时，选择 **DeckOps**。

## DeckOps 还是 DeckUse？

- 解析支持的格式或生成云端派生结果时，选择 **DeckOps**。
- 支持的 Office 文件仍然是可编辑产物，并需要修改或删除已有元素时，选择 **DeckUse**。

## 什么时候使用 DeckHTML？

HTML 或 SVG 是幻灯片结构和视觉设计的源格式时，选择 DeckHTML。它会把浏览器布局转换为 PPTX 或 PNG，并报告元素保持可编辑或发生栅格降级的位置。
