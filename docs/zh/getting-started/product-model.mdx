# 产品模型

产品名描述对文档执行什么操作；CLI、SDK、API 和 MCP 等接入界面描述调用方如何使用这项能力。

| 产品 | 方向 | 主要职责 | 不负责 |
| --- | --- | --- | --- |
| DeckProbe | 只读 | 带证据、置信度和探测成本的目标式文档事实 | 元素级内容提取、渲染、转换或修改 |
| DeckRender | 源文件到视觉产物 | 通过 SDK 调用云端文件渲染 | 解析成 IR 或编辑源文件 |
| DeckOps | 源文件到 IR 与派生结果 | 在统一云端运行时中提供 Probe、Parse 成 Document IR、Extract、Convert 和 Render | 通过源文件感知模型回写变更 |
| DeckUse | 双向 | Manipulate 支持的 Office 源文件 | 通用文档转换或 HTML 原生创作 |
| DeckHTML | HTML-native Deck Engine | 通过本地与云端路径从 HTML 生成演示文稿产物 | 通用已有文档嗅探或 Manipulate |

## 典型组合

1. 使用 DeckProbe 只请求路由与策略判断所需的文档事实。
2. 只需渲染时使用 DeckRender；需要统一 IR、语义 Extract、Convert 或组合运行时时使用 DeckOps。
3. Manipulate 支持的 Office 源文件时使用 DeckUse；HTML 是 Deck 原生创作源时使用 DeckHTML。

<Warning>
  不要从接入界面的名称推断产品契约。例如，一个 MCP Server 可能暴露多个产品支持的工具。应以能力与产品边界为准，传输方式是第二层概念。
</Warning>
