# 使用 Deckflow 构建文档工作流

Deckflow 现在围绕五个产品组织。先按所需的文档操作选择产品，再在产品内部选择已有的 CLI、SDK、API 或 MCP 接入方式。

<CardGroup cols={2}>
  <Card title="DeckProbe" href="/zh/products/deckprobe/overview">
    无需渲染即可嗅探文件，并按需返回目标事实。
  </Card>
  <Card title="DeckRender" href="/zh/products/deckrender/overview">
    把源文件渲染成预览或下游流程所需的视觉产物。
  </Card>
  <Card title="DeckOps" href="/zh/products/deckops/overview">
    将不同格式解析成统一 Document IR，再进行 Extract、Convert 或 Render。
  </Card>
  <Card title="DeckUse" href="/zh/products/deckuse/overview">
    Manipulate 支持的 Office 源文件，并保持文件可继续编辑。
  </Card>
  <Card title="DeckHTML" href="/zh/products/deckhtml/overview">
    使用 HTML-native Deck Engine 生成演示文稿产物。
  </Card>
</CardGroup>

<Card title="运行时架构" href="/zh/getting-started/runtime-architecture">
  了解核心文档运行时、Office Manipulate Layer 和 HTML-native Deck Engine 如何协作。
</Card>

## 按意图选择

| 目标 | 产品 |
| --- | --- |
| 识别文件，读取元数据或结构事实 | [DeckProbe](/zh/products/deckprobe/overview) |
| 生成页面或幻灯片视觉画面 | [DeckRender](/zh/products/deckrender/overview) |
| Parse 成 Document IR、Extract 语义结构、Convert 或使用组合运行时 | [DeckOps](/zh/products/deckops/overview) |
| Manipulate 支持的 Office 源文件元素 | [DeckUse](/zh/products/deckuse/overview) |
| 从 HTML 创作 Deck | [DeckHTML](/zh/products/deckhtml/overview) |

<Note>
  CLI、SDK、API 和 MCP 是接入界面，不是产品分类。对应文档应位于它所暴露的产品或共享平台能力之下。
</Note>
