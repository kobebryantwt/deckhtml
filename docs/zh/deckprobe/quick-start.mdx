本流程使用原生 CLI，全部操作都在本机完成，不需要账号或 API Key。

<Steps>
  <Step title="通过 npm 安装并验证">
    ```bash
    npm install -g @deckflow/deckprobe
    deckprobe --version
    deckprobe --help
    ```

    npm 包会根据当前操作系统和 CPU 架构选择对应的原生可执行程序。
  </Step>
  <Step title="下载多页 PDF">
    ```bash
    curl -fL https://mozilla.github.io/pdf.js/web/compressed.tracemonkey-pldi-09.pdf \
      -o sample.pdf
    ```

    这份论文共有 14 页，包含足够的结构和元数据，便于验证探测结果。
  </Step>
  <Step title="请求格式和页数">
    ```bash
    deckprobe \
      --targets format,page_count \
      --view values \
      --pretty \
      sample.pdf
    ```
  </Step>
  <Step title="验证结果">
    成功的 Values Report 退出码为 `0`，包含 `schema_version: 2`、PDF Driver，以及类似以下内容的 `values`：

    ```json
    {
      "schema_version": 2,
      "tool_version": "<installed-version>",
      "status": "ok",
      "view": "values",
      "driver": {
        "id": "pdf",
        "profile": "pdf"
      },
      "values": {
        "document.format": "pdf",
        "pdf.page_count": 14
      },
      "unresolved_targets": [],
      "diagnostics": []
    }
    ```

    完整结果还包含 `input`；部分 Target 被顺带解析时，可能出现其他字段。
  </Step>
</Steps>

## 接入自动化流程前

- 将格式专属 Target ID 写入程序前，先运行 `deckprobe targets pdf --pretty`，确认每个 Target 的最低 Probe Level 和适用范围。
- 如果所有请求的 Target 都必须解析成功，请加入 `--strict`。存在未解析 Target 时，DeckProbe 仍会输出完整 JSON，随后以状态码 `5` 退出。
