`@deckflow/deckprobe` 包通过 WebAssembly 运行同一套目标驱动 Rust 引擎，接受 `File`、`Blob`、`ArrayBuffer` 和 `Uint8Array`，文档字节始终留在浏览器中。

## 安装

```bash
npm install @deckflow/deckprobe
```

软件包已经包含下文使用的 JavaScript 入口、TypeScript 类型定义和 WebAssembly 运行文件。

## 在主线程中 Probe

`probe()` 会延迟初始化 WebAssembly。可以在应用启动或空闲时调用 `initDeckProbe()`，提前准备第一次交互：

```ts
import { initDeckProbe, probe } from "@deckflow/deckprobe";

await initDeckProbe();

const report = await probe(file, {
  targets: ["@summary", "@security"],
  level: "metadata",
});
```

浏览器 `File` 自带文件名；`Blob`、`ArrayBuffer` 或 `Uint8Array` 需要传入逻辑文件名，让扩展名选择格式：

```ts
const bytes = await fetch("/documents/quarterly-deck").then((response) =>
  response.arrayBuffer(),
);

const report = await probe(bytes, {
  name: "quarterly-deck.pptx",
  targets: ["powerpoint.slide_count"],
});
```

`initDeckProbe()` 的配置只会在首次初始化时生效。自定义运行时必须在第一次调用 `probe()` 前完成配置。

## 在 Worker 中 Probe

用户文件、大文件或不应占用 UI 线程的 Deep Probe 使用 Worker 入口：

```ts
import { createDeckProbeWorker } from "@deckflow/deckprobe/worker";

const worker = createDeckProbeWorker();
try {
  const report = await worker.probe(file, {
    targets: ["@summary"],
    level: "deep",
  });
} finally {
  worker.terminate();
}
```

一批任务可以复用同一个 Worker，在所属页面或任务结束时终止。`terminate()` 会取消尚未完成的 Probe。

## 发现可用能力

主 SDK 入口导出 `formats()`、`targets(format)`、`schema()` 和 `version()`：

```ts
import { formats, schema, targets, version } from "@deckflow/deckprobe";

const engineVersion = await version();
const supportedFormats = await formats();
const pdfTargets = await targets("pdf");
const reportSchema = await schema();
```

所有查询函数都是异步方法。可以用它们生成格式和 Target Selector、按照内置契约校验响应，以及展示当前引擎版本。

## Vite 开发配置

需要把 DeckProbe 从 Vite 依赖预构建中排除。缺少此设置时，开发环境可能把 WebAssembly Wrapper 移离 `.wasm` 文件，导致 404，或在预期 WebAssembly 字节的位置返回 HTML。

```ts
// vite.config.ts
import { defineConfig } from 'vite';

export default defineConfig({
  optimizeDeps: {
    exclude: ['@deckflow/deckprobe'],
  },
});
```

主线程和 Worker 入口都需要此设置。

<Tip>
  `probe()` 与 Worker API 都会把完整输入加载到内存。Worker 可以让字节转换和解析避开 UI 线程，但不会减少内存占用；超大文件或大批量任务应优先使用原生 CLI。
</Tip>
