DeckProbe 将结构化 JSON 写入标准输出。单文件 Probe 输出一个 JSON Value；JSONL 模式为每个非空输入行输出一个紧凑 JSON Value。

Schema v2 定义了三种报告形态：

- Target 成功或部分解析时的 <strong>Full Probe Report</strong>。
- 不需要证据明细时使用的紧凑 <strong>Values Report</strong>。
- 请求、输入、格式、预算或 Parser 失败时的结构化 <strong>Error Report</strong>。

## Full Probe Report

完整报告包含以下顶层字段：

| 字段 | 含义 |
| --- | --- |
| `schema_version` | 契约版本，当前为 `2` |
| `tool_version` | 生成报告的 DeckProbe 版本 |
| `status` | 所有 Target 满足请求时为 `ok`，否则为 `partial` |
| `input` | 展示名称、来源类型和物理文件大小 |
| `driver` | 验证后的格式 Driver 和 Profile |
| `results` | Canonical Target Key 到证据记录的映射 |
| `execution` | Probe Level、执行路径、预估/实际成本和未解析 Target |
| `diagnostics` | Planning 或 Probe 产生的结构化警告 |

以下示例中的数值和成本仅用于说明，字段名与结构遵循 Schema v2。

```json
{
  "schema_version": 2,
  "tool_version": "2.4.0",
  "status": "ok",
  "input": {
    "display_name": "deck.pptx",
    "source_kind": "local_file",
    "file_size": 245760
  },
  "driver": {
    "id": "powerpoint",
    "profile": "pptx"
  },
  "results": {
    "powerpoint.slide_count": {
      "target": "powerpoint.slide_count",
      "status": "resolved",
      "value": 31,
      "confidence": "exact",
      "confidence_score": 1,
      "path": "powerpoint.presentation_xml",
      "source": "ppt/presentation.xml"
    }
  },
  "execution": {
    "probe_level": "metadata",
    "paths": ["powerpoint.presentation_xml"],
    "estimated_cost": 12,
    "actual_cost": {
      "physical_bytes_read": 4096,
      "expanded_bytes": 16384,
      "random_reads": 2
    },
    "unresolved_targets": []
  },
  "diagnostics": []
}
```

## Target Evidence

每个请求的 Target 都有明确状态：

| 状态 | 含义 |
| --- | --- |
| `resolved` | Value 满足请求的置信度 |
| `estimated` | 通过近似或间接证据得到 Value |
| `planned` | Plan-only 模式选择了路径，但没有执行 |
| `unknown` | 对应 Path 已执行，但文档没有记录这项事实；这是正常结果 |
| `unsupported` | 检测到的格式和当前请求下，没有可满足该 Target 的 Path |
| `invalid` | 文档记录了值，但该值没有通过验证 |
| `budget_exceeded` | 解析 Target 超出当前预算 |
| `failed` | 所选 Parser Path 执行失败 |

已解析证据包含 Target 定义的 `value`、分类与数值置信度、执行路径和证据来源。

### 置信度表示证据强度

`confidence` 表示所选 Path 对当前 Value 的证据强度。`confidence_score` 是每个等级对应的固定数值，并不是经过统计校准的正确概率或准确率：

| 等级 | 分数 | 典型证据 |
| --- | ---: | --- |
| `exact` | `1.0` | 直接从权威结构读取 |
| `high` | `0.95` | 从应用保存的统计信息读取，但该统计可能过期 |
| `medium` | `0.7` | 通过结构代理信息推断 |
| `low` | `0.4` | 较弱或间接的证据 |
| `none` | `0.0` | 当前结果不携带 Value |

这些数值适合排序或过滤证据，不能把 `0.95` 解读成真实准确率为 95%。

<Tip>
  报告级 `partial` 表示至少一个请求的 Target 没有达到要求的置信度，并不表示文档已经损坏或不安全，其他已解析结果仍然可以使用。通过 `execution.unresolved_targets` 确认受影响的 Target。
</Tip>

## 确定性执行成本

`execution.actual_cost` 记录物理读取字节数、解压字节数和随机读取次数。默认不输出墙钟时间 `elapsed_ms`，因此相同输入与参数可以生成字节一致的 JSON；需要耗时数据时增加 `--telemetry`。

## 紧凑 Values Report

调用方只需要 Target Value 时使用 `--view values`：

```bash
deckprobe -t @summary --view values report.pdf
```

结果仍保留 Schema Version、Input、Driver、未解析 Target 和 Diagnostics，但会把完整证据记录替换为紧凑的 `values` Map。

## Error Report

语法和运行时错误使用同一种机器可读结构：

```json
{
  "schema_version": 2,
  "tool_version": "2.4.0",
  "status": "error",
  "error": {
    "code": "MALFORMED_INPUT",
    "message": "malformed input: .docx package is missing required main part word/document.xml",
    "exit_code": 4
  }
}
```

稳定错误码包括 `CLI_SYNTAX`、`INVALID_REQUEST`、`UNSUPPORTED_TARGET`、`SOURCE_IO`、`UNSUPPORTED_FORMAT`、`MALFORMED_INPUT`、`BUDGET_EXCEEDED` 和 `PARSER_FAILURE`。

## JSON Schema

版本化的 [deckprobe-report.schema.json](https://github.com/deckflow/deckprobe/blob/main/docs/deckprobe-report.schema.json) 定义 Full Report、Values Report、Evidence、Execution、Diagnostics 和 Error Report，可用于响应校验、生成类型或 Agent Tool Contract。

打印当前已安装二进制内置的准确 Schema：

```bash
deckprobe schema --pretty
```

当应用需要按照所调用二进制的同一契约版本进行校验时，应优先使用该命令输出。

## 查看当前支持能力

DeckProbe 提供 Discovery Command，应用无需硬编码所有格式与 Target：

| 命令 | 返回内容 |
| --- | --- |
| `deckprobe formats --pretty` | 支持的 Driver、Profile 和能力边界 |
| `deckprobe targets --format pptx --pretty` | PPTX 的 Target ID、Alias、Value Type、Selector、最低 Level、Cost 和格式选项 |
| `deckprobe schema --pretty` | 当前二进制内置的完整 Schema v2 JSON Schema |

例如，UI 可以通过 `targets` 预先判断 PPTX 是否支持 `slide_count`、需要哪个 Level，以及应该按什么 Value Type 处理结果。
