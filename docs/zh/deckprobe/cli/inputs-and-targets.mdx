DeckProbe 先根据逻辑文件名的扩展名选择 Driver，再验证容器和内部文档类型，最后只执行完成所请求 Target 必需的 Path。

## 输入方式

### 本地文件

将文件路径作为最后一个参数传入：

```bash
deckprobe report.pdf
```

报告中的 `source_kind` 为 `local_file`，`display_name` 为文件名 `report.pdf`。

### 从 stdin 读取单个文件

位置参数使用 `-`，并通过 `-n` / `--stdin-name` 提供带扩展名的逻辑文件名：

```bash
cat workbook.xlsx | deckprobe -n workbook.xlsx -
```

DeckProbe 使用 `workbook.xlsx` 选择 Excel Driver。stdin 会先在 CLI 边界缓冲；超过当前物理字节预算时，输入会被拒绝。

### 使用 JSONL 批量处理

`--jsonl` 让一个 DeckProbe 进程连续处理多个文件。标准输入中的**每一行都是一条输入记录**，标准输出中的**每一行都是对应记录的结果**。

下面的命令输入两条 Path Record：

```bash
printf '%s\n' \
  '{"path":"sample.pdf"}' \
  '{"path":"deck.pptx","name":"quarterly.pptx"}' \
  | deckprobe --jsonl -t format --view values
```

- 第一行读取 `sample.pdf`。
- 第二行读取 `deck.pptx`，但在报告中显示为 `quarterly.pptx`；`name` 也会作为格式路由名称。
- 命令会输出两行紧凑 JSON，顺序与输入一致。

如果调用方持有文件字节而不是文件路径，可输入 Byte Record。`name` 提供格式路由所需的扩展名，`data_base64` 保存完整文件的 Base64 内容：

```bash
encoded=$(base64 < sample.pdf | tr -d '\n')
printf '{"name":"sample.pdf","data_base64":"%s"}\n' "$encoded" \
  | deckprobe --jsonl -t format --view values
```

`base64` 可以作为 `data_base64` 的别名。JSON 字符串路径（例如 `"sample.pdf"`）等价于 `{"path":"sample.pdf"}`。

传给命令的 Target、置信度、格式选项、预算以及 `--strict`、`--plan`、`--view` 参数会应用到每条输入。JSONL 输出必须保持一条记录一行，因此不能与 `--pretty` 同时使用。某条记录失败时，DeckProbe 会在对应位置输出错误报告，然后继续处理后续记录。

## 格式路由与格式断言

DeckProbe 使用扩展名选择 Driver，然后验证文件签名和内部类型。把 PPTX 重命名成 DOCX 不会让它变成 Word 文档，而会返回 `MALFORMED_INPUT`。

`-f` / `--input-format` 用于声明“这个输入应该属于指定格式”，不会跳过上述验证：

```bash
deckprobe --input-format pdf report.pdf
deckprobe --input-format powerpoint deck.pptx
deckprobe --input-format iwork deck.key
```

如果检测结果与断言不一致，命令会失败。运行 `deckprobe formats --pretty` 可查看接受的格式名称及其 Driver。

## 必选 Target

`-t` / `--targets` 指定必须尝试解析的事实。参数可以重复，也可以使用逗号分隔；未提供时默认为 `@default`。

```bash
deckprobe -t title -t page_count report.pdf
deckprobe -t title,page_count report.pdf
deckprobe -t @summary -t @security upload.docm
```

命令行可以使用不歧义的短名称。例如，在 PPTX 中请求 `slide_count`：

```bash
deckprobe -t slide_count --view values deck.pptx
```

返回结果仍使用稳定的完整 Key，便于程序处理：

```json
{
  "values": {
    "powerpoint.slide_count": 12
  }
}
```

Selector 是一组预定义 Target 的快捷方式：

| Selector | 选择的 Target |
| --- | --- |
| `@header` | Header 级别的文档身份事实 |
| `@default` | 当前探测层级下，该 Driver 的默认 Target |
| `@summary` | 文档身份、通用元数据和主要结构 |
| `@security` | 加密、宏、签名、外部关系和活动内容信号 |
| `@structure` | 格式专属的数量、名称、尺寸和结构 |
| `@assets` | 预览、图片、媒体、字体和嵌入对象 |
| `@quality` | 完整性、修复、扩展名匹配和规范性信息 |
| `@format` | 当前层级可用的全部格式专属 Target |
| `@all` | 当前层级可用的全部 Target |

`@summary` 是为快速概览设计的精选集合，并不保证包含该格式的每项统计。如果应用明确依赖 PDF 页数，应直接请求 `page_count`，而不是假设它一定包含在 `@summary` 中：

```bash
deckprobe -t @summary,page_count --view values report.pdf
```

## 可选 Target

小写 `-o` / `--optional-targets` 指定“有现成结果就返回，没有也不增加额外读取”的 Target：

```bash
deckprobe -t page_count -o object_count --view values report.pdf
```

在这个示例中，`page_count` 是必选 Target，会参与 Path 规划；`object_count` 是可选 Target。只有已为 `page_count` 选择的 Path 同时能以所需置信度得到对象数量时，结果中才会出现 `pdf.object_count`。否则它会被省略，不会新增 Path，也不会让报告变为 `partial`。

这种“复用已选 Path 顺带收集结果”的行为称为 Piggyback。`-N` / `--no-piggyback` 会关闭它，因此通常不会与 `-o` 一起使用。

## 探测层级与置信度

### 探测层级

`-l` / `--probe-level` 限制 Planner 可以选择的 Path 深度和成本。Target 决定“要什么”，探测层级决定“允许执行哪些 Path”。

| Level | 接受值 | 允许的探测范围 |
| --- | --- | --- |
| `header` | `header`、`h`、`l0`、`0` | 容器和 Header 身份；适合快速格式验证 |
| `metadata`（默认） | `metadata`、`m`、`l1`、`1` | 有界元数据、核心属性和常用结构数量 |
| `deep` | `deep`、`d`、`l2`、`2` | 成本更高的格式专属结构、资源和完整性 Path |

使用方式：

```bash
# 只验证文档身份
deckprobe -l header -t @header --view values report.pdf

# 使用默认层级读取摘要与页数
deckprobe -l metadata -t @summary,page_count --view values report.pdf

# 允许执行更高成本的 Path，并只请求实际需要的 Target
deckprobe -l deep -t @security,attachment_count --view values report.pdf
```

### 置信度

`-c` / `--minimum-confidence` 规定可接受证据的最低置信度，可选 `low`、`medium`、`high` 或 `exact`（缩写为 `l/m/h/x`），默认值是 `high`：

```bash
deckprobe -c exact -t format report.pdf
```

`-C` / `--target-confidence TARGET=CONFIDENCE` 只覆盖一个 Target：

```bash
deckprobe -t slide_count,orientation \
  -C slide_count=exact \
  deck.pptx
```

`deckprobe targets --format FORMAT --pretty` 列出的 Target 表示 Driver **认识这个事实**。实际请求时，如果 Target 的最低层级高于当前 `-l`，或者可用 Path 的置信度低于 `-c` / `-C`，Planner 就无法选择合适的 Path。此时 Target 会进入 `execution.unresolved_targets`；使用 `--strict` 可把该情况转换为退出码 `5`。

## 格式选项

<Warning>
  小写 `-o` 表示可选 Target；大写 `-O` 才表示格式选项。两者用途不同。
</Warning>

`-O` / `--format-option` 使用 `KEY=VALUE` 调整当前 Driver 的解析行为。它不是任意参数，也不是把 Target Schema 中的字段都作为选项。

以 PDF Driver 为例，当前公开两个选项：

| Key | Value | 作用 |
| --- | --- | --- |
| `pdf.repair_xref` | `none` 或 `safe`；默认 `safe` | PDF xref 损坏时，是否允许有界的安全恢复 |
| `pdf.max_objects` | 正整数；默认 `100000` | 解析出的 PDF 对象数量超过该值时拒绝文件 |

```bash
# 禁止修复损坏的 xref
deckprobe -O pdf.repair_xref=none report.pdf

# 将允许的 PDF 对象数量上限设为 50000
deckprobe -O pdf.max_objects=50000 report.pdf
```

`deckprobe targets --format pdf --pretty` 的输出包含 `format_options` 数组。只有该数组列出的 Key、Value 类型和枚举值可以传给 `-O`；`targets` 数组及其 JSON Schema 描述的是输出 Target，不是 Driver 选项。Driver 确定后，`repair_xref` 这类不歧义的 Key 可以省略 `pdf.` 前缀。

## 资源预算

探测层级会提供默认预算。处理不可信输入时，可以覆盖单项限制：

```bash
deckprobe \
  --probe-size 8388608 \
  --max-expanded-bytes 16777216 \
  --max-archive-entries 5000 \
  --timeout-ms 1000 \
  -t format,has_macros \
  upload.docm
```

| 参数 | 限制 |
| --- | --- |
| `-b`, `--probe-size BYTES` | Probe Path 最多读取的物理字节数 |
| `-x`, `--max-expanded-bytes BYTES` | 最多累计解压的字节数 |
| `-e`, `--max-archive-entries COUNT` | 最多处理的 ZIP/OPC 条目数量 |
| `-T`, `--timeout-ms MILLISECONDS` | 协作式墙钟时间预算 |

超出预算时以状态 `4` 退出。能够生成报告时，已经消耗的资源会记录在 `execution.actual_cost`。需要硬性截止时间的应用，还应在 CLI 外层设置进程级超时。

## 查询当前可用 Target 与选项

以当前安装的二进制为准：

```bash
deckprobe targets --format pdf --pretty
deckprobe targets --format docx --pretty
deckprobe targets --format xlsx --pretty
deckprobe targets --format pptx --pretty
deckprobe targets --format key --pretty
deckprobe targets --format numbers --pretty
deckprobe targets --format pages --pretty
```

输出中的 `targets`、`selector_expansions` 和 `format_options` 分别描述 Target、Selector 展开结果和 Driver 选项。
