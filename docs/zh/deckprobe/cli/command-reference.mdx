本页列出当前命令模型公开的完整 CLI Surface。准确契约应以已安装版本的 `deckprobe --help` 和各子命令 `--help` 为准。

## Synopsis

```text
deckprobe [OPTIONS] <INPUT>
deckprobe --jsonl [OPTIONS]
deckprobe <COMMAND> [OPTIONS]
```

## 命令

| 命令 | 用途 |
| --- | --- |
| `deckprobe [OPTIONS] <INPUT>` | Probe 一个本地文件或原始 stdin 输入 |
| `deckprobe --jsonl [OPTIONS]` | 从每个 stdin 行读取一个 Path/Byte Descriptor，并逐行输出紧凑 Report |
| `deckprobe formats` | 列出 Format Profile、所属 Driver 和支持边界 |
| `deckprobe targets [FORMAT]` | 列出指定 Profile 的 Target 和 Format Option Schema |
| `deckprobe schema` | 输出二进制内置的 Schema v2 JSON Schema |
| `deckprobe completion <SHELL>` | 根据当前命令模型生成 Shell Completion |
| `deckprobe generate man` | 生成主 Roff Man Page，或完整 Man Page 目录 |
| `deckprobe help [COMMAND]` | 输出主帮助或某个子命令的帮助 |
| `deckprobe --help` | 输出完整的帮助文本 |
| `deckprobe --version` | 输出已安装的 DeckProbe 版本 |

每个 Discovery Command 都有独立帮助：

```bash
deckprobe formats --help
deckprobe targets --help
deckprobe schema --help
deckprobe completion --help
deckprobe generate --help
```

## 输入解释参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `<INPUT>` | 无 | 本地文件；或使用 `-` 表示一个原始 stdin 文档；与 `--jsonl` 冲突 |
| `-n`, `--stdin-name NAME` | 无 | 原始 stdin 的带扩展名逻辑文件名；需要位置参数 `-`，并与 `--jsonl` 冲突 |
| `--jsonl` | 关闭 | 每个 stdin 行读取一个 JSON String 或 Input Record；与 `<INPUT>`、`--stdin-name`、`--pretty` 冲突 |
| `-f`, `--input-format FORMAT` | 无 | 断言检测到的 Driver 或 Profile；不会强制使用 Parser |
| `-O`, `--format-option KEY=VALUE` | 无 | 可重复的 Driver Option；`--option` 是 Visible Alias |

## Target 选择参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `-t`, `--targets SELECTOR` | `@default` | Required Target 或 Selector；可重复、可用逗号分隔 |
| `-o`, `--optional-targets SELECTOR` | 无 | 只有在已选 Path 已经产生时才返回的 Optional Target；可重复、可用逗号分隔 |
| `-c`, `--minimum-confidence CONFIDENCE` | `high` | 最低 Confidence；`--confidence` 是 Alias |
| `-C`, `--target-confidence TARGET=CONFIDENCE` | 无 | 单 Target Confidence Override；可重复、可用逗号分隔 |
| `-N`, `--no-piggyback` | 关闭 | 禁用 Optional Target 的零额外路径收集 |

### Selector

```text
@header  @default  @summary  @security  @structure
@assets  @quality  @format   @all
```

### Confidence 取值

| 取值 | 缩写 |
| --- | --- |
| `low` | `l` |
| `medium` | `m` |
| `high` | `h` |
| `exact` | `x` |

Target 参数示例：

```bash
# 请求两个必选 Target
deckprobe -t format,page_count report.pdf

# 请求安全相关的一组 Target
deckprobe -t @security upload.docm

# object_count 只在已选 Path 能顺带得到时返回
deckprobe -t page_count -o object_count report.pdf

# 仅要求 slide_count 达到 exact 置信度
deckprobe -t slide_count,orientation -C slide_count=exact deck.pptx
```

## Probe Level 与资源参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `-l`, `--probe-level LEVEL` | `metadata` | 选择 Budget 与 Eligible Path Profile；`--level` 是 Alias |
| `-b`, `--probe-size BYTES` | Level Profile | 最大物理读取字节；`--probesize` 是 Alias |
| `-x`, `--max-expanded-bytes BYTES` | Level Profile | 最大累计解压字节 |
| `-e`, `--max-archive-entries COUNT` | Level Profile | 最大 ZIP/OPC Entry 数量 |
| `-T`, `--timeout-ms MILLISECONDS` | Level Profile | 协作式墙钟 Probe Budget |

Probe Level 取值：

| Level | 接受值 |
| --- | --- |
| Header | `header`、`h`、`l0`、`0` |
| Metadata | `metadata`、`m`、`l1`、`1` |
| Deep | `deep`、`d`、`l2`、`2` |

Probe Level 使用示例：

```bash
# Header：只检查容器和文档身份，适合快速格式验证
deckprobe -l header -t @header --view values report.pdf

# Metadata：默认层级，读取有界元数据和常用结构数量
deckprobe -l metadata -t @summary,page_count --view values report.pdf

# Deep：允许执行成本更高的 Path；仍建议只请求需要的 Target
deckprobe -l deep -t @security,attachment_count --view values report.pdf
```

`-l` 也可以写成 `--probe-level`，例如 `deckprobe --probe-level deep ...`。Level 决定允许执行的 Path，并不自动选择该层级下的全部 Target。

## 输出与执行参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `-s`, `--strict` | 关闭 | 任一请求 Target 未解析时以 `5` 退出；仍然输出完整报告 |
| `-p`, `--pretty` | 关闭 | 格式化 Probe 和 Discovery JSON；与 `--jsonl` 冲突 |
| `-P`, `--plan-only` | 关闭 | 输出 Plan，不运行非 Header Path；`--plan` 是 Visible Alias |
| `--telemetry` | 关闭 | 在 Cost Object 中加入非确定性的墙钟 `elapsed_ms` |
| `--view VIEW` | `full` | 选择 `full` Evidence Report 或紧凑 `values` Envelope |
| `-h`, `--help` | — | 输出帮助；`--help` 包含完整说明 |
| `-V`, `--version` | — | 输出版本 |

输出参数示例：

```bash
# 输出便于阅读的完整证据报告
deckprobe --pretty --view full -t page_count report.pdf

# 只输出紧凑的 Target 与 Value 映射
deckprobe --view values -t format,page_count report.pdf

# 查看执行计划，不运行非 Header Path
deckprobe --plan --pretty -t @summary,@security upload.docm

# 任一必选 Target 未解析时以状态码 5 退出
deckprobe --strict -t format,page_count report.pdf
```

## `formats`

```bash
deckprobe formats
deckprobe formats --pretty
```

以 JSON 返回支持的 Profile Name、Extension、所属 Driver 和实现边界。`--pretty` 是全局参数，以下两种位置都有效：

```bash
deckprobe --pretty formats
deckprobe formats --pretty
```

## `targets`

通过位置参数或 `-f` / `--format` 传入 Profile：

```bash
deckprobe targets pdf --pretty
deckprobe targets --format pptx --pretty
```

两种 Format 写法不能同时使用。接受名称包括：

```text
pdf
word / docx / docm
excel / xlsx / xlsm
powerpoint / pptx / pptm
keynote / key
numbers
pages
legacy / doc / xls / ppt
```

返回结果包含 Target ID 与 Alias、Compatibility Value Type、JSON Schema Fragment、Selector Membership 与 Expansion、最低 Level、Cost Class 和支持的 Format Option。

## `schema`

```bash
deckprobe schema
deckprobe schema --pretty
```

输出当前运行二进制编译时内置的准确版本化 Report Schema。

## `completion`

根据当前命令模型生成 Completion Source：

```bash
deckprobe completion bash > deckprobe.bash
deckprobe completion zsh > _deckprobe
deckprobe completion fish > deckprobe.fish
deckprobe completion powershell > deckprobe.ps1
deckprobe completion elvish > deckprobe.elv
```

支持的取值为 `bash`、`elvish`、`fish`、`powershell` 和 `zsh`。可以通过 `deckprobe completion --help` 确认当前二进制支持的取值。

## `generate man`

向标准输出写入主 Man Page：

```bash
deckprobe generate man > deckprobe.1
man ./deckprobe.1
```

使用 `-d` / `--output-dir DIRECTORY` 创建主页面和所有子命令页面：

```bash
deckprobe generate man --output-dir ./man
man -M ./man deckprobe
man -M ./man deckprobe-targets
```

目录包含：

```text
deckprobe.1
deckprobe-formats.1
deckprobe-targets.1
deckprobe-generate.1
deckprobe-schema.1
deckprobe-completion.1
```

## Exit Status

| 状态 | 含义 |
| ---: | --- |
| `0` | 成功；未启用 `--strict` 时允许存在未解析 Target |
| `1` | 无效请求或不支持的 Target，包括缺少 Input |
| `2` | CLI 语法错误或 Source I/O 错误 |
| `3` | 不支持或无法识别的输入格式 |
| `4` | Malformed Input 或超出 Probe Budget |
| `5` | 启用 `--strict` 时存在未解析的请求 Target；仍然输出完整报告 |
| `6` | 内部 Parser 或 Report Serialization 失败 |

接入行为和示例请查看[自动化与输出](/zh/deckprobe/cli/automation-and-output)。仓库中的 [CLI Reference](https://github.com/deckflow/deckprobe/blob/main/docs/CLI-REFERENCE.md)继续作为与源码同步的底层规范。
