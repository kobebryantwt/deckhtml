DeckOps 把文档转换成适合 Agent 与应用继续处理的中间表示。先解析一次并得到本地产物目录，之后可以反复读取 IR 或生成 Markdown，无需再次打开和解析源文件。

| | 概览 |
| --- | --- |
| 适合场景 | 搜索入库、RAG、文档理解和需要重复执行的下游处理 |
| 本地输入 | PDF、PPTX、DOCX，以及静态网页源码 |
| 云端输入 | Keynote、需要运行时渲染的网页；也可明确选择把本地格式交给云端 |
| 主要结果 | 包含 `deckir.v1`、资源、质量信息和可选 DeckProbe 报告的版本化产物目录 |
| 派生视图 | Markdown，可按页拆分或为 PDF 增加来源锚点 |
| 接入方式 | CLI、Node.js SDK，以及仅接入云端的 Browser SDK |

## DeckOps 为应用提供什么

- <strong>统一文档模型：</strong>页面、节点、文本片段、几何信息、来源引用、资源和质量检查都使用公开的 `deckir.v1` Schema。
- <strong>可复用产物：</strong>源文件哈希、解析器身份、参数、IR、资源和已生成视图保存在一起。
- <strong>明确的质量边界：</strong>不能完整解析的内容会标记为降级或不透明节点，不会悄悄近似处理。
- <strong>默认本地执行：</strong>PDF、PPTX、DOCX 和静态 URL 源码默认在本地解析，不需要凭证。
- <strong>明确选择云端：</strong>Keynote、运行时网页，或应用主动选择云端解析时才进入云端路径。

```text
文档 ── parse ──> 产物目录/
                    ├── ir.json
                    ├── manifest.json
                    ├── probe.json
                    ├── assets/
                    └── views/markdown/
                             ↑
                       从 IR 执行 convert
```

<Tip>
  `parse` 是唯一会读取并理解源文件的操作。`convert` 消费已有产物；直接把文档传给 `convert` 时，DeckOps 只是用一次性快捷流程完成解析和转换。
</Tip>

## 选择执行引擎

- `local` 是默认值。支持的文件留在当前机器，无需 DeckFlow 账号。
- `cloud` 会明确上传输入，需要可用的游客或认证云端路径。
- `auto` 仍先在本地执行，只有同时传入 `--allow-upload` 或 `allowUpload: true` 才获得上传许可。

Browser SDK 只接入云端。它可以在上传前通过 DeckProbe 检查浏览器中选中的本地文件，但真正的文档解析仍在 DeckFlow 云端执行。
