`ir.json` 是跨格式的 `deckir.v1` 文档。它为应用提供稳定的外层契约，同时通过节点类型、样式、来源引用和扩展字段保留源格式细节。

## 顶层结构

```json
{
  "schemaVersion": "deckir.v1",
  "format": "pptx",
  "source": {
    "sha256": "<source-sha256>",
    "name": "slides.pptx",
    "bytes": 45210
  },
  "producer": {
    "engine": "local",
    "name": "deckparse-pptx",
    "version": "1"
  },
  "document": {
    "metadata": {},
    "pages": [],
    "nodes": [],
    "assets": []
  },
  "quality": {
    "status": "pass",
    "checks": [],
    "coverage": {}
  }
}
```

## 页面与节点

每个页面包含稳定 ID、从零开始的索引、可选尺寸、有序节点 ID 和来源引用。节点通过 `parentId` 与 `children` 形成树形结构，还可以包含：

- `type`、`order`、文本、富文本片段、样式和链接
- 源格式提供布局时的页面、边界框和层级
- 置信度和问题代码
- DeckOps 能保留但不能完整理解对象时的 `opaque` 记录
- 不适合放入通用字段的格式专属 `extensions`

`sourceRef` 记录页面或节点在源文件中的位置，例如页码、部件名、XML 路径、对象 ID、字节范围或字符范围。需要追溯来源时应使用这些字段，不要从 Markdown 顺序反推。

## 资源

资源记录包含稳定 ID、相对产物路径、哈希、字节数、可选媒体类型和来源引用。节点使用这些持久身份引用资源；应用应以产物目录为根解析路径。

## 质量报告

质量报告把“解析完成”和“解析保真度”分开表达：

- `status` 为 `pass`、`degraded` 或 `unsupported`。
- `checks` 包含稳定代码、严重程度、说明和可选的页面/节点详情。
- `coverage` 可以记录已解析页面、已解析与不透明对象数量、文本字符数。
- `recommendation: "cloud"` 表示云端解析可能改善本地结果，但不会自动触发上传。

如果降级结果应导致 CLI 任务失败，请使用 `--fail-on-degraded`。

## 校验 Schema

npm 包导出了 JSON Schema：

```js
import schema from '@deckflow/deckops/schemas/deckir.v1.schema' with { type: 'json' };
```

Node.js SDK 还导出 `validateDeckIR()` 用于运行时校验。
