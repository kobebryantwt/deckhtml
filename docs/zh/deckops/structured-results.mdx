每个 Parser 会保留对应源格式可提供的结构。这些结果用途相近，但并不共享同一套节点 Schema。

<Warning>
  依赖下列 Schema 前，请先确认已安装 SDK 提供对应的 Parse 方法。如果类型化方法不可用，请选择软件包已提供的底层任务方法，并检查下载结果。
</Warning>

## PDF

`pdf.parse` 返回 `textBlocks` 和可选的 `images`。文本块包含文本、从 0 开始的页定位、可选的粗体或斜体样式，以及 `heading`、`list-item`、`caption` 等可选语义角色。

## PPTX

`pptx.parse` 返回演示文稿对象模型，可以保留幻灯片、形状、Transform、Text Body、表格、图片、Group、Layout 和 Master 关系等 PPTX 专属数据。Markdown 转换器会利用几何与形状关系重建阅读顺序。

## DOCX

`docx.parseTextAndImage` 返回有序文档元素，包括文本、图片、表格、图表、Diagram、Group 和结构化文档标签。只有上游 Parser 提供段落样式时，Markdown 转换才能还原标题层级。

## Keynote

`keynote.parseTextAndImage` 返回文档尺寸、包含文本、表格和图表标签的 Slide，以及带页索引的图片。Markdown 转换器会把没有有效页索引的图片保留到兜底段落，避免静默丢失。

## 网页

`html.getByURL` 可以获取源码或运行后的 HTML。Markdown 门面会提取正文、转换为 GitHub-flavored Markdown、补全相对图片地址，并移除脚本、样式和 iframe。

## Markdown 是结果投影

Markdown 便于使用，但会主动丢弃部分源格式细节。以下场景应使用底层结构化结果：

- 需要页面或幻灯片几何
- 需要形状层级和组合关系
- 需要 Rich Text Run 与样式
- 需要表格、图表、图片、备注、Layout 或 Master
- 需要保留 Task ID 以便后续检查原始结果

如果当前需要 Markdown，同时希望保留 Task ID 和实际 Parser，请使用 `parseDetailed()`。
