本地解析和转换不需要 DeckFlow 账号。只有 DeckOps 实际选择云端引擎时才会读取认证信息，例如处理 Keynote、解析运行时网页，或显式传入 `--engine cloud`。

## 获取 API Key

访问 [DeckFlow 设置](https://app.deckflow.com/start#settings)，进入设置页面并创建或复制 API Key。请把它保存在密钥管理系统中，只提供给服务端进程。

```bash
export DECKOPS_API_KEY="<api-key>"
deckops parse slides.key --engine cloud
```

`DECKOPS_API_KEY` 的优先级高于共享的 `DECKFLOW_API_KEY`。不要把任意一种 Key 写入前端 JavaScript。

## CLI 浏览器登录

```bash
deckops auth login
deckops auth status
deckops config list
```

登录得到的用户 Token 保存在 DeckFlow 共享凭证目录中，DeckOps、DeckRender 和 DeckHTML 可以复用同一次登录。使用 `deckops auth logout` 退出。

凭证位于 `~/.deckflow/credentials`，DeckOps 产品默认值位于 `~/.deckflow/deckops/config.json`。`deckops config list` 会显示每项最终值的来源，便于判断具体由哪个环境变量或配置文件生效。

## Node.js

```ts
import { createClient } from '@deckflow/deckops';

const client = createClient({
  apiKey: process.env.DECKOPS_API_KEY,
  spaceId: process.env.DECKOPS_SPACE_ID,
});

const document = await client.parse('slides.key', { engine: 'cloud' });
```

Client 也可显式传入用户 `token` 和 `apiBase`。CLI 适合使用环境变量；多租户服务端应用通常更适合为每个 Client 显式传值。

## 浏览器应用

Browser SDK 特意不提供 `apiKey` 参数。请传入适合在浏览器使用的用户级 Token，或通过认证后的后端代理转发请求，把服务端 API Key 留在后端。

```ts
import { createClient } from '@deckflow/deckops/browser';

const client = createClient({
  apiBase: '/api/deckops',
  token: userAccessToken,
  onUnauthorized: refreshUserAccessToken,
});
```

如果部署环境允许游客访问，可以用于有限体验；生产流程不应依赖游客额度或可用性。
