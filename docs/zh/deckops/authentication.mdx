DeckOps 支持三种身份。所有模式都在 Deckflow 云端执行，因此都会上传任务输入。

| 模式 | 请求头 | 启动行为 | 适用场景 |
| --- | --- | --- | --- |
| API Key | `Authorization: Bearer <key>` | 任务自动启动 | 生产服务和 CI |
| 用户 Token | `X-Auth-Token: <token>` | 任务自动启动 | 交互式应用和已登录 CLI |
| 游客 UUID | 客户端生成游客身份 | 底层任务需要 `tasks.start()` | 评估和受限试用 |

## API Key

创建 TypeScript 客户端时传入 Key。请保存在服务端密钥系统中，不要打包到浏览器代码里。

```ts
const deck = createDeck({ apiKey: process.env.DECKOPS_API_KEY });
```

## 用户 Token

DeckOps CLI 可以打开浏览器登录流程，并把 Token 保存到 `~/.deckops/config.json`：

```bash
deckops login
```

SDK 客户端可以显式传入返回的 Token 和可选的空间 ID。不要提交该配置文件。

## 游客执行

游客底层任务创建后处于 `pending` 状态。需要显式启动，再等待和下载：

```ts
const task = await deck.convertPptToPdf({ files: ['./slides.pptx'] });
await deck.tasks.start(task.id);
const completed = await deck.tasks.wait(task.id);
const result = await deck.tasks.down(completed.id);
```

Node.js CLI 会自动启动游客任务。TypeScript 和 Go SDK 提供 `tasks.start`；当前 Python SDK 没有，因此 Python 接入请使用已认证执行。

<Warning>
  高层 `parse()` 和 `parseDetailed()` 会创建任务并直接等待，不会启动游客任务。使用这些方法时请配置 API Key 或用户 Token。
</Warning>

## 生产检查清单

- 把 API Key 和 Token 存放在部署环境的密钥管理系统中。
- 需要让任务共享工作空间时，配置稳定的空间 ID。
- 把任务 ID 和下载结果视为应用数据处理。
- 分别处理认证失败、任务失败和超时。
