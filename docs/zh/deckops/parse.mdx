`parse` 读取源文件并创建产物目录，不会生成 Markdown；需要文本视图时，在解析后执行 `convert`。

## 支持的路径

| 输入 | 默认路径 | 常用参数 |
| --- | --- | --- |
| PDF | 本地 | `--profile`、`--password`、`--no-images`、`--page-furniture`、`--overlaid-text` |
| PPTX | 本地 | 不能完整解析的复杂图表和 SmartArt 会保留为不透明节点 |
| DOCX | 本地 | `--tracked-changes final\|original\|all` |
| Keynote（`.key`） | 云端 | `--stay-image-area-rate` |
| HTTP(S) URL | 本地源码 | `--mode source` 获取 HTML；`--mode runtime` 选择云端浏览器运行时 |

运行 `deckops formats` 可以查看当前已安装 CLI 实际实现的路径。

## 选择引擎

```bash
# 默认：本地解析，不上传文档
deckops parse report.pdf

# 明确选择云端解析
deckops parse report.pdf --engine cloud

# 先本地解析，质量降级时给出云端建议
deckops parse report.pdf --engine auto

# 允许 auto 在本地质量不足时上传
deckops parse report.pdf --engine auto --allow-upload
```

`--engine auto` 本身不代表允许上传。只有同时使用 `--allow-upload`，才明确授权 DeckOps 回退到云端。

## 解析前预检

本地文件和标准输入会先使用 DeckProbe 预检：

| 模式 | 行为 |
| --- | --- |
| `validate` | 默认值。拒绝容器不匹配或损坏的文档，以及未提供有效密码的加密文档；探测运行或预算失败会转成警告。 |
| `strict` | 请求的预检证据不能确定时也会失败。 |
| `off` | 在启动延迟或浏览器 CSP 更重要的环境中跳过预检。 |

```bash
deckops parse report.pdf --preflight validate
deckops parse slides.pptx --preflight strict
```

预检成功后，完整报告写入 `probe.json`，摘要写入 manifest 和命令结果的 `inspection`。URL 输入跳过本地预检。

## 格式专属示例

<Tabs>
  <Tab title="PDF">
    ```bash
    deckops parse report.pdf \
      --profile balanced \
      --page-furniture drop \
      --overlaid-text auto \
      -o report-ir
    ```

    PDF Profile 包括 `fast`、`balanced` 和 `quality`。DeckOps 不执行 OCR；`--no-images` 会跳过内嵌图片导出。
  </Tab>
  <Tab title="DOCX">
    ```bash
    deckops parse contract.docx \
      --tracked-changes final \
      -o contract-ir
    ```

    `original` 读取修订前内容，`all` 同时保留修订前后内容。
  </Tab>
  <Tab title="URL">
    ```bash
    deckops parse https://example.com/article \
      --mode source \
      -o article-ir
    ```

    源码模式只获取指定 URL 和受限次数的重定向；运行时模式使用云端引擎，需要云端访问能力。
  </Tab>
</Tabs>

## 质量与降级

每份 `deckir.v1` 都包含 `quality`，其中记录状态、检查项和覆盖率。解析器无法完整理解某个对象时，会把它保留成不透明节点并说明限制。

如果流水线不接受降级结果，可使用：

```bash
deckops parse slides.pptx --fail-on-degraded --json
```
