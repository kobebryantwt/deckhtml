sidebarTitle: 快速开始
description: "通过 npm 安装 DeckOps，在本地解析文档，并从产物生成 Markdown。"
---

本页使用 CLI 展示完整的本地流程，不需要账号或 API Key。DeckOps 需要 Node.js 22.18 或更高版本。

<Steps>
  <Step title="安装并验证 CLI">
    ```bash
    npm install -g @deckflow/deckops
    deckops --version
    deckops --help
    ```

    如果不希望全局安装，可以在后续命令中把 `deckops` 替换为 `npx -y @deckflow/deckops@latest`。
  </Step>
  <Step title="下载示例文档">
    ```bash
    curl -fL https://docs.deckflow.com/images/deckuse-sample.pptx -o sample.pptx
    ```

    示例文件包含可编辑的演示文稿文本，并由本站直接提供。首次跑通后，可以换成自己的 PDF、PPTX 或 DOCX。

    ```bash
    test -s sample.pptx
    ```

    校验下载结果；PowerShell 使用第二种写法：

    ```powershell
    if (!(Test-Path sample.pptx) -or (Get-Item sample.pptx).Length -eq 0) { exit 1 }
    ```
  </Step>
  <Step title="把源文件解析成产物">
    ```bash
    deckops parse sample.pptx --json
    ```

    成功结果会包含 `"op": "parse"`、`"engine": "local"`、`"irSchemaVersion": "deckir.v1"` 和产物路径。默认目录是 `sample/`：

    ```text
    sample/
    ├── ir.json
    ├── manifest.json
    ├── probe.json
    └── assets/
    ```

    该示例还可能出现一条关于内嵌对象的预检提示。应根据 `ok` 与 `quality` 判断解析是否成功，并由应用单独保留和展示 `warnings`。
  </Step>
  <Step title="从产物生成 Markdown">
    ```bash
    deckops convert sample/ --json
    ```

    结果会显示 `"reusedParse": true`，并写入 `sample/views/markdown/index.md`。这一步不会重新解析源 PPTX。

    ```bash
    test -s sample/views/markdown/index.md
    ```
  </Step>
</Steps>

如果只需要产物目录之外的一份 Markdown，可以使用一次性写法：

```bash
deckops convert sample.pptx -o sample.md
```

DeckOps 会在需要时先解析文档，并把引用的资源放到输出附近。格式专属参数见[解析文档](/zh/deckops/parse)，自动化和错误处理见 [CLI](/zh/deckops/cli)。
